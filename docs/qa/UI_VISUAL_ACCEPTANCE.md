# 화면 개발의 기본 시각 검사

2026-10-24 · 사용자가 반복해서 지적한 정렬·높이·시안 이탈의 재발 방지

사용자가 다시 요청하지 않아도 매 UI 작업에 적용한다. [구현 가이드](../design/DESIGN_IMPLEMENTATION_GUIDE.md)의 정확한 원본과 고정 구조를 먼저 확인한다. 선택한 구조 안의 정렬 보정은 진행하고, 새 정보 구조를 임의로 섞지 않는다.

## 아이콘의 기준선부터 정하기

| 역할                                    | 맞출 대상                             | 구현/검사 기준                                                               |
| --------------------------------------- | ------------------------------------- | ---------------------------------------------------------------------------- |
| 오늘의 완료 체크, 상세 제목 앞 체크     | 제목 **첫 줄**의 중앙                 | 제목이 길어져도 아래 보조 설명까지 포함한 중앙으로 내리지 않는다.            |
| 계획 항목의 종류 아이콘                 | 제목 + 보조 설명 **전체 블록**의 중앙 | 부모 행의 `alignItems: center`와 공통 `ItemLeading`/`ItemCopy`를 재사용한다. |
| 상세의 일정/실행일 아이콘·오른쪽 화살표 | 라벨 + 값 **전체 블록**의 중앙        | 라벨 첫 줄에 붙이지 않는다. 양쪽 장식이 같은 수평선에 있어야 한다.           |
| 추가 행·아이콘 버튼·한 줄 메타 정보     | 해당 한 줄 또는 버튼 콘텐츠의 중앙    | 폰트의 암묵적인 행간이나 전역 `translateY`로 보정하지 않는다.                |

예를 들어 라벨18 + 간격4 + 값24 = 높이46인 블록은 위에서23이 중심이다. 24 아이콘은 위에서11, 16 화살표는15에 배치한다. 이는 설명용 계산이며 글자 확대/줄바꿈 시에는 실제 블록 높이로 다시 계산한다. 고정 높이로 잘라 맞추지 않는다.

수치상 박스 중심과 눈에 보이는 그림 중심은 다를 수 있다. 실제 캡처에서 아이콘/글자 부분을 확대해 확인하고, 특정 글리프의 폰트 행간이 원인이면 해당 공통 아이콘의 line box를 수정한다. 모든 아이콘을 한꺼번에 아래로 옮기지 않는다.

## 매번 확인할 항목

- **구조:** 흰 바탕·목표 레일/원형 체크·네 탭·작은 헤더를 유지한다. 중복 페이지 제목, 날짜, 카드, 구분선을 다시 추가하지 않는다.
- **높이와 간격:** 같은 역할은 같은 토큰/공통 컴포넌트를 쓴다. 관련 정보8–12, 섹션24를 출발점으로 읽는 덩어리를 확인한다. 행 높이만 늘려 잘못된 중심을 숨기지 않는다.
- **글자:** 명시적인 글자 크기/행간, 긴 제목 줄바꿈, 한글/영문/숫자 혼합을 확인한다. 탭은 말줄임/가로 스크롤, 읽는 본문은 줄바꿈이라는 기존 결정을 지킨다.
- **조작:** 24px 아이콘 그림과 최소44px 조작 영역을 구분한다. 헤더/더보기/닫기/완료/추가 버튼이 글자를 밀거나 겹치지 않아야 한다.
- **상태:** 완료/미완료, 설명 유무, 한 줄/여러 줄, 긴 목표 경로를 확인한다. 새 기능이면 관련 오류/복구도 확인한다.
- **일정 수정:** 날짜 변경 후 상세/이전·새 날짜 목록/달력과 하루 계획 집계가 일치하는지 확인한다. 완료 이력·원문/목표·반복 규칙/알림 off·시간차와 여러 날 기간을 보존하고, 반복 수정 범위의 날짜 의미를 구분한다. 종일은 그림 크기와 별개로44px 이상 조작·단일 스위치 접근성 노출과 시각 초안 복원을 확인한다.
- **폼 오류:** 저장 후 화면 순서상 첫 오류로 이동하고 해당 입력과 수정 설명이 함께 보여야 한다. 접힌 입력은 펼치고 원문을 유지한다. 스크롤이 끝난 다음에도 초점이 남아 입력을 이어갈 수 있는지 확인한다. 반복 제출·관련/무관 입력 수정·좁은 화면의 오류 줄바꿈과 `aria-invalid`/설명 연결을 확인한다. 정상 상태의 배치/조작 수가 늘지 않아야 한다.
- **예상 동작:** 목표 경로는 목표 탐색, 필드 편집은 해당 필드의 범위로 이어지는지 확인한다. 메뉴를 열어 읽던 제목이 이동하는지, 손잡이가 실제 gesture를 제공하는지, 아무것도 바꾸지 않았거나 원문으로 복원했을 때 버리기 확인이 뜨는지도 검사한다. 초기 초점의 시각적 비중과 키보드 초점 가시성을 함께 확인한다.
- **화면:** 기준390×844 및320/430의 동일 데이터 캡처를 비교한다. 영향을 받는 native 글자 확대1.5/키보드/safe area는 실제 확인 여부를 따로 기록한다. Web 폭 변경을 native 검증으로 취급하지 않는다.
- **미감:** 아이콘이 위로 뜨는지, 행마다 높이가 달라 보이는지, 빈 공간이나 강조가 과한지 실제 크기와 확대 상태에서 함께 본다. 자동 검사 결과만으로 판정하지 않는다.

## 실제 Web 좌표 자동 검사

새 의존성 없이 개발 Web에만 측정 표식을 붙인다. `uiAuditProps`는 native/production에서는 빈 객체를 반환하며 레이아웃 스타일을 바꾸지 않는다.

공통 `ItemLeading`, `ItemCopy`, `Button`, `IconButton`, `AddItemRow`와 오늘/계획의 표시 행에 기본 표식이 있다. 새 수평 행은 아래처럼 역할을 명시하고 공통 컴포넌트를 재사용한다.

```tsx
<View {...uiAuditProps({ uiRow: 'detail-date', uiAlign: 'text-block' })}>
  <ItemLeading>{/* icon */}</ItemLeading>
  <View {...uiAuditProps({ uiText: 'block' })}>{/* label + value */}</View>
</View>
```

`title-line`은 `ItemCopy`의 `uiText: 'title'` 첫 줄을 기준으로 사용한다. 아이콘 슬롯 없이 직접 그리는 경우 `uiIcon: 'glyph'`/`'control'`, 조작 영역에는 `uiTouch: '44'`를 지정한다. 중첩 행은 가장 가까운 소유 행으로 분리한다.

1. 연결된 브라우저에서 수정한 화면을 열고 기준 크기/데이터/상태를 맞춘다. [브라우저 선택 정책](./PRODUCT_DESIGN_REVIEW_POLICY.md)을 따른다. 여러 탭을 썼다면 측정 JSON의 실제 viewport를 기대값과 대조한 뒤 캡처에 이름을 붙인다. 다른 활성 탭에만 크기가 적용된 상태를 통과시키지 않는다.
2. `scripts/collect-ui-layout.js` 전체를 **읽기 전용 evaluate 표현식**으로 실행한다. 실제 표시 중인 행의 좌표/경로/viewport만 수집한다. 사용자 텍스트·입력값·앱 상태·인증 정보는 수집하지 않는다.
3. 반환 JSON과 같은 상태의 캡처를 해당 작업의 audit 폴더에 저장한다. 브라우저 API가 표현식을 괄호로 감싸면 끝 세미콜론을 제거한 문자열을 전달한다. 앱 상태를 주입하거나 숨겨진 상태를 읽지 않는다.
4. 아래 명령을 실행한다. 여러 실제 보고서를 함께 전달할 수 있다.

```sh
npm run check:ui-layout -- docs/audits/<작업>/today-390.json docs/audits/<작업>/today-320.json
```

검사 대상은 아이콘과 기준 텍스트 중심의 차이2px 초과, 텍스트/아이콘 가로 겹침, 행/문서 가로 넘침, 표시된 조작 영역44px 미만이다. 측정0행·누락 데이터도 실패한다. 화면에 표시되지 않은 항목/표식 없는 요소/폰트 그림의 광학적 중심/색 대비/native는 판정하지 않는다.

**실패 → 원인 확인 → 공통 레이아웃 수정 → 새 좌표/캡처 → 재검사**를 같은 작업에서 수행한다. 고정 fixture 수치를 통과하도록 검사 허용치를 늘리거나 오래된 JSON을 재사용하지 않는다. 실제 화면을 열 수 없으면 미확인으로 남기며 자동 검사를 통과했다고 쓰지 않는다.

`npm run validate`는 이 검사기의 회귀 테스트를 실행한다. 브라우저가 필요한 새 좌표 수집/검사는 별도 필수 단계이며 `validate`가 대신 실행하지 않는다. 기하 검사는 자동이고, 광학적 정렬과 실제 사용성 판정은 캡처 검토를 유지한다. 자동으로 모든 UI를 임의 이동시키는 도구가 아니다.

## 완료 기록

원본·변경 범위·사용 도구/자료·실제 환경·좌표 검사 결과·눈으로 확인한 항목·미확인 native/상태를 audit에 남긴다. 생성 이미지만 고쳤으면 **시안 보정**으로 표시한다. 실제 앱에도 적용했다고 표현하지 않는다. 디자인 제안은 공식 자료의 기존 검토를 재사용할 수 있지만 새로운 현재 동작 주장은 확인 후 기록한다.
