# Dooit 전체 디자인 완성도 재검토

2026-10-22 · `479ae87` 이후 working tree · 검토/수정 계획, 이번 회차 앱 소스 변경 없음

## 결론

현재는 선택 시안의 요소를 옮겼지만 화면을 넘나들 때 크기·정렬·색·행동 방식이 충분히 일치하지 않는다. 오늘의 목표 레일을 유지하면서 **헤더와 공통 컴포넌트 → 계획·상세 → 작성 흐름 → 달력·돌아보기 → 보조 화면** 순서로 다듬는다. 네이버·배민처럼 정돈된 인상을 원한다는 요청은 일관된 시각 위계와 매끄러운 조작을 품질 목표로 해석한다.

현재 화면과 발견 사항은 [이번 실제 Web 감사](../audits/visual-cohesion-2026-10-22/README.md)에 있다. 예전 시안 일치 검사 통과를 앱 전체의 완성도 승인으로 확장하지 않는다. 아래 수치는 구현 전 제안이며 현재 토큰이 아니다.

## 유지할 제품 결정

- [사용자 첨부 원본](./goal-lanes-correction-2026-10-21/reference.png)의 흰 배경, 목표별 색상 레일·마커, 원형 체크, 넓은 추가 버튼을 유지한다. 항목별 카드나 가로 구분선으로 되돌리지 않는다.
- 하단은 오늘 / 달력 / 계획 / 돌아보기다. 오늘은 실행, 달력은 날짜 탐색, 계획은 목표·반복·연결 항목 관리, 돌아보기는 실제 기록이다.
- 큰 ‘오늘’ 제목·상시 날짜·주간 달력은 오늘 화면에 다시 넣지 않는다. 메뉴는 왼쪽에, 작은 동기부여 문구는 dooit 옆에 둔다.
- 문구의 저자는 헤더에 표시하지 않는다. 출처 확인은 기존 설정에서 제공한다. 영어와 한국어를 함께 쓰되 긴 문장을 억지로 줄이거나 번역을 실제 인용문으로 가장하지 않는다.
- 빈 곳을 채우려고 성과 카드·점수·목표 달성률·연속 기록·AI 칭찬을 추가하지 않는다. 작은 행동과 휴식을 사용자가 선택할 수 있어야 한다.

## 사용한 도구·추가 프론트엔드 자료

Product Design의 index/audit와 검토 기준을 적용했다. 추가 스킬을 찾기 위해 로컬 설치 목록·공식 curated 목록·plugin 검색을 확인했다. 독립적인 `codex-design` 또는 `frontend-design`은 현재 설치 목록에서 확인하지 못했다. 아래 외부 스킬은 **원문을 읽고 검토 기준을 참고한 것**이며 설치·자동 실행한 것으로 표현하지 않는다. 신규 의존성은 없다.

## 가장 먼저: 상단 dooit 영역

### 확인된 문제

1. 헤더는 메뉴 26, dooit 28/36·800·자간 -1.2, 문구 13/18이다. 대비가 큰 세 요소가 좁은 간격에 모여 있다. [현재 코드](../../src/components/navigation/planner-drawer.tsx)와 [실제 오늘](../audits/visual-cohesion-2026-10-22/06-today-resting.png)에서 확인했다.
2. 긴 영문 문구는 두 줄이 되어 로고 옆이 빽빽해진다. 320px에서도 가로 잘림은 없지만 헤더의 밀도가 높다. 문구 내용에 따라 같은 헤더의 인상이 바뀐다.
3. 오늘 본문 위 여백은 32, 계획은 0, 달력은 16이다. 계획의 가로 탭이 필요한 차이는 있지만 헤더와 다음 정보 사이의 연결 규칙이 없다.
4. 1024px에서 본문과 하단 탐색은 가운데 최대 폭에 맞춰지는데 헤더는 뷰포트 왼쪽 끝에 남는다. [넓은 화면](../audits/visual-cohesion-2026-10-22/23-today-wide.png)에서 직접 확인했다.

## 디자인과 함께 연결할 기능

1. **계획 → 오늘:** 새 Goal의 반복 계획을 만들 수 있지만 오늘 회차 hook은 아직 화면에 연결되지 않았다. 실제 Goal 회차를 체크하고 작은 행동·휴식/취소로 이어져야 한다. 이전 Task fixture가 이 연결의 증거는 아니다.
2. **오늘 → 계획:** 목표 메뉴에서 해당 목표가 선택된 계획으로 이동해야 한다. 현재 일반 계획 탭 이동에 그친다.
3. **오늘 작성 → 같은 목표:** 선택 목표·오늘 날짜를 기본 문맥으로 전달하고 명시한 다른 날짜는 존중한다. 새 Task의 Goal 연결과 부분 성공 재시도도 포함한다.
4. **완료 → 돌아보기:** 기존 Task 기록 외에 새 Goal 회차와 직접 기록을 실제 여정 API로 연결한다. 기록 없는 성과나 감정을 생성하지 않는다.

새 Goal 전체 일회성 목록(G-07), 색상·순서 동기화(G-06)는 기존 백엔드 요청서에서 계속 추적한다. 위 헤더·토큰·행·오류 복귀 개선의 선행 조건은 아니다. 이 회차에 새 API 요구를 추가하거나 백엔드에 메시지를 보내지 않았다.

## 구현 순서와 완료 기준

| 순서 | 완결 단위                           | 완료 기준                                                                                                                   |
| ---- | ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 1    | 공통 헤더·brand·글자/색/아이콘 규칙 | 같은 내용의 오늘/계획/돌아보기, 좁은/넓은 화면을 나란히 비교. 로고·문구와 본문 축, 긴 문구·숨김·확대, tab 아이콘/label 확인 |
| 2    | 계획·상세의 정렬과 선택 맥락        | 생성 직후 선택 목표가 보임, 동일 Task의 제목/메타 크기 통일, 상세 정보·체크리스트·삭제의 위계 확인                          |
| 3    | 작성/편집 흐름                      | 기본 할 일 작성 진입 단축, 목표/날짜 문맥 보존, 반복 필수 입력 단순화, 첫 오류 복귀·취소·부분 성공 확인                     |
| 4    | 달력·돌아보기                       | 날짜 탐색 단위가 명확하고 선택일 내용을 쉽게 읽음. 같은 목표/행 규칙, 실제 기록 범위 유지                                   |
| 5    | Drawer·인증·설정 등 확장            | brand·버튼·폼·안내가 같은 계열. 보조 목적지 중복을 줄이고 기존 경로 보존                                                    |

각 단위는 미완료다. 국소 보정은 기존 선택안을 사용한다. 새 선택기·작성 화면·달력 모드처럼 의미 있는 정보 구조 변경은 **세 가지 시각안 비교 → 선택 → 구현** 순서다. 자동 검사 결과와 사용자가 느끼는 시각 완성도를 별개로 평가한다.

## 확인 범위

- 현재 run의 실제 Web 캡처 23장과 코드. 390×844 기본, 오늘은 320×844·1024×844 추가 확인.
- 내장 브라우저/Chrome 확장 연결 실패와 초기화·복구 시도를 기록했다. 사용자 승인 후 로컬 Playwright + 임시 Chrome으로 전환했다.
- mock/개발 fixture 및 UI로 생성한 임시 Goal만 사용했다. 현재 Chrome Web의 관찰이며 Android/iOS·production API·dark·글자 확대·보조 기술 전체 검증은 아니다.
- 검색·기록함·템플릿·공유 공간의 내부 흐름 전체는 이번에 재검증하지 않았다. 이전 감사와 기존 코드 검토 범위를 유지하며 완료 판정하지 않는다.
- 이번 회차는 감사·문서 변경이다. 수정 구현·신규 TO-BE 이미지·커밋·푸시는 하지 않았다.
