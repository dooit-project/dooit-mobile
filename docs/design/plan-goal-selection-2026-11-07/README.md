# 계획 화면 목표 전환 시안

2026-11-07 · 사용자가 선택한 방향 · 생성 이미지, 실제 앱 캡처 아님

- [계획 기본 화면](./plan-reference.png)
- [전체 목표 선택 화면](./all-goals-reference.png)

기존 세 방향 중 1번을 우선 선택하고 3번의 전체 목록 접근성을 결합한 보정안이다. 목표가 많거나 이름이 길 때 가로 탭에서 몇 개만 보이는 문제를 고려했다. 두 이미지는 별도 선택지가 아니라 같은 화면의 두 상태다.

## 결정과 구현 조건

- 가로 목표 탭에서 빠르게 전환하고, 고정된 전체 목표 진입점에서 전체 이름과 검색으로 찾는다. 탭은 한 줄 말줄임, 선택한 목표 제목과 전체 목표 목록은 필요한 만큼 줄바꿈한다.
- 목록의 현재 목표는 색뿐 아니라 선택 표시로 구별하고, 같은 목표에는 두 화면 모두 같은 색을 쓴다. 생성 이미지의 일부 색 차이는 따라 하지 않는다.
- 목표별 반복 계획, 일회성 할 일과 일정을 한 목록에서 관리하는 방향이다. 현재 새 Goal에서 일회성 Task 목록 연결이 모두 지원되는 것으로 가정하지 않는다. [백엔드 요청과 계약](../../api/API_GOAL_JOURNEY_CHANGE_REQUEST.md)을 확인하고 지원되지 않는 기능을 완성된 것처럼 표시하지 않는다.
- 목표별 항목 순서 편집은 맥락 메뉴에서 시작하며, 드래그 이외에도 접근 가능한 이동 조작을 제공한다. 목표 자체의 순서 편집과 구별한다. 저장 위치와 지원 범위는 구현 시 명확히 한다.
- 작은 화면·확대 글씨·긴 이름·많은 목표·검색 결과 없음과 로딩/오류/복구 상태, 닫기 및 초점 복귀를 실제 구현에서 확인한다.
- 시안의 날짜와 제목은 예시이며 사용자 기록이 아니다. 시안에서 빠진 기존 기능이나 하단 탐색을 삭제한다는 뜻은 아니다.

## 검토와 다음 단위

Product Design `ideate`로 사용자가 선택한 시각안을 보정했다. `better-layout` 지침으로 선택 경로와 목록의 스크롤·접근 가능한 대체 조작을, `better-typography` 지침으로 탭의 말줄임과 전체 이름을 읽는 경로를 검토했다. 이는 정적 시안에 대한 설계 검토이며 실제 화면 감사, 자동 접근성 검사 또는 사용성 시험이 아니다. 새 외부 앱을 조작하거나 새로운 자료 조사를 수행하지 않았다.

먼저 현재 계획 화면의 기존 가로 탭·목표 검색·선택 로직을 재사용해 전체 목표 선택을 분리하는 단위부터 진행한다. 목표별 일회성 항목·일정의 목록과 혼합 정렬은 API 계약 및 실제 지원을 확인한 후 별도로 연결한다. Android·iOS·Web 화면 동작과 확대·키보드·스크린리더는 아직 검증하지 않았다.
