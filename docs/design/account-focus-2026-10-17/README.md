# 계정 화면: 중복 도구를 덜어내는 구성 비교

2026-10-17 · 사용자 추천 1번 진행 승인 · 코드 반영·미커밋·미검증 · 생성 시안이며 실제 화면 캡처 아님

선택한 보조 메뉴 구현은 `19fb0b8`로 커밋했다. 사용자의 “추천하는 걸로 해서 진행해줘”에 따라 1번을 선택해 `/profile`의 중복 도구를 덜어내고 계정 상태와 로그인·로그아웃, 게스트 보관 안내에 집중하는 코드를 반영했다. 이번 시안·문서·구현은 아직 미커밋이며 검증은 보류했다.

## 비교와 추천

번호는 이번 대화에서 생성 이미지가 표시된 순서다. 앞서 열어 본 기존 계정 캡처는 시안 번호에 포함하지 않는다. 세 안 모두 동일한 Web 게스트 예시 상태이며 실제 사용자 데이터가 아니다.

| 번호 | 시안                                                         | 위계와 차이                                                          | 한계                                                                       |
| ---- | ------------------------------------------------------------ | -------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 1    | [계정과 보관 안내, 주요 행동](./01-account-action-stack.png) | 계정 상태 → 보관 안내 → 로그인 버튼 → 설정. 작업 도구 없는 세로 흐름 | 안내 영역의 강조가 커 보일 수 있어 기존 notice 토큰으로 보정 필요          |

**선택한 방향은 추천 1번**이다. 상태와 보관 안내를 먼저 읽고 다음 행동을 선택할 수 있으며 긴 이메일·설명·글자 확대도 세로로 수용하기 쉽다. 이는 사용자 조사 결과가 아니라 기존 요구와 코드에 근거한 판단이며 사용자가 추천안 진행을 승인했다.

## 구현 기록

- `ProfileOverview`를 작은 계정 제목 → 실제 계정 상태/설명 → 필요한 보관/오류 안내 → 전체 너비 계정 행동 → 설정 한 행으로 구성했다. 기존 카드·장식 아바타·중복 작업 도구·수제 Web 아이콘을 제거했다.
- 목표·검색·완료 기록·템플릿·공유 공간의 route는 제거하지 않는다. 이 화면에서만 링크를 덜어내고 아래 대체 경로 표의 기존 메뉴·하단 탭으로 접근한다. 설정은 계정 맥락의 관련 이동으로 남긴다.
- 실제 이름/이메일과 계정 종류는 기존 `getProfileAuthPresentation`을 재사용한다. 기본 문구와 인증 API/캐시 교체는 유지한다. 게스트 안내는 기존 플랫폼별 helper를 사용하며 보장되지 않은 동기화·복구 기능을 추가하지 않는다.
- 로그인은 기존 `/login`, 로그아웃은 기존 `logoutToGuest`로 연결한다. 계정 확인 중에는 버튼에 `계정 확인 중`을 표시하고 잠근다. 로그아웃 시작 직후 ref 잠금과 mutation pending 상태로 중복 제출을 막고 완료/실패 후 해제한다.
- 로그아웃 mutation과 후속 캐시 교체가 진행되는 동안 계정 전환 중이라는 중립 문구·loading/busy 상태를 표시하고 설정 이동도 잠근다. 인증 저장 변경 중의 중간 상태를 확정된 새 계정으로 안내하지 않는다.
- `logoutToGuest`는 logout 후 guest를 호출하며 logout은 finally에서 로컬 인증 정보를 지운다. 실패가 어느 단계인지 UI가 구분할 수 없으므로 기존의 `로그아웃은 완료했지만 새 게스트 계정을 시작하지 못했어요` 단정을 `계정 전환을 마치지 못했어요`로 고쳤다. 기존 오류 시 캐시 정리와 로그인/앱 재진입 복구 경로는 유지한다.
- 보관·전환 오류 안내는 기존 `InlineNotice`를 사용한다. 읽기 위한 본문 옵션 `messageVariant="body"`만 추가했으며 기본값은 caption으로 유지해 다른 notice의 글자 크기를 일괄 변경하지 않는다.
- 공통 헤더/하단 탭을 다시 만들지 않고 좌우 safe area와 기존 스크롤을 사용한다. 계정 행동은 최소 48dp, 설정은 최소 56dp이며 긴 이름·이메일·안내가 줄바꿈할 수 있게 고정 높이·말줄임을 사용하지 않는다. 설정 행의 키보드 초점 테두리와 disabled 상태를 제공한다.

구현 전 선택 이미지를 다시 직접 열어 확인했다. 본문 문구·버튼·notice는 공통 컴포넌트로 구현하고 이미지의 버튼 광택·장식 아이콘을 복제하지 않았다. 사용자 요청에 따라 테스트·`npm run validate`·실제 화면 감사는 실행하지 않았다. Android·iOS·Web에서의 실제 계정 전환·긴 이메일·글자 확대와 원본 대비 간격은 미확인이다.

## 유지할 역할과 경로

- 계정은 핵심 하단 탭이 아니다. 기존 네 탭을 유지하고 메뉴의 계정에서 `/profile`로 접근한다. 해당 숨김 route에서는 특정 핵심 탭을 임의로 선택 상태로 만들지 않는다.
- 로그인은 기존 `/login`, 로그아웃은 기존 `logoutToGuest`와 계정별 캐시 전환을 사용한다. 이번 시안을 새 인증 API·동기화·계정 삭제 기능으로 해석하지 않는다.
- 설정 한 행은 유지한다. 알림·동기부여 문구·사용 가이드를 계정 화면에 복제하지 않고 기존 `/settings`로 연결한다. 메뉴의 설정과 중복이지만 계정 관리 맥락에서 한 번의 관련 이동으로 허용하는 제안이다.
- 제거할 중복 도구의 대체 경로는 다음과 같다. 기존 route·데이터·deep link는 삭제하지 않는다.

| 계정의 기존 도구              | 대체 경로                                               |
| ----------------------------- | ------------------------------------------------------- |
| 목표 `/dday`                  | 하단 계획 `/plan`에서 목표 구성. 기존 `/dday` 주소 유지 |
| 검색 `/search`                | 메뉴 첫 행                                              |
| 날짜별 완료 기록 `/completed` | 메뉴의 기록 정리                                        |
| 할 일 템플릿 `/templates`     | 메뉴의 도구                                             |
| 공유 공간 `/workspaces`       | 메뉴의 도구                                             |

## 상태별 구현 경계

이번 세 이미지는 Web 게스트 상태 하나를 비교한다. 로그인된 상태·오류·처리 중 상태를 실제로 감사한 결과가 아니다.

- 게스트: 로그인 행동과 기존 `getGuestRecoveryMessage`를 사용한다. Web은 브라우저/주소, native는 기기/앱 데이터 안내를 적용한다. 이미지의 브라우저 문구를 native에 그대로 사용하지 않는다.
- 등록 계정: 실제 이메일/표시 이름을 사용하고 로그인 대신 로그아웃을 제공한다. 게스트 안내는 표시하지 않는다. 이름·이메일 수정, 비밀번호 변경·계정 삭제·데이터 내보내기·구독은 현재 API/화면에 없으므로 추가하지 않는다.
- 계정 확인 중: 현재 표현 helper는 로그인 label을 반환하므로 구현 시 확인 중임을 보이고 제출을 잠그는 범위를 검토한다. 이미 확인 중인 계정에서 새 로그인을 반복 시작하게 하지 않는다.
- 계정 확인 오류: 실제 오류와 기존 로그인/재진입 경로를 제공하며 등록/게스트라고 추측하지 않는다. 인증 재시도 API를 새로 가정하지 않는다.
- 로그아웃 처리 중: 중복 제출과 관련 행동을 잠그고 기존 mutation의 상태·캐시 교체를 보존한다. 실패 안내는 실제 인증 처리 결과의 범위와 맞는지 기존 API 코드를 함께 확인한다. 시안만으로 로그아웃 실패/후속 게스트 생성 실패를 동일하게 확정하지 않는다.
- UI만 정리하며 계정 간 데이터 이전·로그아웃·게스트 복구가 실제로 검증됐다고 표현하지 않는다.

## Product Design 검토와 구현 조건

- 대상/사용자 목적: 더보기 역할을 벗어난 계정 화면에서 현재 계정 상태와 계정 관련 다음 행동을 이해한다.
- 확인 자료: 현재 `ProfileOverview`, `getProfileAuthPresentation`, `getGuestRecoveryMessage`, 선택된 메뉴 코드와 [메뉴 결정](../menu-navigation-2026-10-17/README.md)을 읽었다. [기존 계정 캡처](../../screenshots/profile.png)를 직접 열어 반복 목록과 계정/안내 구성을 참고했다. 과거 캡처를 현재 감사 증거로 사용하지 않는다.
- 적용 도구: Product Design ideate와 내장 Image Gen. 기존 get-context의 제품 맥락을 재사용하고 목적과 범위를 대화에서 설명했다. preflight 결과 저장된 컨텍스트는 없어 대화/저장소를 사용했다. 각 생성에 기존 계정 캡처와 선택된 계획 시안 두 이미지를 실제로 전달했다.
- 참고 원칙: [메뉴 비교에서 확인한 공식 자료와 판단](../menu-navigation-2026-10-17/README.md)의 핵심/보조 목적지 구분을 재사용했다. 이번에 외부 앱이나 Figma를 새로 조작하지 않았고, 인증 UX의 최신 플랫폼 사양을 새로 확인했다고 주장하지 않는다.
- 세 생성 결과를 직접 확인했다. 모두 게스트 상태·보관 안내·로그인·설정과 중립 상태 네 탭을 포함하며 작업 도구 목록을 제거했다. 로그인/계정 전환이 실제로 작동하는 화면 캡처는 아니다.
- 여백은 기존 52dp 공통 헤더와 safe area를 재사용한다. `계정`은 작은 문맥 제목으로만 사용하고 큰 영웅 제목이나 새 상단 프로필 아이콘을 추가하지 않는다. 이미지의 긴 빈 하단을 채우려고 활동 지표나 기능을 추가하지 않는다.
- 이미지의 버튼 광택·그라데이션·큰 아이콘을 그대로 복제하지 않는다. 기존 Button·InlineNotice·AppText와 아이콘 라이브러리/테마를 사용한다. 작업 도구와 함께 제거되는 Web용 수제 아이콘 도형은 유지할 필요가 없다.
- 최소 44dp 터치 영역, 본문 14–16sp와 긴 이메일/경고 줄바꿈, focus/disabled/busy 상태를 구현 조건으로 둔다. 320dp·글자 확대·스크린리더·Web 키보드 동작은 시안으로 검증할 수 없다.
- 사용자 요청에 따라 실제 화면 감사·테스트·`npm run validate`는 보류했다. 예상 영향 플랫폼은 Android·iOS·Web이다. 별도 서버 구현이나 의존성은 필요하지 않은 범위다.
