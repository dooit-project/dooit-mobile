# UX Review

Last updated: 2026-10-21

현재 제품 결정과 남은 위험의 요약이다. 최신 근거는 [전체 UI/UX 감사](../audits/whole-app-2026-10-21/README.md), 수정 목록은 [후속 작업](../product/UI_UX_BACKLOG_2026-10-21.md), 구현 순서는 [로드맵](../product/ROADMAP.md)이다. 이전 문서의 Today 주간 strip·더보기 탭·완료 최근 3개 노출을 현재 구현으로 보지 않는다.

## 유지할 구조

- 하단은 오늘 / 달력 / 계획 / 돌아보기다. Drawer는 검색·기록함·다시 정리할 항목·보조 도구·계정/설정의 진입이다.
- 오늘은 그날의 실행이다. 큰 제목·상시 날짜·주 달력을 복원하지 않는다. 목표별 묶음과 간단한 체크를 기본으로 한다.
- 계획은 목표·선택 목표일·반복 정의·연결 항목의 생성/수정이다. 가로 목표 탭과 전체 목표 선택을 유지한다.
- 달력은 별도 하단 직접 진입으로 날짜별 항목을 찾는다. 현재 3주 그리드의 밀도와 주/월 이동 표시는 개선 대상이다.
- 돌아보기는 실제 행동의 기록이다. Goal 퍼센트·연속 달성 압박·기록 없는 성과/감정·AI 칭찬을 만들지 않는다.

## 공통 시각 기준

[최신 3번 목표 묶음 기준](./soft-goal-surfaces-2026-10-21/README.md)을 우선한다. 일반 본문 16/24, label 14/20, 보조 13/18, 목표 제목 18/26, 기본 헤더 52와 하단 탭 72에 플랫폼 inset을 더한다. 탭 label은 12/18이다. 화면별 정보 위계를 조정하며 전체 글자를 다시 같은 비율로 확대하지 않는다.

파란 브랜드/활성 선택·중립 회색 보조 정보·선형 아이콘을 사용한다. 오늘은 옅은 회색 바탕에 목표당 한 흰 묶음이며 항목마다 카드나 구분선을 넣지 않는다. 작은 동기부여 문구는 로고 옆에 두고 저자 표시는 설정 출처에서만 제공한다. 큰 명언 카드나 자동 팝업을 추가하지 않는다. 문구는 실제 실행 기록에 대한 평가가 아니다.

## 현재의 주요 미완료

- 매일 반복 계획이 있어도 오늘 회차 화면은 아직 연결하지 않았다. F3a-1 hook만 있다는 것을 실행 기능 완료로 표현하지 않는다.
- 개인 Task 상세는 아직 기존 D-Day 연결만 제공한다. 새 Goal과 D-Day의 ID를 구분해 연결하고 없는 ‘D-Day 탭’ 안내를 고친다.
- 오늘 빠른 작성은 기본 기록함 저장 후 오늘 이동이다. 오늘 문맥의 기본 목적지와 부분 성공 재시도 UX를 개선한다. 명시한 다른 날짜를 임의로 오늘로 바꾸지 않는다.
- 완료 후 오늘이 초기 빈 안내로 돌아가는 상태와 처음부터 할 일이 없는 날을 구분한다. 기록 취소·실제 Goal 여정은 후속이다.
- 상세의 빈 체크리스트 0/0·빈 설명·‘없음’ 정보와 중첩 카드는 주요 행동보다 낮은 위계로 정리한다.
- 반복 폼의 긴 필수 입력과 오류 필드가 화면 밖에 남는 문제를 해결한다. 이름/기본 행동의 중복 입력과 날짜/시간대 노출도 검토한다.
- 전체 목표 펼침의 본문 중복, 검색의 Task/D-Day 용어와 Goal 검색 범위, 선택적 첫 Goal 진입은 후속 목록을 따른다.
- mock 모듈 로드 날짜가 자정 뒤 일반 Task 완료에 사용되는 문제는 운영 서버 문제와 구분해 고친다.

## 접근성·검증 경계

- 터치 목표는 내부 44 이상이며 WCAG의 최소 기준과 구분한다. 측정한 달력 이전 주 버튼은 44×44다.
- 목표 tab의 Web aria-selected/tablist와 요일 버튼의 선택 상태가 빠져 있음을 DOM에서 확인했다. 시각 선택선만으로 완료 처리하지 않는다.
- Drawer Escape 닫기와 열기 버튼 초점 복귀는 실제 Web에서 확인했다. 전체 키보드·보조 기술 검증을 대신하지 않는다.
- 320px의 계획·회원가입과 390px 주요 흐름을 확인했다. native 글자 확대 1.5·키보드·safe area·dark·VoiceOver/TalkBack·대량 데이터·실제 네트워크 실패는 미검증이다.
- 공통 Button은 최소 높이를 사용하며 중요한 오류·결과 안내를 말줄임하지 않는다. light/dark 대비 자동 검사를 유지한다.
- 비활성 탭이 DOM snapshot에 남는 현상만으로 실제 보조 기술 노출을 단정하지 않는다.

## 인증·데이터·알림에서 유지할 조건

- 최초 사용은 `/start`의 게스트 시작/로그인 선택을 유지한다. 게스트 발급/토큰 확인 실패는 시작 단계에서 복구하며 Goal 입력을 강제하지 않는다.
- 게스트 데이터 보관 한계를 정확히 안내하고 실제 병합/동기화 완료를 과장하지 않는다. 계정 전환 뒤 이전 계정 캐시·문구·알림이 남지 않아야 한다.
- API/token 진단은 development build 전용이다. 실제 비밀 값은 화면 증거/문서에 남기지 않는다.
- 알림 권한을 최초 실행에서 강제하지 않고 거부 후 반복 요청하지 않는다. 실제 권한·전달·앱 종료/복귀는 native 검증 대상이다.
- Goal Plan 회차 알림과 연결 Task 알림을 중복 예약하지 않는다. 이번 UI 감사가 native 알림 연결 완료를 뜻하지 않는다.
- Workspace VIEWER에게 변경 행동을 제공한 뒤 403으로 막는 흐름을 기본으로 삼지 않는다. 이번 감사에서는 게스트 입구만 확인했다.
