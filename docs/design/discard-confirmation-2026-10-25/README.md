## 시안 검토와 남은 보정

세 결과를 직접 확인했다. 공통으로 노란/갈색 경고와 검은 focus 사각형이 빠지고 계속 작성이 파란 주 행동으로 표시된다. 버리기는 보조 red이며 두 행동의 의미/한국어 문구를 확인했다. 시각 생성 결과를 상호작용·접근성 검증으로 확대하지 않는다.

선택 후 보정할 차이도 남아 있다.

- 1의 버리기 경계는 최초 생성 시 검토 항목이었다. 2026-10-26 사용자가 해당 원본을 선택했으므로 얇은 중립 경계·빨간 글자를 그대로 적용한다. 별도 보정 이미지나 추가 선택이 필요한 구조 변경은 없다.
- 1/2의 배경에는 기존 개별 유형 버튼과 폼의 보조 문구/선이 남았다. 이번 선택은 확인창 구조이고, 이 표현을 새 공통 필드/선택 기준으로 승인한 것이 아니다.
- 파란 채움의 미세한 색 변화/이미지 질감, 패널 시작 위치·배경 문구/서체/반경은 래스터 근사다. 구현에서는 기존 `AppText`·색/간격 토큰·공통 컴포넌트를 사용하고 무단으로 전체 header/폼 수치를 바꾸지 않는다.
- 3의 넓은 빈 면은 구조 비교의 일부다. 큰 확인 페이지가 필요한지 사용자 선택 전에 비용으로 판단한다. 빈 곳에 장식/기능을 추가해 채우지 않는다.

## 구현 조건과 다음 단계

실제 dirty가 없으면 확인을 띄우지 않는다. 확인 중에는 기존 폼 비활성, 키보드·보조 기술 초점 범위 고정, 계속 작성/Escape/Back은 확인만 닫고 기존 입력/스크롤/적절한 초점으로 복귀한다. 명시적인 버리기만 원래의 상세 닫기/편집 취소 의도를 실행한다. Web/Android/iOS의 방법과 실제 native 한계는 따로 검사한다. 색만으로 버튼 의미를 전달하지 않고44px 조작 영역과 긴 문구를 유지한다.
