## 정확한 이미지 대응

번호는 이번 대화에서 생성 결과가 **실제로 표시된 순서**에 연결했다. 생성 호출 계획 순서로 재추정하지 않는다. 아래 파일이 이 세트의 정확한 원본이다. 사용자가 목표를 세로로 이어 보여주는 추천 이미지를 확인한 뒤 모바일과 같은 사용 방식을 우선하는 방향에 동의했다. 선택한 구조 원본은 **01-workspace-canvas.png**이며, 첨부했던 목표 두 열 이미지03과 구분한다. 생성 이미지의 모든 세부 요소/크기를 승인한 것으로 확대하지 않는다.

## 확인한 참조/도구

- [현재 실제 PC1440](./current-wide-1440.jpg): Chrome 확장1, localhost8082, mock/goal-lanes,1440×1024, light. 저장 파일을 직접 열고 중앙720 제한/좌우 빈 공간을 확인했다. 같은 Chrome viewport override를 복구한 뒤 촬영했고 검토 후 reset했다. 운영/실사용자 데이터는 아니다.
- [사용자 오늘 원본](../goal-lanes-correction-2026-10-21/reference.png), [현재 상세390](../../audits/task-goal-navigation-2026-10-25/01-detail-390.jpg)을 직접 열었다.
- 위 세 이미지를 세 ImageGen 호출 각각에 실제 로컬 경로로 첨부했다. 텍스트만으로 시안을 추정하지 않았다. 독립적인 세 결과를 생성했고 한 이미지에 여러 안을 합치지 않았다.
- user-context preflight: 저장 context 없음. 현재 대화/저장소의 사용자 결정과 공통 토큰을 사용했다.
- 외부 비교는 brief에 연결된 공식 Todoist sidebar/Android list-detail 조사 재사용. 외부 앱 실행/Figma 사용/새 plugin 설치/공통 컴포넌트 변경은 없다.
- [프롬프트 조건 기록](./PROMPTS.md): 실제 호출 조건을 재현할 수 있게 정리한 요약이다. 원래 긴 호출 문자열과 token 단위로 동일한 transcript는 아니다.

## 시안 단계 검토

공통으로: 전체 작업 공간·목록/상세 동시 읽기·기존 목표색/레일·동기부여 문구·원형 체크를 유지한다. PC의 주요 탐색은 왼쪽으로 옮기고 모바일 네 탭은 그대로 남기는 제안이다. 새 대시보드 지표/퍼센트/연속 달성/가짜 성과는 넣지 않았다. 선택된 행의 옅은 배경은 현재 선택 표시이며 모든 Task를 카드로 바꾸는 제안이 아니다.

1번은 현재 모바일의 목표별 세로 읽기 순서를 가장 적게 바꾸는 설계다. 사이드바 폭/접기·중앙 읽기 폭/상세 최소 폭은 실제 창 크기로 검증해야 한다.2번은 작업 폭이 넓지만 생성 이미지에 dooit이 rail과 헤더에 **중복**되어 있다. 선택 시 브랜드를 한 곳으로 모으는 보정을 먼저 보여줘야 한다.3번은 두 목표를 나란히 보지만 목표 수/긴 이름/항목 수 차이와 좁아진 각 열이 부담이다. 목표가 늘었을 때 임의로 계속 가로 열을 추가하지 않고 재배치 규칙을 정해야 한다.

세 결과 모두 Inspector에 생긴 가로 구분선과 생성기의 글자/아이콘 수치·광학 중심을 그대로 새 공통 규칙으로 승격하지 않는다. 선택 후 현재16/24 본문·13/18 보조·18/26 섹션·22/30 상세 제목과 공통 아이콘/터치 토큰으로 정리한다. 아이콘은 정보 블록 중앙, 제목 체크는 첫 줄 중앙을 실제 새 좌표와 캡처로 확인해야 한다. 생성 이미지의 제어 요소는 작동하거나 키보드 접근 가능한 상태가 아니다.

이 검토는 시각안의 구조/위계/밀도/발견 가능성·접근성 위험을 정리한 것이다. 실제 앱의 읽기 순서·Tab/Escape·스크린리더·44px hit target·변경 중 창 축소/직접 URL·모바일/native 회귀는 선택 후 구현/감사에서 확인한다. 시안 선호를 사용성 테스트 결과로 표현하지 않는다.

선택 후 Product Design ideate의 선택 단계와 저장소 정책에 따라 정확한 파일/보정 범위를 고정하고 구현한다. 저장소 제품 원본은 위 PNG/brief/구현 가이드로 유지한다.

## 사용자 선택 후 범위

사용자 최신 결정: 모바일과 같은 세로 읽기/체크 흐름을 우선한다. PC는01의 왼쪽 탐색·가운데 세로 목록·선택 시 우측 상세 방향을 후속으로 확장한다. 모바일의 미완료 UX 보완(R2 등)을 우선하며 PC shell을 바로 구현하지 않는다.

제목 앞 원에 대한 질문 후 사용자는 작은 전체 완료 체크 유지와 오늘 목록과 같은 크기/사용 방식에 동의했다. 실제 기준은24px 시각 크기/44px 조작 영역이며 현재 코드와 같다. 생성 이미지에서 커진 원을 실제 공통 토큰으로 옮기지 않는다. 이 결정으로 체크를 제거하거나 큰 원을 적용하지 않는다.
