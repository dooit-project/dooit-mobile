# Task 편집의 알림·반복 노출 비교

2026-10-26 · 사용자 선택: 첫 번째 속성 행 · 구현/실제 감사는 아래 연결

버튼 밀도가 남은 [실제 재감사](../../audits/task-form-density-review-2026-10-26/README.md)에 따라 새 정보 구조를 비교한다. Product Design audit/get-context/ideate와 built-in Image Gen을 사용했다. 아래 번호는 대화에 실제 표시된 세 독립 결과의 순서다. 생성 시안이며 실제 화면 캡처가 아니다. 정확한 입력은 [프롬프트](./prompts.json)에 보존했다.

| 표시 번호 | 정확한 파일                             | 노출과 편집 방식                                                        | 판단                                                      |
| --------- | --------------------------------------- | ----------------------------------------------------------------------- | --------------------------------------------------------- |
| 1         | [속성 행](./01-property-rows.png)       | 알림/반복 현재 값을 두 행으로 노출하고 필요한 속성만 전용 선택기로 편집 | 추천. 상태를 바로 읽고 여러 그룹의 동시 노출을 없앰       |
| 2         | [행별 펼침](./02-inline-disclosure.png) | 한 속성만 inline 펼침. 시안은 반복을 편집 중인 스크롤 상태              | 이동은 적지만 목록 확장으로 아래 내용이 밀리고 긴 폼이 됨 |
| 3         | [별도 설정](./03-settings-view.png)     | 부모에는 알림·반복 한 요약 행, 별도 화면에서 두 속성과 custom 간격 편집 | 집중하기 쉽지만 단일 속성 변경에도 진입/적용이 추가됨     |

세 안은 기본 제목/유형/날짜/종일/시각과 저장 계약을 유지한다. 알림7개·반복5개·직접 단위3개를 삭제하는 제안이 아니다. 선택지를 필요한 편집 순간에 제공한다. 설명/예상 시간/카테고리는 기존 추가 정보로 남긴다. 사용자 선택한 중앙 변경 버리기 확인과 오늘/하단 탭은 범위 밖이다. 생성 이미지의 임의적인 경계·아이콘·그림자/글자 크기를 전역 승인으로 확장하지 않는다.

목표는390×844이며 출력 PNG는853×1844다. 이미지1은 기본 편집, 이미지2는 반복을 펼친 편집 위치, 이미지3은 별도 설정 화면이므로 같은 상태의 픽셀 비교가 아니다. 직접 이미지를 확인했으며 1의 얇은 구분선/작은 상단 맥락·2의 펼침 영역·3의 설정 집중 구조를 비교했다. 2의 넓은 회색 면과 3의 테두리 선택기는 필수 구현 조건이 아니다.

선택 후 필요한 구현 조건:

- 1: 기존 패널 안에서 선택기로 전환하고 뒤로 가면 원래 입력·스크롤·초점 복원. 새 sheet 중첩은 피함. 일반 단일 선택은 선택 즉시 초안 반영/복귀, custom 반복은 유효한 간격을 적용한 뒤 복귀.
- 2: 한 번에 한 속성만 펼침, expanded/selected 전달, 선택 후 접기와 초점 복귀. Custom 간격은 선택 직후 닫지 않음.
- 3: 자식 설정의 로컬 초안과 부모 초안 구분. 적용은 부모에만 반영하며 Task 저장은 부모의 수정 완료에서 수행. 뒤로는 자식 변경 취소.
- 공통: 종일 알림 제한/변환과 시각 보존, custom 간격 오류 표시·복구, 44px 조작·긴 요약 줄바꿈·320/390/430·확대/키보드/Back·dirty 확인. 운영 API 계약은 변경하지 않음.

사용자는 첨부한 첫 번째와 두 번째의 비교 설명을 확인한 뒤 첫 번째 진행을 승인했다. 정확한 선택 원본은01-property-rows.png다. [구현과 실제 감사](../../audits/task-form-properties-2026-10-26/README.md)에서 확인 범위와 미확인 상태를 구분한다. 세 생성 이미지 자체를 동작/접근성 통과 근거로 쓰지 않는다. 커밋/푸시는 별도 승인 전 진행하지 않는다.
