# 최초 사용과 게스트 온보딩

ToDoLab을 처음 여는 사용자가 인증 오류를 보지 않고, 데이터 보존 방식을 이해한 상태에서 바로 첫 Task를 만들도록 하는 제품 흐름이다.

## 2026-08-09 현재 상태

현재 인증 bootstrap은 저장 token이 없으면 서버 게스트를 자동 생성하고, 성공하면 별도 안내 없이 Today로 이동한다. 저장 token이 있으면 `/auth/me`로 계정을 확인한 뒤 Today를 연다.

- 성공: 샘플 일정과 Task가 채워진 Today가 첫 화면이다.
- 실패: Today를 열지 않고 `ToDoLab을 시작하지 못했어요` 재시도 화면을 표시한다.
- 게스트 안내: Profile에 들어가야 `게스트로 사용 중`, 로그인 후 연결 가능, 앱 데이터 삭제 시 복구 불가 안내를 볼 수 있다.
- 로그인: Profile의 로그인 버튼에서 진입하며 로그인·회원가입 성공 뒤 게스트 데이터를 연결하도록 클라이언트가 준비돼 있다. 실제 병합 정확성은 백엔드 계약과 real smoke가 남아 있다.
- 온보딩: 최초 실행 여부, 시작 방식 선택, 기능 소개, 맥락형 도움말은 아직 없다.

기존처럼 Today의 각 데이터 영역에 `인증 정보가 필요합니다`가 반복되는 상태는 bootstrap 단계에서 막았다. 다만 게스트 발급 API가 준비되지 않았거나 네트워크가 없으면 앱 전체가 재시도 화면에서 멈추고, 로그인으로 우회할 수도 없다.

## 제품 용어

현재 구조는 순수한 로컬 전용 모드가 아니다. 데이터 기능은 서버가 만든 게스트 사용자와 access token을 사용하고 첫 시작에도 네트워크가 필요하다.

- 기본 버튼: `로그인 없이 시작`
- 보조 설명: `이 기기에서 게스트로 시작하고 나중에 계정에 연결할 수 있어요.`
- 계정 버튼: `로그인 또는 계정 만들기`
- 사용하지 않을 표현: `로컬에만 저장`, `오프라인으로 시작`, `단말 계정`

진짜 로컬 전용 모드를 제공하려면 로컬 데이터베이스, 변경 queue, 동기화와 충돌 해결, 삭제·재설치 복구 정책을 별도 설계해야 한다. 현재 게스트 MVP와 같은 기능으로 취급하지 않는다.

## 목표 흐름

### 1. 앱 시작

1. splash 뒤 저장 token을 확인한다.
2. 유효한 token이 있으면 `/auth/me`를 확인하고 기존 세션으로 Today를 연다.
3. token이 없으면 서버 게스트를 자동 생성하지 않고 시작 안내를 연다.
4. token 확인이 실패하면 데이터 화면을 열지 않고 현재 계정 보존을 우선한 복구 화면을 연다.

### 2. 시작 안내

한 화면에서 가치와 저장 방식을 설명하고 바로 선택하게 한다. 여러 장의 필수 소개 슬라이드보다 행동 선택을 우선한다.

- 제목: `오늘 할 일부터 가볍게 시작해요`
- 설명: `Task, 일정, D-Day를 한곳에서 계획하고 완료 흐름을 기록할 수 있어요.`
- 기본 CTA: `로그인 없이 시작`
- 기본 CTA 보조 문구: `게스트 데이터는 이 앱에 연결되며, 나중에 로그인하면 계정으로 옮길 수 있어요.`
- 보조 CTA: `로그인 또는 계정 만들기`
- 하단 링크: `기능 둘러보기`

기능 둘러보기는 선택 사항이며 다시 보지 않기 상태를 저장한다. 알림 권한이나 상세 설정은 이 단계에서 요구하지 않는다.

### 3. 게스트 시작

1. 사용자가 `로그인 없이 시작`을 누른 뒤 게스트 생성 요청을 보낸다.
2. 버튼 내부 진행 상태를 표시하고 중복 요청을 막는다.
3. 성공하면 온보딩 완료 버전을 저장하고 빈 Today를 연다.
4. 실패하면 같은 화면에서 이유와 재시도를 제공한다. `로그인 또는 계정 만들기` 우회도 유지한다.

실패 시 사용자가 보는 문구는 인증 구현보다 다음 행동을 설명한다.

- 제목: `지금은 게스트로 시작할 수 없어요`
- 설명: `인터넷 연결을 확인하고 다시 시도하거나, 기존 계정으로 로그인해 주세요.`
- CTA: `다시 시도`
- 보조 CTA: `로그인하기`

### 4. 첫 성공 경험

실제 API의 신규 게스트에게 mock 샘플 데이터를 사용자 데이터처럼 보여주지 않는다. 빈 Today에서 한 가지 행동을 바로 완료하도록 한다.

1. 빈 상태 제목: `오늘 할 일을 하나 적어볼까요?`
2. 예시 placeholder: `예: 오후 3시 병원 예약`
3. 사용자가 첫 Task를 저장한다.
4. 저장 성공 뒤 해당 Task를 Today 목록에서 바로 보여준다.
5. 첫 Task 주변에서 완료 체크 방법을 한 번만 안내한다.

### 5. 기능 학습

필수 온보딩은 시작 방식 선택까지만 둔다. 기능은 실제 화면 가까이에서 한 번에 하나씩 설명한다.

| 계기                | 안내                                    | 완료 조건                  |
| ------------------- | --------------------------------------- | -------------------------- |
| 첫 Today 진입       | 빠른 기록과 완료 체크                   | 첫 Task 생성 또는 건너뛰기 |
| 첫 Calendar 진입    | 날짜별 Task·일정과 여러 날 일정         | 날짜 1회 선택              |
| 첫 D-Day 진입       | 중요한 날짜를 만들고 관련 Task 연결     | D-Day 생성 또는 건너뛰기   |
| 첫 정리할 항목 진입 | 미완료·추천·기록함을 오늘 계획으로 정리 | 항목 1회 처리              |
| 첫 Search 진입      | 과거 Task·일정·완료 기록 검색           | 검색 1회 또는 닫기         |

각 안내에는 `건너뛰기`가 있고 Settings의 `앱 사용 가이드 다시 보기`에서 재실행할 수 있어야 한다. 기능을 설명하기 위한 가짜 데이터 대신 짧은 설명, 빈 상태, 실제 사용자의 첫 행동을 조합한다.

### 6. 계정 연결

- Profile 상단에 게스트 상태와 `계정에 연결` CTA를 유지한다.
- 앱 데이터 삭제 전에는 복구할 수 없다는 경고를 과도하게 반복하지 않고 Profile과 계정 연결 진입에 표시한다.
- 로그인·회원가입 요청에는 유효한 게스트 token을 유지한다.
- 서버 병합·승격 성공을 확인한 뒤에만 정식 token으로 교체한다.
- 성공 뒤 Today에서 `Task N개, D-Day N개를 계정에 연결했어요`처럼 결과를 보여준다. 서버가 종류별 개수를 제공하지 않으면 현재의 일반 성공 문구를 사용한다.
- 실패하면 게스트 세션과 작성 데이터를 유지하고 같은 화면에서 재시도한다.

## 오류와 복구 상태표

| 상태                 | 이동                  | 사용자에게 제공할 행동           | 금지 사항                    |
| -------------------- | --------------------- | -------------------------------- | ---------------------------- |
| token 없음           | 시작 안내             | 게스트 시작, 로그인, 계정 만들기 | Today query 선실행           |
| 게스트 생성 중       | 시작 안내 유지        | 취소 없이 진행 표시              | 중복 요청, 빈 화면           |
| 게스트 생성 실패     | 시작 안내 오류 상태   | 재시도, 로그인                   | Today의 영역별 인증 오류     |
| 저장 token 확인 실패 | 계정 복구 화면        | 재시도, 정식 계정이면 로그인     | 새 게스트 자동 발급          |
| 정식 token 만료      | 로그인                | 재로그인, 만료 안내              | 게스트 자동 전환             |
| 게스트 token 만료    | 게스트 복구 화면      | 같은 guest id의 갱신·재인증      | 새 guest id 생성             |
| 병합·승격 실패       | 로그인·가입 화면 유지 | 재시도, 게스트로 돌아가기        | 기존 guest token·cache 삭제  |
| 데이터 query 실패    | 현재 데이터 화면      | 기존 cache 유지, 새로고침        | 인증 실패로 단정한 공통 문구 |

## 다른 앱과 플랫폼 지침에서 가져올 원칙

- Apple HIG는 온보딩을 빠르고 선택 가능하게 만들고, 많은 내용을 한 번에 외우게 하기보다 실제 UI 근처의 맥락형 도움말을 권장한다. 비필수 설정과 권한 요청은 해당 기능을 사용할 때까지 미루는 기준을 적용한다.
- Todoist의 시작 가이드는 프로젝트, Inbox, 날짜, Today처럼 핵심 행동을 실제 작업 순서로 설명하고 입력란에 자연어 예시를 제공한다. ToDoLab도 기능 목록보다 첫 Task 생성과 Today 계획에 집중한다.
- Things는 Today, Upcoming, Inbox 등 기본 목록의 목적을 도움말에서 단계적으로 설명하고, 동기화 계정은 별도 안내한다. ToDoLab도 기본 화면의 역할과 계정 연결 설명을 분리한다.
- TickTick은 캘린더, 반복 알림, 습관, 집중, countdown처럼 기능 범위가 넓지만 한 시작 화면에서 모두 가르치지 않는다. ToDoLab의 D-Day와 반복 일정도 해당 화면에 처음 들어갈 때 안내한다.

## 구현·검증 단위

1. 온보딩 완료 버전과 기능별 안내 완료 상태를 저장하는 preference 계층을 만든다.
2. 인증 bootstrap을 `세션 복원`과 `첫 시작 선택`으로 분리한다.
3. 시작 안내 route와 게스트 생성·로그인 우회·재시도 상태를 구현한다.
4. 실제 신규 사용자의 Today 빈 상태와 첫 Task 작성 흐름을 구현한다.
5. Today, Calendar, D-Day에 맥락형 도움말을 추가하고 Settings에 다시 보기 진입을 둔다.
6. 게스트 token 만료·병합 실패 복구는 백엔드 계약이 준비되면 연결한다.
7. Android, iOS, Web에서 최초 설치, 재실행, offline, API 4xx/5xx, 큰 글꼴, 화면 읽기 순서를 검증한다.

온보딩 완료 여부는 boolean 하나가 아니라 버전으로 관리한다. 이후 중요한 정책 안내가 추가돼도 기존 사용자의 기능별 도움말 상태를 불필요하게 초기화하지 않도록 `onboardingVersion`과 개별 tip id를 분리한다.
