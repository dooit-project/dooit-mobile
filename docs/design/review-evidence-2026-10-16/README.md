2026-10-17 · 추천 1번으로 코드 반영 · 생성 이미지, 실제 앱 캡처 아님 · 구현 미검증

동기부여 문구 노출 설정/이력 단계는 `b1915a1`로 커밋했다. 다음 단계는 날짜별 체크 개수를 중심으로 보여주는 기존 돌아보기를 실제 한 일과 목표의 관계를 읽을 수 있는 화면으로 확장하는 것이다.

**추천은 1번**이다. 사용자의 목적이 단순 활동량보다 원하는 방향에 대한 행동의 증거를 확인하는 것이므로 목표별 실제 제목을 우선한다. 이는 사용자 조사 결과가 아니라 현재 요구와 확인한 코드에 근거한 설계 판단이다. 세 안과 추천을 제시한 뒤 사용자의 “커밋하고 다음꺼 하자”를 추천안 진행 지시로 해석해 그 방향을 알리고 구현했다. 사용자가 번호를 직접 지정한 것은 아니다.

## 2026-10-17 구현 범위

- 시안·검토 문서는 `e57202e`, 목표별 주간 기록 구현은 `ce0c007`로 커밋했다. 구현 검증은 보류 상태다.
- 돌아보기 탭은 `WeeklyEvidenceOverview`로 전환한다. 기존 `/completed`의 날짜별 완료 취소·상세 경로는 유지한다.
- 기존 날짜별 완료 조회를 재사용해 목표별 제목·완료 기록 수·서로 다른 기록 날짜 수·원본 제목·날짜를 보여준다. 목표 미연결 기록은 마지막 `일상의 기록`에 모은다. 활동 없는 목표나 빈 날짜 목록은 추가하지 않는다.
- 날짜는 날짜별 완료 조회의 응답 소속을 사용한다. 예정일·마감일·일정 시작일로 대체하거나 시각 문자열을 임의 시간대로 변환하지 않는다. 서버의 날짜 필터 의미와 과거 목표 귀속 보존은 실 API 확인이 남아 있다.
- 동일 Task ID는 주간에서 한 번 집계하고 같은 제목의 서로 다른 회차 ID는 유지한다. 목표는 첫 기록이 등장한 순서, 각 목표 안 기록은 날짜 오름차순이다. 계획 탭에서 정한 관리 순서를 회고 목록에 억지로 적용하지 않는다.
- 주 이동·이번 주 복귀를 제공하고 현재 주에서는 다음 주 이동을 비활성화한다. 다른 연도의 기록은 연도를 함께 표기한다. 현재 주와 과거 주 문구를 구분한다.
- 각 목표당 20개씩 표시하고 `더 보기`로 늘린다. 집계는 화면에 펼친 개수와 무관하게 전체 수신 기록을 사용한다. 서버 페이지네이션이나 전체 기간 여정은 새로 가정하지 않는다.
- 조회 중에는 골격, 한 날짜라도 오류면 오류/재시도를 표시한다. 부분 조회 결과를 전체 집계나 빈 상태로 보여주지 않는다. 빈 상태는 저장된 기록이 없다는 사실과 오늘로 돌아가는 경로만 안내한다.
- 행을 누르면 기존 Task 상세로 이동한다. 체크박스를 반복하지 않는다. 주 이동/기록 행의 최소 44dp 터치 영역, 키보드 초점 배경과 테두리, 전체 날짜 접근성 이름, 제목 줄바꿈을 코드에 반영했다. 실제 작동·확대·대량 목록의 성능 확인은 보류했다.
- 추가 API·AI 호출·의존성은 없다. 기존 목표 색상 저장/대체 색상을 재사용한다. 제목의 계획 분량을 실제 수행량으로 합산하지 않는다.

영향 플랫폼은 Android·iOS·Web이다. 사용자 요청에 따라 `npm run validate`, 테스트와 구현 후 실제 화면 감사는 실행하지 않았다. 시안 검토·코드 반영을 실제 화면 검증 완료로 취급하지 않는다.

## 공통 제품 기준

- 기존 dooit 헤더·작은 동기 문구·목표 색상·4개 하단 탭 유지. 이번 화면은 돌아보기 탭 활성 상태다.
- 큰 페이지 제목과 주 달력의 숫자 격자를 추가하지 않고 간결한 주간 이동/이번 주 복귀를 제공한다.
- 기록 제목과 날짜가 중심이다. 달성률·연속 달성·목표 점수 추정·과장된 격려를 넣지 않는다.
- 수치는 완료 기록 수와 실제 기록 날짜 수만 사용한다. 제목의 계획 분량을 실제 학습량으로 합산하지 않는다.
- 기록 없는 날을 실패나 의지 부족으로 해석하지 않는다. 일주일 전체를 만회하도록 요구하지 않는다.
- 읽는 화면에 완료 체크 조작을 반복 노출하지 않는다. 원본 상세를 열어 수정/완료 취소할 수 있는 기존 경로는 유지한다.
- 주 이동/행 터치 영역은 충분히 확보하고 글자 확대 시 잘라내지 않는다. 이미지의 여백과 글자 크기를 픽셀 명세로 그대로 복제하지 않는다.
- 헤더는 기존 52dp 기본 높이와 안전 영역 기준을 재사용한다. 새 독립 상단 여백을 덧붙이지 않는다.

## 확인한 기존 기능과 구현 경계

- `CompletedOverview`: 주 이동·날짜별 완료 목록·상세 진입·완료 취소·오류 재시도·20개 단위 더 보기.
- `useCompletedWeek`: 기존 `GET /tasks/done?date=...`를 주간의 날짜별로 조회한다. `TaskResponse`의 제목·목표 ID/이름·완료 시각과 날짜별 완료 원본을 재사용할 수 있다.
- 1번 선택 시 먼저 기존 주간 완료 Task에서 목표별 목록을 만든다. 동일 원본 ID를 중복 집계하지 않으며 조회 실패나 일부 로딩을 0개 성과로 바꾸지 않는다.
- 범위 문구는 선택된 주를 따른다. 지난주를 보고 있을 때 `이번 주`라는 집계 문구를 잘못 붙이지 않는다.
- 기존 응답이 현재 목표 소속/이름을 보여주는지 완료 당시 스냅샷을 보존하는지는 확인이 필요하다. 이 UI만으로 과거 귀속 보존을 보장하지 않는다.
- 기본/최소 행동, 휴식/미실행, 실제 학습량·감정·피로도는 현재 완료 Task만으로 추론하지 않는다.
- Goal의 전체 여정·별도 반복 실천·직접 완료 기록 통합·AI 요약은 [백엔드 변경 요청서](../../api/API_GOAL_JOURNEY_CHANGE_REQUEST.md)의 계약 확인 후 연결한다. 이번 주 목록을 목표 시작 이후 전체 기록이라고 표현하지 않는다.
- 신규 서버 엔드포인트를 가정해서 호출하거나 mock 수치로 실제 피드백을 채우지 않는다.

## Product Design 검토와 한계

대상은 원하는 삶을 위한 실제 행동을 돌아보는 모바일 주간 화면이다. 기존 코드와 선택된 [계획 탭 시안](../plan-navigation-2026-10-15/05-goal-tabs-polished.png)을 직접 확인하고 Product Design ideate와 내장 Image Gen으로 구조 세 가지를 만들었다. 각 생성 호출에 실제 참고 이미지와 동일 예시 데이터를 전달했다. 이 작업에서 Figma·외부 운영 앱을 새로 조작하거나 실제 앱 화면을 감사하지 않았다.

정보 위계·목표/날짜 탐색의 차이·계획과 회고의 역할·원본 근거·접근성 위험을 비교했다. 터치/스크롤/긴 제목/목표 다수/글자 확대/빈 상태/조회 실패/완료 취소 동작은 이미지로 검증할 수 없다. 사용자 요청에 따라 실제 화면 감사와 `npm run validate`는 보류했다. 예상 영향 플랫폼은 Android·iOS·Web이다.

이미지 세 개를 직접 확인했으며 날짜/예시 원본 구성은 위 표와 일치한다. 세부 간격·큰 글자·타임라인 선·원형 주 이동 버튼은 구현 전 선택안에 맞춰 보정할 수 있다.
