# 달력: 선택 날짜와 표시 범위의 데이터 일치

2026-10-18 · 코드 반영·미커밋·미검증

빠른 기록 수정과 별도 백엔드 요청서는 `6b7ac90`으로 커밋했다. 유형 보존 계약은 여전히 미전달·미합의다. 이번에는 로드맵 U4에서 프론트만으로 해결할 수 있는 달력 조회 범위를 정리했다. 달력 배치·탭·주간 이동/월 선택 구조를 새로 선택하는 작업은 아니다.

## 확인한 문제

- `WeekCalendar`는 선택 주의 전후를 포함한 21일을 보여주지만 일정은 선택 날짜가 속한 한 달만 조회했다. 월초/월말에는 옆 달의 날짜가 보여도 그 달만의 일정은 응답 범위에 포함되지 않을 수 있었다.
- 날짜별 목록 query가 `keepPreviousData`를 사용했다. 캐시가 없는 날짜로 전환하면 이전 날짜의 결과를 새 날짜 맥락에서 잠시 보여줄 수 있는 코드였다. 그 상태의 완료 버튼도 새 선택 날짜 mutation을 사용하므로 날짜 구분이 중요하다.
- 달력 범위 조회는 실패/로딩 상태가 화면에 드러나지 않았다. 일정 표시가 없을 때 실제 없음과 아직 조회되지 않음의 구분이 어려웠다.

이는 기존 코드에서 확인한 가능성과 범위 불일치다. 이번에 앱에서 실제 재현하거나 운영 응답을 확인한 결과가 아니다.

## 이번 변경

- 표시하는 날짜들에서 유효한 `YYYY-MM-01` 목록을 만들고 각 달을 기존 MONTH API로 조회한다. 현재 21일 범위는 한 달 또는 두 달이며 임의의 새 서버 엔드포인트를 가정하지 않는다. API serializer의 기존 `YYYY-MM` 전송 규칙을 재사용한다.
- 같은 월 안에서는 같은 월 첫날 query key를 사용해 날짜를 누를 때마다 월 조회 캐시가 분산되는 것을 줄였다.
- 월 경계에 걸친 같은 Task ID의 일정은 한 번만 합친다. 서로 다른 ID의 반복 회차는 유지하고 기존 기간 막대/하루 일정 배치는 같은 데이터를 받는다.
- 필요한 모든 달의 조회가 준비된 뒤 합친 결과를 표시한다. 일부 월이 로딩/실패한 상태를 전체 결과로 보여주지 않고 기존 텍스트/InlineNotice/Button으로 로딩·오류/재시도를 제공한다. 날짜 선택 자체는 계속 사용할 수 있다.
- 날짜별 예정/완료 조회에서는 이전 날짜 placeholder를 제거했다. 현재 날짜의 캐시는 재사용하며 캐시가 없을 때는 기존 skeleton, 조회 실패 시 기존 오류/재시도를 사용한다.
- 날짜별 목록을 선택 날짜 key로 분리해 이전 날짜의 완료 mutation pending/error 표시가 새 날짜에 남지 않게 했다. 이미 요청한 완료 mutation을 취소하거나 다른 날짜의 요청으로 바꾸지 않는다.
- 기존 `Calendar`·`Task` 안내 일부를 `달력`·`항목`으로 맞췄다. 신규 화면이나 기능 메뉴는 추가하지 않았다.
- 기존 날짜 일관성 테스트 파일에 월초와 연말의 인접 월 포함·월 key 안정성·잘못된 날짜 제외 사례를 추가했다. 실행은 보류했다.

## Product Design 검토와 한계

대상은 선택 날짜에서 올바른 일을 읽고 조작하는 기존 달력 흐름이다. 구현 전 현재 달력 코드·날짜 배열/레이아웃·날짜별 query·일정 막대와 기존 MONTH serializer를 읽었다. [기존 달력 캡처](../screenshots/calendar.png)를 직접 열어 기존 헤더·날짜 그리드·하단 목록 위치를 참고했다. 과거 캡처를 현재 구현 감사 증거로 사용하지 않는다.

기존 선택 구조와 공통 컴포넌트의 상태 표현을 재사용하는 국소 수정이므로 새 시각안 세 개를 만들지 않았다. Product Design의 상태 일치·오류 복구·원본 근거와 저장소 기본 검토 기준을 적용했다. 새 Figma 파일·생성 이미지·외부 앱 조작은 없다. 화면 안에 새로운 빈 기록 숫자나 성과 추정을 추가하지 않는다.

영향 플랫폼은 Android·iOS·Web이다. 사용자 요청에 따라 실제 화면 감사·기기/브라우저 재현·mock/real API 확인·`npm run validate`·테스트 실행은 보류했다. 코드 반영과 사례 추가를 통과로 기록하지 않는다. 서버의 월 범위 일정/반복 회차 반환·지연/부분 실패·날짜를 빨리 전환하는 동작은 실제 확인이 남아 있다.

## 다음 범위

이번 변경으로 달력 밀도·3주/월간 표시 방식·목표/일정 색상·탐색 버튼의 전체 디자인 검토가 끝난 것은 아니다. 현재 3주 구조를 유지했으며 큰 변경은 시각 비교 후 선택한다. 앱을 자정 넘게 열어 둔 경우의 오늘 표시/오늘 이동 기준일 갱신도 별도 후속 범위다. 기존 레거시 `TodayWeekStrip`용 범위 hook의 전체 개편은 이번에 섞지 않았다.
