# 왼쪽 메뉴: 밀도와 중복 목적지 비교

2026-10-17 · 사용자 선택 전 · 생성 시안이며 실제 화면 캡처 아님

직접 진입 시 화면 내 복귀 보강은 `76e7d51`로 커밋했다. 다음은 거대한 메뉴 제목·반복되는 목적지·큰 아이콘 배경을 줄여 보조 기능을 찾기 쉽게 하는 단계다. 이번에는 시안과 문서만 만들었으며 메뉴 코드는 변경하지 않았다. 커밋 전후 검증은 기존 사용자 요청에 따라 보류했다.

## 비교와 추천

번호는 이번 대화에서 생성 이미지가 표시된 순서다. 이전에 열어 본 참고 이미지는 번호에서 제외한다.

| 번호 | 시안                                                         | 바꾸는 점                                        | 장점                                | 한계                                                          |
| ---- | ------------------------------------------------------------ | ------------------------------------------------ | ----------------------------------- | ------------------------------------------------------------- |
| 1    | [모든 경로를 유지하는 목록](./01-all-destinations.png)       | 큰 제목·아이콘 배경을 줄이고 현재 12개 행을 유지 | 익숙한 경로를 그대로 찾음           | 오늘·달력·목표가 핵심 탭과 겹치고 목록이 김                   |
| 2    | [보조 기능에 집중하는 목록](./02-secondary-destinations.png) | 검색을 먼저 두고 보조 기능 9개를 직접 노출       | 중복을 줄이면서 기능을 한 번에 찾음 | 기존 목표/달력 메뉴에 익숙한 사용자는 하단 탭을 이용해야 함   |
| 3    | [접어서 관리하는 목록](./03-expandable-tools.png)            | 보조 기능 9개 중 세 개를 `기록 관리` 안에 묶음   | 접었을 때 짧음                      | 펼침이 한 단계 늘고 템플릿을 기록 관리로 분류하는 의미가 약함 |

**추천은 2번**이다. 핵심 탭과 보조 메뉴의 역할이 가장 분명하고, 단순히 짧아 보이려고 필요한 기능을 접어 숨기지 않는다. 이는 사용자 조사 결과가 아니라 현재 목적·기존 코드·참고 자료에 근거한 설계 판단이다. 사용자의 선택 전 구현하지 않는다.

## 공통 기준과 구현 시 보정

- 왼쪽 메뉴를 유지한다. 오늘·달력·계획·돌아보기 네 하단 탭의 위치는 바꾸지 않는다.
- 작은 `dooit`와 닫기 버튼으로 헤더를 줄인다. 기본 콘텐츠 높이 52dp와 safe area만 확보하고 거대한 `나의 플래너` 제목은 제거하는 방향이다.
- 행은 기본 48dp 이상으로 하고 긴 글자·글자 확대에서는 높이가 늘어난다. 본문 16sp, 아이콘 약 20dp를 기준으로 기존 토큰에 맞춘다. 생성 이미지의 여백·폰트 크기를 픽셀 명세로 사용하지 않는다.
- 기능별 큰 아이콘 배경·카드를 없애고 정렬·간격·작은 그룹 제목을 우선한다. 이미지의 그룹 구분선은 필수가 아니며 옅은 선이 어색하면 간격으로 대체한다. 선택·키보드 초점에는 색과 보조 기술 상태를 함께 제공한다.
- 계정·설정도 같은 스크롤 안에 둔다. 작은 화면에서 고정 푸터가 목록을 가리게 하지 않는다. 메뉴 열기/닫기·Escape·Android back·초점 복귀 등 기존 상호작용을 보존한다.
- 카테고리는 현재처럼 펼침 목록과 로딩·오류/재시도를 유지한다. 미분류는 현재 서버 필터 제약을 그대로 안내한다. 그림에 없는 카테고리 CRUD·새 집계는 추가하지 않는다.
- 2번의 `함께 쓰는 도구`는 개인 템플릿까지 포함하므로 구현 시 그룹 이름을 `도구`로 단순화하는 것을 권한다. 계정은 가상 이름·이메일·활동 수치를 표시하지 않고 기존 계정 화면에 연결한다.
- 배경의 Today 일부는 이미지 생성으로 단순화된 분위기 참고다. 기존 오늘 목록을 카드나 차트로 바꾸자는 제안이 아니다. 네 탭은 drawer 뒤의 가려진 영역에 있으며 시안에서 모두 보이지 않는다고 삭제된 것이 아니다.

## 2번의 목적지와 보존할 경로

| 메뉴/탭                      | 기존 목적지                                     | 역할                        |
| ---------------------------- | ----------------------------------------------- | --------------------------- |
| 검색                         | `/search`                                       | 기존 개인 검색              |
| 기록함                       | `/today/review?focus=inbox`                     | 날짜 없는 기록 정리         |
| 카테고리                     | `/search?browse=categories` 및 기존 category 값 | 기존 카테고리 펼침/선택     |
| 오래 미룬 일                 | `/today/review?focus=stale`                     | 지난 미완료 정리            |
| 날짜별 완료 기록             | `/completed`                                    | 날짜별 확인·완료 취소       |
| 할 일 템플릿                 | `/templates`                                    | 자주 하는 일 작성 도구      |
| 공유 공간                    | `/workspaces`                                   | 기존 공유 기능              |
| 계정                         | `/profile`                                      | 로그인/로그아웃·게스트 안내 |
| 설정                         | `/settings`                                     | 알림·문구·사용 가이드       |
| 하단 오늘·달력·계획·돌아보기 | `/`, `/calendar`, `/plan`, `/review`            | 핵심 목적지                 |

2·3번은 메뉴에서 오늘·달력·목표의 중복 행만 덜어내는 제안이다. `/dday`를 포함한 기존 route·직접 링크·데이터를 삭제하거나 자동 redirect하지 않는다. 목표 구성은 `/plan`에서 제공한다. 돌아보기와 `/completed`는 현재 역할이 다르므로 중복이라고 단정해 합치지 않는다.

계정 화면의 기존 도구 목록은 세 시안의 대상이 아니다. 메뉴 결정 후 모든 도구의 대체 경로를 확인한 뒤 계정 관리에 집중하도록 별도 정리한다. 이 시안을 앱 전체 중복 제거 완료로 취급하지 않는다.

## Product Design 검토 기록

- 대상/목적: Dooit 모바일의 보조 탐색. 실행·목표 구성·회고의 핵심 탭을 유지하면서 보조 기능 찾기와 메뉴 밀도 개선.
- 확인한 자료: 현재 `PlannerDrawer`, 탭 layout, 계정·설정 코드, [기존 탐색 결정](../../product/NAVIGATION_INFORMATION_ARCHITECTURE.md), [메뉴 캡처](../../audits/navigation-drawer-2026-08-31/implementation-open-final.png), [선택된 계획 시안](../plan-navigation-2026-10-15/05-goal-tabs-polished.png). 과거 캡처와 생성 시안을 직접 열어 참고했다. 현재 감사 증거로 사용하지 않는다.
- 적용 도구: Product Design get-context/ideate와 내장 Image Gen. preflight 결과 저장된 사용자 컨텍스트가 없어 대화·저장소 자료를 사용했다. 각 생성 호출에 두 참고 이미지를 실제로 전달했고, 독립 결과 세 개를 표시했다. Figma·외부 앱을 직접 조작하지 않았다.
- 외부 자료: 2026-10-17 [Todoist 공식 탐색 안내](https://www.todoist.com/help/todoist/features/customize-the-todoist-navigation-bar-L4qpkI0xj)를 읽었다. 하단에 추가한 목적지를 Browse에서 제거하는 설명을 중복 판단에 참고했다. 해당 앱의 탭 사용자 설정·Browse 고정 정책까지 Dooit에 복제하지 않는다.
- 외부 자료: 같은 날 [Material의 navigation drawer 자료](https://m1.material.io/patterns/navigation-drawer.html)를 읽었다. 왼쪽 패널·dimmed background·선택 상태·목록 정렬을 참고했다. 구버전 자료이며 최신 M3 치수/높이의 근거로 주장하지 않는다.
- 직접 확인한 생성 결과: 1번은 기존 목적지 12행, 2번은 보조 목적지 9행, 3번은 기록 관리가 펼쳐진 상태로 동일 보조 목적지 9행을 포함한다. 닫기 버튼·작은 브랜드와 왼쪽 overlay 구조를 확인했다. 배경과 세부 간격은 구현 원본이 아니다.
- 접근성 위험: 320dp·글자 확대·긴 카테고리명·키보드 focus trap·스크린리더 순서·메뉴 밖 배경 노출은 시안으로 검증할 수 없다. 구현 후 확인 대상으로 남긴다.
- 검증 범위: 사용자 요청에 따라 테스트·`npm run validate`·실제 화면 감사는 보류했다. 생성 이미지 검토를 실제 앱 통과로 표현하지 않는다. 선택 후 예상 영향은 Android·iOS·Web이다.
