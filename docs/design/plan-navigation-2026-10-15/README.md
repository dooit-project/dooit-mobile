다음은 목표 아래 항목 순서와 안정적인 서버 항목 ID/저장 계약 연결이다. 임시 로컬 목표 순서를 서버로 이전하는 시점과 충돌 처리는 계약 회신 후 결정한다.

#### 2026-10-16 후속 작업: 목표 안의 항목 순서 편집

목표 순서 편집은 `1a6ddec`로 커밋했다. 이어서 목표 아래 할 일·일정·반복 묶음·개별 예외의 표시 순서 편집을 코드에 반영했다.

- 대상/목적: 시험 접수 일정처럼 중요한 항목을 반복 행동보다 먼저 배치한다. 선택된 시안의 목표 관리 메뉴를 사용하며 정상 화면에 독립 `순서 편집` 행을 추가하지 않는다.
- 검토 근거: 최종 목표 탭 시안의 메뉴/편집 상태와 앞선 목표 순서 조작 패턴을 재사용했다. Product Design의 행동 위계·혼합 목록·취소/재시도·접근성 기준을 적용했으며 이번에 외부 앱·Figma·실제 화면을 새로 캡처하지 않았다.
- 진입/저장: 목표 옆 `··· → 순서 바꾸기`로 진입한다. 편집 중 메뉴 자리는 `완료`로 바뀐다. 드래그·위/아래 이동과 직전 이동 되돌리기·취소를 제공하며 완료 시에만 저장한다. 저장 실패 시 편집 상태와 임시 순서를 보존한다. 항목이 두 개 미만이거나 조회/복원 중이면 진입할 수 없다.
- 편집 중: 다른 목표 전환·전체 목표 펼침·항목 추가를 막아 편집 중인 목록의 맥락을 유지한다. 취소하면 기존 목록을 복원한다. 드래그 중 바깥 스크롤을 잠그며 이동 버튼·보조 기술 조절 동작도 제공한다. 목표 순서와 항목 순서는 같은 조작 컴포넌트를 사용한다.
- 저장 범위: 계정·API 환경·목표 ID별 **이 기기의 임시 표시 순서**다. 기존 SecureStore/localStorage 사용, 서버 API 호출 없음. 편집 안내에 기기 저장 범위를 표시한다. 목표일·Task 날짜·반복 규칙·완료 상태·소속·Today/달력 순서는 바꾸지 않는다.
- 항목 식별: 단건/예외는 Task ID 기반 표시 키, 일반 반복 묶음은 서버 묶음 ID와 규칙을 조합한 기존 표시 키를 재사용한다. 대표 회차가 바뀌어도 같은 반복 표시 키는 위치를 유지한다. 서버 반복 정의 ID 계약을 대체하지 않으며 이 키를 서버에 보내지 않는다. 반복 규칙이 바뀌면 새 표시 키로 뒤에 추가될 수 있다.
- 목록 변화: 저장 순서에 없는 항목은 뒤에 추가하고 삭제/연결 해제된 항목은 표시하지 않는다. 편집 도중 조회 결과가 바뀌어도 현재 유효한 항목 목록과 임시 순서를 합쳐 저장한다. 더 이상 존재하지 않는 항목을 재생성하지 않는다.
- 상태: 후속 변경은 미커밋·미검증. Android·iOS·Web 공통이며 신규 의존성·백엔드 구현 없음. 사용자 요청에 따라 실제 화면 감사와 `npm run validate`는 보류했다. 드래그 자동 스크롤과 기기 간 동기화, 서버 저장 이전은 미완료다.

남은 기능은 서버 순서 저장·안정적 계획 항목 ID, 시간 없는 반복 TODO, 반복 정의 전체 목록/시리즈 목표 연결, 목표 색상 서버 이전이다. 계약과 배포가 확인되지 않은 경로는 연결하지 않는다.

[최신 이미지: 관리 메뉴와 목록 정리](./05-goal-tabs-polished.png) · [이전 보정안](./04-goal-tabs-final.png)

사용자가 2번을 선택하고 상단의 `계획` 제목 제거를 요청했다. 큰 제목과 해당 여백을 없애고, 헤더 바로 아래에 가로 목표 탭과 고정된 `전체 목표` 진입점을 배치했다. 본문은 선택한 목표의 제목·목표일과 연결된 항목을 표시한다. 항목별 화살표는 제거하고 아이콘과 보조 정보로 일정·반복·할 일을 구분한다. 추가 진입점은 `항목 추가` 하나로 통합한다.

최종 동작 목표는 평소 드래그 손잡이를 숨기고 목표 제목 옆 `···` 메뉴의 `순서 바꾸기`에서 진입하는 것이다. 편집 중에만 손잡이를 표시하며 목표 옆 메뉴 자리에 `완료`를 둔다. 하단 탐색의 `계획` 이름은 유지하고 체크박스 아이콘은 목록 아이콘으로 바꾼다. 실제 코드 반영 범위와 남은 기능은 위 구현 진행 상태를 따른다.

### 최신 시안의 검토 기록

- 대상/사용자 목적: 계획 탭에서 목표에 연결된 일정·반복·할 일을 찾고 수정·정렬한다.
- 확인한 시안: `04-goal-tabs-final.png`를 직접 확인하고 수정한 생성 이미지가 `05-goal-tabs-polished.png`다. 실제 앱 캡처가 아니다.
- 적용한 스킬·도구: Product Design의 정보 위계·발견 가능성·접근성 기준, ideate와 내장 Image Gen 편집. Figma 파일을 직접 열거나 별도의 codex-design 도구를 사용하지 않았다.
- 참고 근거: 2026-10-15 대화에서 확인한 [Material 목록 조작](https://m1.material.io/components/lists-controls.html)과 [Things 이동 안내](https://culturedcode.com/things/support/articles/9651894/). 기본 행동과 보조 조작을 구분하고 드래그 이외의 진입점도 제공한다. 공식 자료 참고이며 운영 앱 직접 조작 감사가 아니다.
- 유지: 목표 탭·전체 목표, 선택한 목표 제목·목표일, 하나의 항목 목록, `항목 추가` 진입점.
- 변경: 독립 순서 편집 행 제거, 목표와 목록 사이 간격 축소, 날짜 없는 할 일의 `날짜 미정` 생략, 계획 탭을 목록 아이콘으로 변경. 실제 구현에서는 행 아이콘을 20–22 논리 픽셀과 동일한 선 두께로 맞춘다. 생성 이미지는 정확한 치수 명세가 아니다.
- 동작 조건: 행 전체를 누르면 편집하며 눌림 반응과 충분한 터치 영역을 제공한다. 반복 행은 반복 정의를 수정하고 오늘 화면은 회차를 완료한다. 항목 추가에서 종류를 선택하며 현재 목표를 기본 지정한다.
- 접근성 조건: 긴 탭 이름은 말줄임하고 본문·전체 목표에서 원문 제공, 색 이외의 선택 표시 유지, 정렬에 위/아래 이동 대체 조작과 취소·복구 제공.
- 미확인/보류: 이번 이미지는 기본 상태만 표현한다. 메뉴·순서 편집·추가 화면은 동작 명세이며 이미지에 보이지 않는다. 실제 터치·스크롤·글자 확대·보조 기술·코드 테스트는 사용자 요청에 따라 보류했다.
- 생성 방식과 프롬프트: 내장 Image Gen 사용, [최종 프롬프트](./05-image-prompt.txt).

직전 계획 요약안을 바탕으로 사용자가 목표별 탭과 순서 관리를 요청해 다시 비교했다. 목표의 반복 정의·일회성 할 일·일정을 직접 편집하고 순서를 관리하는 화면이다. 오늘은 해당 날짜의 실행을 담당한다.

대화 표시 순서대로 1번은 [목표 목록](./01-goal-list.png), 2번은 [가로 목표 탭](./02-goal-tabs.png), 3번은 [목표 선택기](./03-goal-switcher.png)다. 이 번호는 이전 비교 이미지의 번호와 별개다.

| 방식                  | 장점                                    | 한계                                          |
| --------------------- | --------------------------------------- | --------------------------------------------- |
| 1 목록                | 목표들을 비교하고 순서를 정하기 쉬움    | 펼친 항목이 많으면 길어지고 Today와 비슷해짐  |
| 2 가로 탭 + 전체 목표 | 빠른 목표 전환, 선택 목표의 편집에 집중 | 긴 이름과 많은 목표에는 전체 목표 선택창 필요 |
| 3 제목 선택기         | 공간 절약, 긴 이름·많은 목표 대응       | 다른 목표가 보이지 않고 전환에 추가 탭 필요   |

추천은 2번. 목표 수가 적을 때의 빠른 전환과 많을 때의 전체 선택을 함께 제공한다. 이는 사용자 목표 수를 측정한 결과가 아닌 현재 요구에 근거한 설계 판단이다.

## 공통 동작 제안

- 일정·반복·일회성 항목을 하나의 사용자 순서로 표시한다. 없다는 안내와 실행 체크박스는 표시하지 않는다.
- 반복은 회차를 매일 나열하지 않고 반복 정의 하나로 표현한다.
- 순서 편집에서 전체 항목과 드래그 손잡이를 표시한다. 위/아래 이동 대체 동작과 실행 취소를 제공한다.
- 전체 목표 선택창에서 검색·목표 생성·목표 순서 변경에 접근한다. 항목 이동은 목표 내부에 한정하고 목표 변경은 명시적 메뉴로 처리한다.
- 순서 변경은 날짜·반복 규칙·소속을 바꾸지 않는다. 달력은 날짜순을 유지한다.
- 마지막 선택 목표를 복원하되 삭제·보관됐으면 유효한 목표나 빈 상태로 이동한다.
- 목표 이름을 자동 요약해 탭 이름으로 저장하지 않는다. 긴 제목은 말줄임하고 본문과 전체 선택창에서 원문을 제공한다.
- 색상과 사용자 지정 순서는 최종적으로 서버에 저장해야 한다. 아직 새 순서 API 계약을 확인하지 않았다.

## 시안 보정과 한계

1번 이미지에 생성된 구분선, 3번 항목별 색상 점은 필수 요소가 아니다. 색상은 목표 식별에만 사용한다. 최종안에서는 2번의 상단 제목과 항목별 반복된 화살표를 제거해 실제 내용 공간을 확보했다. 시안의 예시는 2026-10-15 기준이며 일정·수치 모두 예시다. 전체 목표 선택창과 실제 드래그 상태는 이번 이미지에 포함하지 않았다.

새 탐색 구조의 첫 단계를 구현했으며 사용자 요청에 따라 검증은 실행하지 않았다. 이미지에 표현된 전체 기능의 구현 완료를 의미하지 않는다.

참고: [Material 탭 가이드](https://m1.material.io/components/tabs.html)의 고정/스크롤 탭 차이, [Todoist 정렬 안내](https://www.todoist.com/help/todoist/features/sort-or-group-tasks-in-todoist-WFWD0hrb)의 수동 정렬 구분, [Things 제스처 안내](https://culturedcode.com/things/support/articles/2803582/)의 항목·헤딩 이동. 공식 문서를 참고했으며 운영 앱 직접 조작 감사는 아니다.
