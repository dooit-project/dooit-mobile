# 디자인 기준과 구현 프롬프트

2026-10-22 · 이후 UI 작업의 공통 시작점

## 왜 시안에서 멀어졌나

이번 이력에서 확인된 직접 원인은 구현 측에서 사용자의 ‘3번’을 다른 이미지 파일과 연결한 참조 오류였다. 이후 화면별로 글자·여백·아이콘을 따로 조정해 공통 규칙이 일치하지 않았고, 제한된 시안 일치 검사를 전체 디자인 완성도 판정으로 확대했다. 사용자가 프롬프트를 짧게 작성해서 생긴 문제로 돌리지 않는다.

원인과 대응을 함께 관리한다.

| 원인                                        | 다음 작업의 규칙                                                    |
| ------------------------------------------- | ------------------------------------------------------------------- |
| 선택 번호와 실제 파일의 연결 오류           | 번호 대신 정확한 이미지 파일/프레임 링크를 저장하고 직접 열어 확인  |
| 대화와 문서에 최신 기준이 여러 개 남음      | 이 문서를 시작점으로 사용. 현재 원본과 적용 범위를 아래 표에서 확인 |
| 기능 추가 중 레이아웃/스타일도 함께 변경    | 작업 전에 고정 요소·변경 범위·범위 밖을 짧게 명시                   |
| 페이지별 임의 수치와 비슷한 컴포넌트 중복   | 같은 역할의 토큰과 공통 컴포넌트를 먼저 확인. 예외는 이유 기록      |
| 자동 검사/국소 시안 일치를 전체 품질로 해석 | 기능 검사·시안 정합성·실제 사용 시 시각 완성도를 각각 판정          |

## 현재 기준의 우선순위

1. **사용자의 최신 명시 결정**이 우선이다. 해당 결정으로 무엇이 대체됐는지 기록한다.
2. **정확한 시각 원본과 선택 범위**를 아래에서 확인한다. 순번이나 생성 프롬프트만으로 원본을 추정하지 않는다.
3. **현재 승인된 보정과 제품 규칙**을 적용한다. 전역 재디자인 요구로 해석하지 않는다.
4. **실제 앱의 코드/캡처**는 구현 현황이다. 불일치하는 현재 화면을 자동으로 새 디자인 기준으로 승격하지 않는다.

| 대상                  | 원본/결정                                                                                                                         | 적용 범위                                                                                      |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 오늘과 기본 시각 언어 | [사용자 첨부 이미지](./goal-lanes-correction-2026-10-21/reference.png), [결정/이력](./goal-lanes-correction-2026-10-21/README.md) | 흰 배경·목표색 레일/마커·원형 체크·추가 버튼·네 탭. 생성 이미지의 큰 상단 공백은 복제하지 않음 |
| 계획 탐색             | [가로 목표 탭 최종안](./plan-navigation-2026-10-15/README.md)                                                                     | 목표 전환·전체 목표·맥락 메뉴. 큰 ‘계획’ 제목 없음                                             |
| 최신 완성도 개선      | [10월 22일 개선 기준](./VISUAL_COHESION_REVIEW_2026-10-22.md)                                                                     | 기존 구조를 유지하는 헤더/공통 규칙 보정. 표의 제안 수치를 구현 완료로 간주하지 않음           |
| 실제 현황/미완료      | [로드맵](../product/ROADMAP.md), [실제 Web 감사](../audits/visual-cohesion-2026-10-22/README.md)                                  | 디자인 작업 순서와 기능 연결의 경계                                                            |

변경 내용을 버리는 확인은 2026-10-26 사용자가 첨부/선택한 [중앙 확인 원본01](./discard-confirmation-2026-10-25/01-centered-decision.png)과 [선택 범위](./discard-confirmation-2026-10-25/README.md)를 따른다. 흰 작은 면·가로 두 버튼·얇은 중립 경계의 빨간 버리기·파란 계속 작성을 유지한다. 이전 경계 없는 보조 행동 권고와 달리 최신 사용자 선택의 경계를 보존한다. 배경 폼 전체를 승인한 것이 아니다.

## 고정할 큰 틀

Task 작성·편집의 알림·반복은 사용자가2026-10-26 비교 후 선택한 [속성 행 원본01](./task-form-density-2026-10-26/01-property-rows.png)과 [선택 범위](./task-form-density-2026-10-26/README.md)를 따른다. 기본 입력 아래 두 현재 값 행을 보이고 필요한 속성만 편집한다. 설명·예상 시간·카테고리는 별도 추가 정보다. 이전15개 inline 선택/ChoiceChips 표현 보정은 최종 기준이 아니다. [구현/실제 감사](../audits/task-form-properties-2026-10-26/README.md)에서 실제 환경·검증 한계를 확인한다. 기존 유형3분할·패널/중앙 버리기 확인·저장 계약을 유지하며 생성 이미지의 임의 경계/gradient를 전역 적용하지 않는다.

개인 할 일 상세의 최신 권장 기준은 [목록 위 상세 패널 정리](./task-detail-options-2026-10-24/RECOMMENDED_DIRECTION.md)와 [05 정렬 보정 이미지](./task-detail-options-2026-10-24/05-context-panel-aligned.png)다. 사용자가 첨부한 원본은 같은 폴더의03 패널이며, 이전 별도 페이지 추천/큰 원을 그대로 재사용하지 않는다. 05는04의 아이콘/정보 행 정렬을 보정한 버전이며 새 구조 선택안이 아니다. [개인 Task 패널 연결과 실제 Web 감사](../audits/task-detail-panel-2026-10-24/README.md)를 진행했다. 직접 URL은 같은 내용의 일반 상세다. native/확대/운영 API/미지원 Web traversal은 감사의 한계로 남긴다. 기본 탭/오늘 시안은 유지한다.

- 흰 배경, 목표색 레일과 마커, 간단한 원형 체크. Today 항목별 카드·가로 구분선을 다시 만들지 않는다.
- 하단 순서: 오늘 / 달력 / 계획 / 돌아보기. Drawer는 검색·정리·도구·계정의 보조 진입이다.
- 오늘은 실행, 계획은 목표/반복/연결 항목 관리, 달력은 날짜 탐색, 돌아보기는 실제 기록이다.
- 상단은 왼쪽 메뉴 → dooit → 작은 동기부여 문구. 큰 오늘 제목·상시 날짜·주 달력·큰 명언 배너를 Today에 넣지 않는다.
- 목표 퍼센트·노력 점수·연속 달성 압박·기록 없는 AI 칭찬을 넣지 않는다. 목표 아래 반복·일회성 행동·일정을 연결한다.
- 문구의 원문·출처와 실제 기록의 사실성을 보존한다. 디자인을 맞추려고 가짜 성과를 넣지 않는다.
- 긴 이름은 탐색 라벨과 읽는 본문을 구분한다. 현재 목표 탭은 한 줄 말줄임/가로 스크롤, 본문 제목과 전체 목표 목록은 줄바꿈이다. [외부 비교·360/430 실제 확인](../audits/long-goal-labels-2026-10-24/README.md)의 추천을 따르며 새 별명 입력·두 줄 탭·자동 스크롤 문구를 임의로 추가하지 않는다. 현재 라벨 maxWidth 172 때문에 큰 화면에서도 탭 이름이 계속 길어지지는 않는다.

## 일정 행의 전용 편집 기준

2026-10-27 사용자가 직접 확인한 [1번 보정 원본](./task-schedule-edit-2026-10-27/04-focused-editor-refined.png)을 적용한다. 같은 상세 패널의 본문에서 일정 날짜/종일/시작/종료만 수정하고, 취소는 공통 outline·완료는 primary로 세로 배치한다. 날짜 고정 안내는 제거한다. 상단 수정의 전체 폼과 실행일 빠른 변경은 유지한다. 공통 필드/오류/버튼/뒤로·미저장 보호와 [실제 감사](../audits/task-schedule-edit-2026-10-27/README.md)의 서버 날짜·반복 범위/알림 보존 조건을 따른다. 생성 그림의 gradient/픽셀 여백을 전역 스타일로 확대하지 않는다.

## 작업 시작 시 작성할 짧은 범위

내부 계획/해당 작업 문서에 아래 여섯 줄을 쓴다. 이미 결정된 항목을 사용자에게 재확인할 필요는 없다.

```text
이번 단위: [예: 공통 헤더와 Today 시작 간격]
원본: [정확한 파일/프레임과 적용할 부분]
유지: [기존 큰 틀과 관련 상호작용]
변경: [이번에 바꿀 컴포넌트·토큰·상태]
범위 밖: [이번에 함께 바꾸지 않을 화면/기능]
완료 조건: [같은 조건의 실제 화면 비교·동작·플랫폼 한계]
```

페이지가 늘어나도 `BrandWordmark`, `AppText`, 화면 padding, 버튼/행 등 동일 역할을 재사용한다. 단, 아직 전역 승인되지 않은 보정 수치를 무관한 화면까지 일괄 적용하지 않는다. 이번 단위가 끝나면 다음 단위로 이동한다.

아이콘 정렬과 높이는 [기본 시각 검사](../qa/UI_VISUAL_ACCEPTANCE.md)를 매번 적용한다. 오늘 체크/상세 제목 체크는 제목 첫 줄, 계획 종류/상세 정보 아이콘은 전체 텍스트 블록 중앙이다. 실제 Web 수정은 새 좌표 보고서의 `check:ui-layout`과 캡처의 광학적 검토를 모두 거치고, 실패를 수정·재측정한 뒤 완료한다.

## 재사용할 구현 프롬프트

아래 프롬프트에서 `[이번 범위]`만 바꿔 사용한다. AGENTS에 이 문서를 연결했으므로 사용자가 매번 전체 내용을 붙일 필요는 없다.

```text
docs/design/DESIGN_IMPLEMENTATION_GUIDE.md와 ROADMAP의 최신 기준을 읽고
[이번 범위]를 구현해줘.

기준 이미지는 docs/design/goal-lanes-correction-2026-10-21/reference.png야.
직접 열어 보고, 이번 화면에 해당하는 구조와 시각 요소를 적용해줘.
계획 탐색은 가이드에 연결된 별도 선택안을 따라줘.

작업 시작에 원본·유지 요소·변경 범위·완료 조건을 짧게 정리하고 진행해줘.
같은 역할은 공통 토큰/컴포넌트로 맞추고, 기능 추가와 전역 재디자인을 섞지 마.
이미 선택한 구조 안의 보정은 진행하고, 의미 있는 새 구조만 3안 비교 후 선택받아줘.

구현 후 같은 viewport/데이터/상태의 실제 캡처를 원본과 비교해줘.
정상·긴 문구·좁은 화면·중요한 실패/복구를 확인하고 미확인 범위를 밝혀줘.
자동 검사 결과와 시각 완성도 판정을 구분해서 코드·문서·검증까지 마무리해줘.
커밋과 푸시는 별도 명시 승인 후 진행해줘.
```

현재 첫 단위의 예시는 `[이번 범위]`에 **‘공통 헤더의 메뉴·dooit·문구 비율, 본문과 최대 폭 정렬, Today 첫 섹션 간격’**을 넣는 것이다. 달력 구조·반복 작성 화면·전역 색 체계는 각각 후속 단위다.

## 완료 판정과 기준 변경

- 먼저 같은 viewport·데이터·상태를 맞춘다. 원본/이전 실제 화면/수정 후 실제 화면을 함께 비교한다. 시안에 없는 native safe area는 별도 구현 조건으로 기록한다.
- 시안과의 차이는 ‘수정할 차이 / 사용자 승인에 따른 차이 / 플랫폼 조건 / 미완료 기능’ 중 무엇인지 설명한다. 픽셀 완전 일치와 전체 기능 완료를 과장하지 않는다.
- 작은 시각 변경에 구현을 그대로 복제하는 테스트를 추가하지 않는다. 저장소 필수 `npm run validate`와 실제 화면 확인은 수행한다.
- 사용자가 큰 틀 변경을 명시하면 새 기준과 대체된 기준을 함께 갱신한다. 대화의 번호만 남기거나 오래된 문서를 모두 ‘최신’으로 두지 않는다.
- 관련 기준: [Product Design 검토 정책](../qa/PRODUCT_DESIGN_REVIEW_POLICY.md). 현재 안의 국소 보정에 매번 3안을 요구하지 않는다. 의미 있는 새 화면/정보 구조만 선택 단계를 거친다.
