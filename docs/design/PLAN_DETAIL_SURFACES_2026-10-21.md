# 계획·상세 화면의 목표 묶음 디자인 확장

2026-10-21 · 기준 커밋 `479ae87` · 미커밋

최신 [첨부 원본 기준 정정](./goal-lanes-correction-2026-10-21/README.md)에 따라 회색 바탕·둥근 카드는 제거했다. 아래 정보 축소/날짜/기록 개선은 유지한다. [현재 계획과 상세 재촬영](../audits/goal-lanes-correction-2026-10-21/README.md)을 이전 캡처보다 우선한다.

구현 후 [실제 Web 감사](../audits/plan-detail-surfaces-2026-10-21/README.md)를 진행했다. 미커밋이며 새 Goal 연결·전체 시안 구현 완료가 아니다. 날짜를 내일로 옮긴 뒤에도 상단에 ‘오늘’이 남던 표시는 선택 날짜에 맞게 정정했다.

## 대상과 목적

최초에는 카드형으로 잘못 연결한 기준을 계획과 개인 Task 상세에 확장했다. 현재는 [사용자 첨부 원본](./goal-lanes-correction-2026-10-21/README.md)에 맞춰 흰 바탕과 평평한 목록으로 정정했다. 계획은 목표 구성 관리, 상세는 항목 내용과 날짜·체크리스트 확인이라는 역할을 유지한다. 새 페이지나 탐색 구조를 만드는 선택이 아니라 확정한 디자인의 확장이므로 새 시각안 세 개를 요청하지 않는다.

Product Design의 audit와 기존 image-to-code 검토 기준을 이어 적용한다. 이전에 확인한 Anthropic frontend-design/Vercel React Native/Web Interface Guidelines의 제품 내용 우선, 명확한 위계, native Pressable/간격, 긴 글자·선택/확장 상태 기준을 재사용한다. 새로운 외부 자료나 Figma 파일을 확인했다고 표현하지 않는다.

## 확인한 근거와 변경

- 실제 390px 개인 상세를 이번 작업에서 다시 캡처했다. 빈 체크리스트 0/0, 빈 설명, 반복되는 없음/아니오, 날짜 버튼 3+1 배치가 첫 화면을 차지한다. [수정 전](../audits/plan-detail-surfaces-2026-10-21/01-detail-before.png).
- 계획의 가로 목표 탭·전체 목표·제목 옆 관리 메뉴는 유지한다. 선택 목표와 실제 항목 목록을 흰 한 묶음으로 만들고 편집 폼의 중첩 테두리를 줄인다. 없는 일정 안내는 추가하지 않는다.
- 상세의 설명은 있는 경우만 표시한다. 일정·반복·목표일·예상 시간·카테고리도 실제 값이 있는 행만 표시하며 상세에서 편집 진입은 항상 유지한다.
- 체크리스트 0개는 작은 ‘체크리스트 추가’ 진입으로 표시한다. 항목이 있으면 실제 완료/전체 개수와 목록을 표시하고 기존 추가·수정·순서·실패 복구 기능을 유지한다.
- 날짜 변경은 개인 상세에서 같은 흰 묶음과 작은 버튼을 사용한다. 390px에서는 네 행동을 한 줄, 320px에서는 두 열로 배치한다.
- 생성·수정·완료·이월 정보는 ‘기록 정보’에서 펼쳐 볼 수 있게 한다. 오류, 저장 상태, 삭제 확인·반복 범위 선택은 생략하지 않는다.
- 기존 D-Day 연결은 기존 목표임을 명시한다. 없는 ‘D-Day 탭’ 안내를 제거하며 새 Goal 연결 완료로 표현하지 않는다.

## 구현 조건과 확인 범위

개인 상세에만 grouped presentation을 전달하여 Workspace 체크리스트·권한 UI와 다른 날짜 변경 사용처를 일괄 바꾸지 않는다. 카드 역할을 공통 component로 추가하되 기존 variant 기본값은 보존한다. 터치 영역 44, 줄바꿈, 조회/추가/취소/날짜 변경·기록 펼침을 실제 Web에서 확인한다. Android/iOS/Web 공통 영향이며 native 확대·safe area·보조 기술·dark·실제 API 실패는 별도 확인이다.

새 Goal 회차/Goal Task 연결·검색·여정은 기존 후속 목록을 유지한다. 시각 보정으로 해당 기능이 연결됐다고 판단하지 않는다.
