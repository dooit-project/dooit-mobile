# 일정 날짜·시간만 편집하는 구조 비교

2026-10-27 · R4 · 사용자 선택1번 구현/실제 감사 진행

## 최신 결정과 보정

사용자가1번 원본을 직접 첨부해 확인한 뒤, 실행일 안내 제거·날짜 변경 시 목록/달력 일관성과 취소 버튼 경계 검토/진행을 요청했다. [선택1번 보정 원본04](./04-focused-editor-refined.png)을 built-in Image Gen으로 먼저 생성·직접 확인한 뒤 구현했다. 취소는 얇은 중립 경계의 공통 outline 버튼, 완료는 solid primary다. 아래의 선택 전/실행일 보존 설명은 초기 검토 이력이며 이 결정과 [구현/실제 감사](../../audits/task-schedule-edit-2026-10-27/README.md)가 우선한다. 새로운 정보 구조 선택을 다시 요구하는 변경이 아니다.

로컬 backend 코드에서 미완료 일정 PUT이 targetDate/plannedDate를 시작 날짜로 함께 갱신함을 확인했다. 따라서 별도 이동 PATCH를 연속 호출하지 않는다. 완료 기록의 날짜/완료 시각은 보존하고 반복 묶음은 회차 날짜를 유지하는 기존 범위 계약을 따른다. 기존 문구 ‘실행일은 바뀌지 않아요’는 제거했다. 운영 배포 검증은 별도다.

## 이번 범위

- 이번 단위: Task 상세의 일정 행에서 일정 날짜·시작·종료·종일만 수정한다.
- 원본: [선택된 속성 행](../task-form-density-2026-10-26/01-property-rows.png)과 [이번 실제 기본 편집](../../audits/task-form-external-recheck-2026-10-26/01-normal-390.jpg)을 직접 확인하고 세 Image Gen 호출에 실제 파일을 첨부했다.
- 유지: 오늘/네 탭/목표 레일·색/상세 패널, 상단 수정의 전체 TaskForm, 별도 실행일, 공통 TextField/AppText/Button/아이콘·간격 token, dirty 확인과 저장 오류 복구.
- 변경: 일정 행의 진입 대상과 날짜/시각 전용 편집. 기존 입력·정규화/첫 오류 초점 등을 재사용한다.
- 범위 밖: 목표/유형/설명/알림/반복의 별도 재설정, 전역 picker·달력 탭 재디자인, 백엔드 구현/의존성 추가, 손잡이/첫 진입 초점의 별도 R5/R6 문제.
- 완료 조건: 선택 후 같은390 전후·320/430/짧은 화면, 시간/종일/오류/복귀·취소/dirty/저장 실패·반복 범위/값 보존과 새 좌표 검사·validate. 지금은 시각안 선택 단계이며 실제 동작 검증은 아니다.

Product Design audit/get-context/ideate와 built-in Image Gen으로 세 독립 이미지를 생성했다. 번호는 대화에 실제 표시된 결과 순서다. 정확한 입력·첨부 파일은 [prompts.json](./prompts.json)에 보존한다. ## Product Design 기본 검토와 외부 근거

- **필요성/위치:** 현재 일정 행은 상단 수정과 동일한 전체 TaskForm을 열고 제목에 초점을 둔다. 날짜만 바꾸려는 의도에 비해 범위가 크다는 [R4 실제 감사](../../audits/task-detail-external-review-2026-10-25/README.md)를 해결한다. 별도 하단 탭·중복 일정 관리 페이지는 만들지 않는다.
- **행동 위계/발견:** 읽기 화면의 기존 일정 행을 진입점으로 유지한다. 한 번의 명시적 변경 완료, 취소/뒤로/X와 저장 실패 시 초안 보존을 제공한다. 타이핑 즉시 서버 저장하지 않는다.
- **밀도/시각:** 추천1은 현재 속성 편집과 같이 패널 본문만 전환한다.2는 입력/완료·취소 아래 실행일과 체크리스트가 남아 스크롤/혼합 조작 비용이 크다.3은 날짜를 시각적으로 고를 수 있지만 달력의 추가 탐색·초점 관리가 필요하다. 폼 기본 위계/필드/버튼은 공통 UI를 사용하고 새 카드 안 카드나 장식을 만들지 않는다.
- **공식 서비스 패턴:** 2026-10-26 직접 다시 읽은 [Todoist Task view](https://www.todoist.com/help/todoist/features/use-the-task-view-to-manage-tasks-in-todoist-eDeRDO0C)의 모바일 Date 속성→날짜/시각/기간 편집을 참고했다. 속성에 맞게 편집을 제한한다는 근거이며 Todoist 앱 자체를 조작하거나 시각을 그대로 복제한 검토는 아니다.
- **접근성:** 최소44px 조작, 아이콘은 해당 텍스트 블록 중심, 명확한 입력 이름·오류 연결과 첫 오류 초점. 일정 행으로 초점 복귀, 키보드/Android back/Escape와 미저장 확인, 확대/320px·짧은 화면을 선택 후 검증한다. 생성 그림만으로 작동·대비·보조 기술 통과를 선언하지 않는다.

## 구현 계약과 안전한 값 보존

기존 `taskApi.update`/`useUpdateTask`의 PUT 전체 TaskUpsert 계약을 먼저 재사용한다. 날짜/시각만 보내도 되는 PATCH라고 추정하지 않는다. 현재 mock `applyTaskRequest`는 생략한 설명·카테고리·예상 시간·시각·반복/알림 값을 초기화할 수 있으므로 현재 Task에서 보존할 값을 명시적으로 구성해야 한다.

1. 현재 제목·유형·목표 연결·설명·카테고리·예상 시간·반복 설정을 보존하고 일정 필드만 정규화해 교체한다. 기존 TaskForm 전체를 숨겨 제출하는 방식보다 공통 일정 입력/정규화와 명확한 요청 builder를 재사용한다. 불필요한 문자열 trim/요일 규칙 재생성도 하지 않는다.
2. 실행일(plannedDate)·targetDate·완료 상태/체크리스트는 변경 요청 대상에 넣지 않는다. mock에서는 applyTaskRequest가 plannedDate를 변경하지 않지만 real API 응답 보존은 별도 확인 조건이다. 실행일/일정 날짜가 다른 사례를 검사한다.
3. 반복 항목은 기존 THIS/FUTURE 범위를 유지한다. 편집하지 않은 recurrenceRule/byDays/until/count/timeZone을 UI 간단 모드로 재생성해 잃지 않는다. 회차/시리즈 의미를 기존 계약으로 확인하고, 계약에 빈틈이 있으면 클라이언트 요구 문서로 남긴다.
4. 기존 알림 off/시작 시각/시간차를 보존한다. `getInitialTaskNotificationTiming`은 메뉴 밖의 시간차를 AT_START로 단순화할 수 있으므로 이 편집에서는 원본 notifyAt과 startAt의 차이를 확인해야 한다. 날짜/종일 변경의 알림 변환은 기존 정책과 맞추고 임의로 알림을 켜지 않는다.
5. 종일은 기존 다음 날 자정 exclusive 종료를 사용하고, 종일을 다시 끌 때 입력 중 시각을 복원한다. 저장 중 중복 제출/닫기 차단, 오류 시 입력 유지·재시도, 성공 후 상세/오늘/달력/계획 캐시와 알림 동기화를 기존 mutation으로 연결한다.
6. 추천1의 뒤로는 일정 편집 취소 후 상세 복귀, X는 상세 닫기로 구분한다. 두 경로 모두 실제 변경만 보호하고 변경 없이 닫을 때 확인창을 띄우지 않는다. 저장/취소 후 일정 행 초점을 복원한다. 중첩 sheet를 만들지 않는다.

선택1번을 공통 일정 필드와 같은 상세 패널에 구현했다. 현재 검증 결과와 한계는 위 실제 감사에 연결한다. 생성 이미지·자료 참고와 실제 앱 검증은 별개이며 커밋/푸시는 별도 명시 승인 후 수행한다.
