## 정확한 기준과 선택 맥락

사용자가 다시 첨부한 두 이미지는 모두 [목록 위 상세 패널](./03-context-panel.png)과 같은 안이다. 서로 다른 두 디자인이라고 가정해 비교하지 않는다. 사용자는 그중 추천 방향을 정리하도록 위임했으며, **이 패널 방식에 작은 체크·현재 정보 우선·간결한 내용 배치를 적용**하는 것을 권장한다.

초기에는 별도 페이지인 비교안 2를 추천했다. 이후 사용자가 보여준 패널 선호와 목록에서 확인/체크하고 돌아오는 흐름을 반영해 패널을 우선한다. 패널의 접근성/긴 내용 처리 비용이 없어졌다는 뜻은 아니다.

- 원본: [03-context-panel.png](./03-context-panel.png), 사용자가 첨부한 패널 안. 직접 열어 확인했다.
- 최신 보정 기준: [05-context-panel-aligned.png](./05-context-panel-aligned.png). 04의 일정/실행일 아이콘이 위로 떠 보인다는 후속 지적을 반영했다. **04/05는 보정 버전이며 새 선택안이 아니다.**
- 단계: 생성 이미지/권장 명세. 실제 패널 구현·실기기 검증이 아니다. 후속으로 공통 Web 정렬 검사/표식을 추가했으며 [실제 화면 감사](../../audits/ui-alignment-regression-2026-10-24/README.md)와 구분한다.

## 추천하는 이유

오늘·계획·달력에서 항목을 확인한 뒤 닫으면 원래 목록의 위치를 유지할 수 있다. 목표 맥락과 실행 내용을 한 패널에서 보고 체크하는 흐름에 맞는다. 흰 바탕과 단순한 목록이라는 기존 큰 틀을 살리면서 별도 화면으로 이동하는 부담을 줄일 수 있다. 이는 사용자 사용성 테스트가 아닌 설계 판단이다.

## 화면 기준

| 요소                | 정리한 방향                                                                                                                                                                                                                               |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 패널                | 화면 아래에서 열고 배경 목록을 약하게 남긴다. 내용/키보드/글자 확대에 따라 높이와 스크롤을 조정한다. 이미지의 고정 높이를 그대로 복제하지 않는다.                                                                                         |
| 상단                | 작은 연결 목표 경로 + 수정 + 더보기 + 닫기. 목표 제목이 길면 조작 버튼을 밀지 않도록 폭/행을 조정하고 전체 이름 확인을 보장한다.                                                                                                          |
| 제목                | 본문 주인공. 22/30 역할을 유지하고 긴 제목은 줄바꿈한다. ‘할 일 상세’ 같은 중복 제목은 추가하지 않는다.                                                                                                                                   |
| 제목 앞 원          | 할 일 전체 완료 체크. 오늘과 같은 24px 시각 크기·44px 이상 조작 영역을 사용한다. 첫 제목 줄 가운데에 정렬한다. 장식용 큰 원으로 만들지 않는다. 아래 체크리스트와 별도 동작이며 하위 항목을 체크했다고 전체 완료를 임의로 처리하지 않는다. |
| 일정                | 실제 날짜/시간을 제목 가까이에 먼저 표시한다. 해당 행을 눌러 현재 일정 편집으로 연결한다.                                                                                                                                                 |
| 실행일              | 일정 아래의 작은 날짜 행. 오늘/내일 이동 등은 이 행을 누른 뒤 제공한다. plannedDate 변경과 startAt/endAt 변경의 차이를 유지한다.                                                                                                          |
| 설명                | 내용이 있으면 자연스러운 본문으로 표시하고 ‘설명’ 제목은 생략한다. 없으면 빈 섹션을 두지 않는다.                                                                                                                                          |
| 체크리스트          | 항목이 있을 때 제목과 목록을 표시한다. 없으면 작은 추가 진입만 둔다. 공통 원형 체크/추가 행을 재사용한다.                                                                                                                                 |
| 기록·삭제·목표 관리 | 더보기에서 접근한다. 삭제 확인·기록 조회·기존 연결 수정은 유지한다. 새 Goal 연결을 구현한 것으로 표시하지 않는다.                                                                                                                         |

기본 읽기 순서는 **연결 목표 → 제목/전체 완료 → 실제 일정 → 실행일 → 설명 → 체크리스트**다. 시간 정보가 없는 일반 할 일에는 해당 일정 행을 생략한다. 연결 목표가 없으면 임의의 목표/색 점을 만들지 않는다.

간격은 관련 정보끼리8–12, 섹션24를 기준으로 조정한다. 제목 앞 체크와 아래 항목 체크의 역할 차이는 제목의 글자 크기/굵기로 표현한다. 글자나 터치 영역을 줄여 밀도를 맞추지 않는다. 생성 이미지의 간격/획/전체 여백은 구현 시 공통 토큰과 실제 viewport로 다시 맞춘다.

**반복 정렬 지적 반영:** 일정/실행일의 왼쪽 아이콘과 오른쪽 화살표는 작은 라벨이 아니라 라벨+값 전체 블록 중앙에 맞춘다. 제목 앞 체크는 제목 첫 줄, 체크리스트의 원/추가는 해당 한 줄 중앙이다. [기본 시각 검사](../../qa/UI_VISUAL_ACCEPTANCE.md)의 역할별 기준을 적용하고 전역 위치 이동으로 섞지 않는다. 05의 정보 행/체크/추가 행과 상단 조작을 직접 확대해 검토했다. 실행일의 아래 화살표는 펼침, 일정의 오른쪽 화살표는 편집 진입 의미를 유지한다. 실제 터치 영역/긴 내용/글자 확대는 구현 후 확인한다. [정렬 보정 프롬프트](./ALIGNMENT_PROMPT.md)를 보존한다.

## 구현을 위한 범위와 조건

1. 기존 상세 내용을 공통 콘텐츠로 재사용하고 목록 진입에 패널을 연결한다. 알림/직접 URL 등 배경 목록이 없는 진입의 기존 상세 경로는 유지하고 같은 내용을 제공한다. 새 페이지와 기존 페이지의 정보/동작이 갈라지지 않게 한다.
2. 전체 완료/취소는 기존 Task hook·반복 범위·로딩·오류 계약에 맞춰 연결한다. 완료 후 목록 캐시와 실제 기록을 갱신하고 임의 점수나 칭찬은 만들지 않는다. 새 Goal 회차 기능은 별도다.
3. 닫기 버튼·Android back·Web Escape와 초점 복귀를 제공한다. 배경 조작/스크롤과 보조 기술 노출을 막고 패널 안에서 키보드 탐색이 유지돼야 한다. 드래그만으로 닫게 하지 않는다. 입력 중인 내용이 있으면 손실을 막는다.
4. 상세의 날짜/체크리스트/메뉴/편집/삭제 취소를 유지한다. 기록/삭제가 메뉴로 옮겨져도 이름과 발견 가능성을 확인한다. 작은 체크를 터치하기 어렵게 만들지 않는다.
5. 390 동일 데이터 원본/실제 비교, 320/430·긴 목표/제목·없는 필드·키보드·글자 확대1.5·완료/취소·오류/복구·deep link·dismiss를 확인한다. Web 확인과 Android/iOS 실기기 확인을 구분한다.

기본 패널 표현 자체에 백엔드 신규 API가 필요하다고 가정하지 않는다. 기존 D-Day/Task와 새 Goal의 연결 범위, 완료 회차의 계약 차이와 UX-14 캐시는 기존 로드맵에서 추적한다.
