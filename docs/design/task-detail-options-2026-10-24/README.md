# 개인 할 일 상세 구조 비교 시안

후속 개발: [05를 기준으로 개인 Task 상세 패널을 실제 연결·감사](../../audits/task-detail-panel-2026-10-24/README.md)했다. 아래 구현 전 표시는 시안 생성 당시 이력이다. 새 Goal 회차/native/운영 검증 완료를 의미하지 않는다.

2026-10-24 · 패널 권장 방향과 보정안 정리 · 생성 이미지, 실제 앱 캡처 아님

**최신 권장 방향:** 사용자가 다시 첨부한 패널 이미지와 추천 위임을 반영해 [목록 위 상세 패널의 보정 기준](./RECOMMENDED_DIRECTION.md)을 정리했다. 최신 기준은 [05 정렬 보정 이미지](./05-context-panel-aligned.png)다. 04/05는 기존 패널의 보정 버전이며 새 선택안 번호가 아니다. 05에서 일정/실행일 양쪽 아이콘을 라벨+값 전체 중앙으로 수정했다. 아래 2번 추천은 최초 비교 당시 이력이다. 패널 구현은 아직 없고, 이후 추가한 공통 정렬 검사 코드는 [실제 감사](../../audits/ui-alignment-regression-2026-10-24/README.md)로 구분한다.

## 목적과 고정 요소

[상세 재검토](../../audits/task-detail-design-review-2026-10-24/README.md)의 정보 위계 문제를 해결할 구조를 비교한다. 사용자는 목표 맥락과 현재 일정을 먼저 읽고 내용 확인/완료/수정을 할 수 있어야 한다. [사용자 승인 Today 원본](../goal-lanes-correction-2026-10-21/reference.png)과 [현재 상세](../../audits/task-detail-design-review-2026-10-24/01-current-detail-390.jpg)를 직접 열고 매 ImageGen 호출에 로컬 경로로 첨부했다.

흰 바탕·파란 목표 마커·원형 체크·본문16/보조13/제목22 역할·기존 네 탭은 유지한다. goal 진척률/점수/기록 없는 칭찬·새 협업 기능·큰 실행 버튼은 추가하지 않는다. 상세 패널 안도 항목별 카드 없이 구성한다.

모두 같은 비교용 데이터다. 목표 `토익 900점 받기`, 항목 `토익 시험 접수`, 실행일 오늘(2026-10-24 토요일), 실제 일정 `10월 24일 (토) 14:00–14:30`, 예시 설명과 미완료 체크리스트 두 개다. 설명/하위 항목은 시안용 데이터이며 실제 사용자 기록이나 새 백엔드 연동 증거가 아니다. 실행일 이동과 일정 시간 변경을 다른 동작으로 취급한다.

## 검토 방법과 한계

Product Design index/get-context/ideate, imagegen 지침과 저장소 검토 정책을 적용했다. 별도 저장 Product Design context는 없고 대화/저장소의 확정 내용을 사용했다. [공식 서비스 비교](../../audits/task-detail-design-review-2026-10-24/README.md)의 목표 경로·날짜 직접 편집·관리를 메뉴에 묶는 원칙을 재사용했다. 이번에 경쟁 앱의 새 화면/Figma를 검증한 것은 아니다.

세 결과를 생성 직후 직접 보고 한국어/동일 날짜·제목·내용·원형 체크·목표 맥락·기록/삭제 비노출을 비교했다. built-in image_gen을 개별 호출했고 명령행/API fallback·코드로 그린 대체 시안은 쓰지 않았다. 목표 논리 viewport는 390×844이며 실제 생성 파일은 모두853×1844다. 생성 이미지의 미세한 수치/획/터치 영역은 실제 구현 명세가 아니다. [전체 생성 프롬프트](./PROMPTS.md)를 보존한다.

**현재 판정은 패널 권장 방향과 생성 시안 정리다.** 같은 실제 앱 상태로 조작한 결과가 아니다. 완료 취소/반복 회차·저장 실패·긴 제목/목표·320px·글자 확대1.5·native/dark·메뉴 초점 복귀·sheet dismiss는 구현 조건이다. 선택한 구조에서 긴 제목은 줄바꿈, 목표 탐색 라벨은 전체 이름 확인 경로를 보장한다. 단순한 빈 할 일에는 없는 설명/체크리스트 틀을 강제하지 않는다.

최초 3안 비교 당시에는 이미지/문서만 추가하고 기존 미커밋 앱 코드를 수정·커밋·푸시하지 않았다. 이후 정렬 자동화 작업은 상단의 별도 감사를 따른다. 패널 구현 시 정확한 이미지와 범위를 고정하고, 실제 390 동일 데이터 비교와 320/430·주요 조작/실패·필수 validate로 검증한다.

이미지/문서 추가 후 `npm run validate` 통과(116 suites / 597 tests, STG1 제외). 기존 구현과 문서의 검사이며 생성 시안의 실제 동작 검증을 뜻하지 않는다.
