# 자정·앱 복귀 후 오늘 기준일 갱신

2026-10-18 · 코드 반영·미커밋·미검증

달력 표시 범위 수정은 `f3ad95a`로 커밋했다. 이번에는 다시 렌더링될 때만 오늘을 계산하던 화면들이 자정 이후에도 이전 날짜를 사용할 수 있는 문제를 정리한다. 새 화면·탭·일정 이월 정책이나 알림 기능을 만드는 작업은 아니다.

## 날짜 정책과 사용자 맥락

- 앱의 기존 API 날짜 기준 `Asia/Seoul`을 유지한다. 기기의 현지 시간대로 날짜 정책을 바꾸거나 서버 시계를 새로 동기화하지 않는다.
- 기본 오늘/이번 주를 보고 있으면 새 날짜/주를 따라간다. 사용자가 선택한 다른 날짜/과거 주는 유지한다. 달력의 명시적 date 진입도 초기 선택 날짜를 유지한다.
- 자정에 할 일을 완료·미룸 처리하거나 다음 날로 자동 이월하지 않는다. 날짜별 기존 query key를 새 기준일로 구독하는 범위다.
- 열린 빠른 기록 입력은 보존한다. 계정 연결 안내 등 기존 화면 맥락을 날짜 갱신 때문에 전체 초기화하지 않는다.

## 구현

- `useAppToday`는 `useSyncExternalStore` 기반의 공통 날짜 구독이다. 여러 화면이 사용해도 공통 타이머 하나만 유지하며 마지막 구독이 사라지면 해제한다.
- 활성 상태에서 다음 서울 자정에 갱신하도록 한 번 예약하고, 자정 경계 직전 실행 오차를 피하려고 25ms 여유를 둔다. 고정 간격으로 계속 API를 조회하지 않는다.
- native AppState 변경, Web 창 focus/visibility 변경에서 현재 날짜를 다시 읽는다. background/숨김 상태에서는 예약을 중단하고 활성 복귀 시 재계산한다. 지연된 타이머가 하루에 한 번씩 과거 날짜를 따라가는 대신 실제 현재 날짜를 읽는다.
- 오늘 화면의 조회와 달력의 오늘 표시·기본 선택, 돌아보기의 기본 이번 주에 연결했다. 달력에서 오늘을 다시 고르거나 돌아보기에서 이번 주로 돌아오면 현재 날짜를 따라간다.
- 오늘의 목록 mutation 표시와 계획 정리·하루 마감의 임시 집계/피드백은 날짜 key로 분리했다. 진행 중 요청이 새 날짜의 집계에 끼어들지 않게 하며 이미 시작한 네트워크 요청을 새 날짜 요청으로 바꾸지 않는다.
- 빠른 기록의 결과 문구도 날짜 구독을 사용한다. 신규 자연어 파싱과 오늘 화면의 일정 작성 진입은 실행 시점 날짜를 사용한다. 오늘 이동 hook은 날짜 인자를 생략한 경우 요청 시작 시점 날짜를 사용하며 기존 명시 날짜 인자도 계속 지원한다.
- 이동 성공 시 상세와 응답의 실제 plannedDate 캐시를 갱신한다. 화면의 현재 날짜로 원본 날짜를 덮어쓰지 않는다. 응답 날짜가 없거나 유효하지 않으면 날짜를 추정해 삽입하지 않고 목록을 무효화해 다시 조회한다.
- 완료 성공 시 원래 조회 날짜의 예정 목록에서 항목을 제거하되, 완료 기록은 서버가 반환한 유효한 completedAt 날짜에 반영한다. 자정을 걸쳐 응답하면 전날의 완료 기록에 임의로 넣지 않는다. 두 날짜가 다르면 양쪽 하루 요약을 무효화한다. 완료 날짜를 확인할 수 없으면 목록을 다시 조회한다.
- 상세의 오늘/내일/7일 후 빠른 변경은 표시용 날짜를 갱신하고 실행 시점에도 날짜를 다시 계산한다. 날짜 없는 기록함 이동은 기존 동작을 유지한다.
- 날짜 계산 회귀 사례에 서울 자정 전후·연말·윤년의 다음 갱신 지연을 추가했다. 실제 타이머·복귀·UI 동작 테스트를 실행한 것은 아니다.

## 검토와 한계

구현 전 Today/달력/주간 돌아보기·빠른 기록·이동/완료 mutation·계획 정리/하루 마감 코드와 기존 날짜 변환·동기부여 AppState 사용을 확인했다. 기존 화면의 날짜 문맥·상태 표시를 보존하는 시간/데이터 처리 수정이다. Product Design의 맥락 보존·원본 근거·상태 일치 기준과 저장소 기본 검토 정책을 재사용했다. 신규 정보 구조 선택지가 없어 시각안 세 개를 만들지 않았고 새 이미지·Figma·외부 앱 조작도 없다.

영향 플랫폼은 Android·iOS·Web이다. 사용자 요청에 따라 테스트·`npm run validate`·실제 브라우저/기기·API 재현과 화면 감사는 보류했다. 코드 검토와 테스트 사례 추가를 검증 통과로 표현하지 않는다.

복귀 이벤트·자정 타이머·탭 유지/해제·빠른 날짜 전환·자정 직전 요청/직후 응답·pending 상태의 계획 정리/마감·여러 구독 정리·실제 완료 날짜와 캐시 일치는 실제 확인이 남아 있다. 레거시 날짜별 완료 화면과 명시 날짜의 집중 화면, 작성 중인 폼 날짜를 모두 현재 날짜로 바꾸는 전역 이행은 하지 않았다. 동기부여 문구 교체 정책도 이번에 변경하지 않았다.

## 다음 범위

오늘·달력·돌아보기의 기존 시각 방향을 유지한 상태다. 달력의 밀도·3주/월간 범위·이동 버튼과 목표 색상 반영을 포함한 큰 UI 변경은 시각 비교와 선택 후 진행한다. 백엔드 추가 요청의 유형 보존/목표 여정/색상/순서 계약 회신도 별도로 추적한다.
