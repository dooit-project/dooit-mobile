# 계획 탭의 새 Goal 연결 — F2a

2026-10-19 · `7cea6ed` 커밋, 미검증

후속 [F2b-1 반복 계획 관리](./GOAL_PLAN_EDITOR_2026-10-19.md)에서 새 Goal 아래 반복 계획 목록·생성/수정·상태를 연결했다. 아래 항목 미연결 설명은 F2a 당시 범위이며 일회성 항목·오늘 실행은 여전히 후속이다.

## 구현 전 검토

- 대상/목적: 기존 계획 탭에서 날짜가 없는 새 Goal을 만들고 수정·상태 관리한다. 오늘은 날짜별 실행, 계획은 방향과 구성을 다룬다는 기존 역할을 유지한다.
- 확인한 시안: [선택된 가로 목표 탭](./plan-navigation-2026-10-15/README.md)과 `05-goal-tabs-polished.png`를 직접 열었다. 생성 이미지이며 이번 구현 캡처가 아니다. DdayOverview/CreateForm/GoalTasks/OrderList·테마·기존 상태 관리를 코드로 읽었다.
- 적용한 기준/도구: Product Design index와 저장소 [검토 정책](../qa/PRODUCT_DESIGN_REVIEW_POLICY.md), 로컬 파일 읽기·이미지 열람. 새 레이아웃 탐색이 아닌 선택안의 API 연결·국소 폼 보정이므로 기존 세 안의 사용자 2번 선택을 재사용했다. 신규 시안·Figma·실제 화면 감사는 하지 않았다.
- 외부 패턴: 기존 선택안 문서에 기록된 Material 탭, Todoist 수동 순서, Things 항목 이동 자료의 판단을 재사용했다. 이번에는 외부 페이지를 새로 열거나 운영 앱을 조작하지 않았고 최신 사양을 주장하지 않는다.
- 유지/변경/이유: 큰 `계획` 제목 없이 목표 탭·전체 목표·제목 옆 관리 메뉴를 유지한다. 날짜 필수 입력을 없애고 결과/이유는 선택 입력으로 접는다. 진행률·연속 달성·비어 있는 일정 목록은 추가하지 않는다.

## 구현 범위

계획 route는 새 GoalOverview를 사용한다. 새 Goal과 기존 D-Day를 한 탭 목록에서 고를 수 있지만 내부 식별자는 `goal:{id}`와 `dday:{id}`다. 같은 숫자를 동일 목표로 취급하지 않으며 자동 생성/이관/중복 제거를 하지 않는다. 전체 목표 목록과 보조 기술 이름에서 기존 목표를 구분한다.

새 Goal은 제목·선택 목표일·선택 결과/이유·기기 색상으로 작성/수정한다. 목표일을 비우거나 지울 수 있고 자동으로 마감일을 부여하지 않는다. 수정 요청은 전체 내용이며 기존 linkedDdayGoalId는 보존한다. 생성 후 자동 선택하고, 서버 저장 후 색상/마지막 선택 저장만 실패하면 목표를 다시 생성하지 않고 성공 범위와 실패를 안내한다.

관리 메뉴에서 수정·잠시 멈춤·다시 시작·달성 기록/취소·보관을 선택한다. 상태를 바꾸기 전에 확인하고 앞으로의 반복 계획을 함께 멈출지 유지할지 고른다. 다시 진행해도 멈춘 계획을 자동 재개하지 않는다는 설명을 제공한다. 보관은 되돌릴 수 없음을 안내하며 보관 후에는 조회만 제공한다. 목표 자체 삭제는 만들지 않았다. 보관 목표도 선택/조회 가능하다.

기존 D-Day는 기존 GoalTasks와 항목 순서 편집을 재사용하고 항목 추가의 기존 `goalId` 경로도 유지한다. 삭제 등 기존 목표 관리는 `/dday`로 이어진다. 새 Goal ID를 이 경로로 전달하지 않는다. 기존 Today·달력·돌아보기·상세 화면을 일괄 전환하지 않았다.

## 색상·순서·선택 보존

새 preference key는 `dooit.goalPlanPreferences.v1`이며 계정 ID/API mode/URL별로 나뉜다. 문자열 식별자로 혼합 순서·마지막 선택·새 Goal 색상을 저장한다. 최초 읽기에서 기존 D-Day의 숫자 순서/선택을 읽어 D-Day namespace로 해석하되 원래 저장소를 덮어쓰지 않는다. 옛 D-Day 색상은 기존 저장소를 그대로 사용한다.

전체 목표의 순서 편집은 기존 드래그/위·아래 조작을 재사용하며 취소·되돌리기·완료가 있다. 저장 실패 시 편집 순서를 남긴다. 선택/순서/색상은 기기 저장이며 서버 동기화로 표시하지 않는다. 새 Goal은 새 저장 영역에만 색상을 저장한다. 서버 colorKey/G-06 회신은 여전히 대기다.

## 실패·캐시·접근성

Goal/D-Day를 따로 조회해 한쪽 실패가 다른 데이터를 지우지 않게 한다. 부분 실패를 표시하고 출처별 재시도를 제공한다. 저장/상태 변경 중 중복 제출과 맥락 전환을 잠그며, 입력 오류·API 실패는 폼/확인을 보존한다. 늦게 도착한 mutation의 owner가 현재 계정과 다르면 새 계정 캐시에 쓰지 않는다. 상태 변경은 계획/회차/여정/Task/일일 계획을 무효화한다.

터치 영역은 탭 48, 입력 48, 색 선택 44 기준이며 기존 버튼/아이콘/순서 조작을 재사용한다. 텍스트 상태·선택 선·라디오 선택으로 색만을 의미 전달 수단으로 쓰지 않는다. 긴 탭은 말줄임하고 본문/전체 목록에서는 원문을 제공한다. 실제 글자 확대·키보드 초점·보조 기술·드래그·날짜 키패드는 미확인이다.

## 후속과 검증 상태

**새 Goal 아래 반복 계획/일회성 항목 목록·추가/편집은 다음 F2b다.** 현재 새 Goal 상세는 목표 정보 관리까지이며, 실행 계획/오늘 회차/여정 화면 연결 완료가 아니다. 기존 D-Day 아래 항목은 계속 사용할 수 있다. linkedDdayGoalId만으로 기존 Task를 새 Goal 실천에 자동 귀속시키거나 서버 개인 데이터를 이관하지 않는다.

일반 Goal 생성의 서버 멱등성은 미확인이다. 진행 중 제출은 막지만 응답을 받지 못한 생성 결과를 자동으로 실패/재생성하지 않는 추가 복구는 후속 검토 대상이다. 현재 API client는 이 POST를 timeout 자동 재시도 목록에 넣지 않는다.

선택/색상/순서의 namespace·기존 값 보존·계정/API 분리와 부분 저장/저장 실패의 회귀 사례를 작성했다. 사용자 요청대로 `npm run validate`·테스트·구현 후 실제 화면 감사는 실행하지 않았다. Android/iOS/Web 공통 변경이며 새 의존성은 없다. 시안 검토와 포맷 적용을 실제 화면 통과로 기록하지 않는다.
