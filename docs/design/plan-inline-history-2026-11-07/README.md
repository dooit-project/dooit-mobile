## 방향과 구현 조건

- 계획 화면에서 목표에 연결된 현재 계획 다음에 최근 기록을 보여준다. 목표 제목 아래의 별도 기록 보기 버튼은 제거하는 제안이다.
- 반복 계획은 계속 계획에 남고, 실제 완료한 회차는 최근 기록에 표시한다. 일회성 완료와 직접 남긴 기록도 실제 원본과 날짜에 맞춰 표현한다. 분량이 확인되지 않으면 결과를 추정하지 않는다.
- 기록이 많을 때는 같은 화면에서 이전 기록을 이어 보여준다. 기록이 없을 때와 조회 실패는 구분하며 실패를 빈 상태로 처리하지 않는다. 로딩과 재시도, 중복 제거, 페이지 경계·동시 변경, 장기간 조회 및 동작 가능 여부는 구현 전에 별도 확인한다.
- 글자 대비를 유지하면서 기록의 체크를 작고 차분하게 표시한다. 시안의 체크는 즉시 완료 취소 버튼이 아니라 완료 상태의 표시다. 실제 조작 가능 여부는 버튼과 읽기 순서에 명확히 반영한다.
- 390×844를 목표로 생성한 그림이며 표시된 예시 데이터·시각 요소·기능은 실제 앱 동작이나 pixel 기준이 아니다. 제목이 긴 경우 줄바꿈하고, 기록이 많아져도 하단 탭과 주요 행동을 가리지 않도록 실제 화면에서 살핀다.
- 기존 돌아보기 탭은 여러 목표와 일상의 기록을 함께 살피는 역할로 유지한다. 기존 목표 단위 일회성 목록과 순서 저장 지원, 색 동기화 및 조회 계약은 별도로 확인하며 시안만으로 완료를 주장하지 않는다.

## 검토 범위

Product Design `ideate`로 사용자가 선택한 기존 방향을 보정했고 `imagegen-frontend-mobile`의 모바일 위계와 가독성 지침을 참고했다. 첫 시안에서 파란 완료 원이 과도하게 강조되어 두 번째 시안에서는 작은 중립 체크로 조정했다. `better-layout` 지침으로 계획과 기록의 위계·숨은 기록의 발견 가능성을, `better-writing` 지침으로 ‘최근 기록’과 ‘이전 기록 더 보기’의 의미를, `better-accessibility` 지침으로 색에만 의존하지 않는 표시와 읽기/조작 구분을 검토했다. 이들은 생성 이미지에 대한 설계 검토이며 실제 대비·터치·키보드·스크린리더 검증이나 독립 심사가 아니다.

[Todoist 공식 안내](https://www.todoist.com/help/todoist/features/view-completed-tasks-in-todoist-J19h2s)에서 완료 항목을 프로젝트 목록 아래에 표시하는 패턴을 참고했다. 실제 앱을 조작한 비교가 아니며 Dooit의 반복 실천 기록은 그 예와 동일한 동작이라고 가정하지 않는다. 사용자 테스트, Android/iOS/Web 실제 구현과 운영 API 검증은 진행하지 않았다.
