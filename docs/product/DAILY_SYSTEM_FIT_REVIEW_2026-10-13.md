# 매일의 작은 시스템과 세 가지 제품 원칙 점검

검토일: 2026-10-13 · 기준: `6fd5293`의 클라이언트 코드·기존 계약·테스트 소스

2026-10-13 후속 요구: 목표 아래 여러 반복 계획과 일회성 노력을 함께 지원한다. 최신 범위는 [목표·실행 계획·지나온 길](./GOAL_JOURNEY_EXPERIENCE.md)이 우선한다. 아래 기존 코드의 지원/제약은 유효하지만 단일 반복 행동만으로 제품 요구를 충족하지는 않는다.

## 결론과 사용자 결정

현재 Dooit에는 반복 일정·알림·회차 완료·완료 기록의 기반이 있다. 그러나 **작은 행동을 쉽게 반복하고, 어려운 날에는 줄여서 이어가고, 그 기록을 자신이 원하는 방향과 연결하는 경험은 아직 부족하다.** 반복 설정이 있다는 사실만으로 세 가지 제품 원칙을 충족했다고 판정할 수 없다.

사용자는 TO-BE 보드 **1번의 구조(오늘·계획·돌아보기) + 2번의 간결한 목록·타이포·여백** 조합을 선택했다. 이전에 선택한 제안형 실행 sheet는 유지한다. 프로젝트 외에도 매일 운동·영단어처럼 행동 자체가 반복되는 사례를 기본 검증 대상으로 삼는다. 조합 방향 선택은 완료됐고, 이 사례를 반영한 조합 시안과 세부 상태 검토는 구현 전에 남아 있다.

이번 점검은 코드와 계약의 기능 분석이다. 새 실제 화면 감사·운영 API·실기기 알림 검증은 수행하지 않았다. 앞선 [실제 화면 감사](../audits/product-architecture-2026-10-12/README.md)는 별도 근거다. 아래 현재 지원은 클라이언트에서 확인한 범위이며 백엔드 배포 완료를 뜻하지 않는다.

## 세 가지 원칙의 충족 여부

| 원칙                        | 현재 판단                   | 필요한 제품 행동                                                                                                       | 확인 과제                                                                         |
| --------------------------- | --------------------------- | ---------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| 의지보다 반복 가능한 시스템 | 부분 지원                   | 반복을 일정의 부가 설정에서 쉽게 만드는 주요 흐름으로 올림. 요일·시각/상황·기본/최소 행동, 선택적 알림, 휴식·재개 제공 | 영단어를 시간 입력 없이 매일 만들고, 다음 날 다시 만들지 않아도 오늘에 나타나는가 |

명언은 시작을 돕는 보조 장치다. 명언만 바뀌고 반복 설정·작은 행동·증거·복귀가 그대로라면 이 세 원칙은 구현되지 않은 것이다. 자신감 증가 자체는 코드 검증으로 증명할 수 없으며 사용자에게 기록이 어떤 의미로 느껴지는지 별도 확인한다.

## 두 가지 진입을 모두 지원

1. **작은 행동부터:** `매일 영단어 10개` → 주기·시작 조건·작은 버전 확인 → 저장. 큰 목표 질문을 먼저 통과하게 하지 않는다. 원하는 방향과의 연결은 선택이다.
2. **바람부터:** `해외에서 살아보고 싶어요` → 이유는 선택 → `영단어 10개` 같은 행동 하나 제안 → 사용자가 조정. 단어 학습만으로 그 꿈이 달성된다고 약속하지 않는다. 지금 행동하지 않고 보관할 수도 있다.

사용자 표기는 `반복할 행동 만들기`, 목록은 `매일 이어갈 일`처럼 쉽게 풀어쓴다. 내부 제품 모델의 시스템이라는 말을 모든 버튼에 넣지 않는다. 매일 외에도 평일·선택 요일을 제공해 지속 가능한 주기를 사용자가 고르게 한다.

위 분량은 예시이며 건강·학습 효과를 보장하는 권장량이 아니다. 하나부터 쉽게 시작하되 최신 요구에 따라 목표 아래 여러 반복 계획을 첫 버전에 포함한다. 여러 행동을 반드시 동시에 만들도록 강제하지 않는다.

## 매일의 실행은 기록보다 가벼워야 한다

- 오늘 행에서 무엇을 할지 바로 보인다. 짧은 반복 행동을 이미 했다면 `10개 했어요`처럼 기본 행동을 명시한 확인으로 기록할 수 있게 설계한다. 일반 체크에서 종류가 불명확하면 기본 실천으로 추정하지 않는다.
- 시작 전 도움이 필요하거나 작은 버전·휴식을 고를 때 선택된 제안형 sheet를 연다. 매일 `시작→타이머→긴 회고`를 의무화하지 않는다. 타이머 없이 실천 확인 가능.
- 단어·운동처럼 같은 행동을 반복하면 다음 행동 입력은 기본적으로 생략한다. 프로젝트처럼 첫 단계가 바뀔 때 선택적으로 남긴다.
- `이번에는 쉬기`와 `당분간 쉬기`를 구분하고 미실행은 기록 없음으로 둔다. 지난 4일을 영단어 40개로 오늘에 합산하지 않는다.
- 시스템 생성 시각·알림 시각·실제 실천 시각을 구분한다. 상황 조건은 사용자가 읽고 시작하는 단서이며 센서로 자동 감지하지 않는다.
- 계획한 분량은 실제 결과가 아니다. 기본/최소 실천 횟수는 집계해도 학습한 고유 단어 수·암기 정확도·실제 운동 시간은 별도 근거 없이 계산하지 않는다. 최초 버전의 범용 수량 카운터는 제외한다.

## 동기부여 문구의 구체적인 동작

사용자가 원하는 것은 다독이는 문장뿐 아니라 행동을 북돋는 짧고 힘 있는 문장이 바뀌며 보이는 경험이다. 두 톤을 함께 제공한다. 다음은 **노출 정책 제안**이며 UI/기능 구현 전이다.

- 오늘에 1–2줄 영역 한 곳을 둔다. 첫 방문에 한 문장, 새 날 또는 마지막 교체 후 4시간이 지나 다시 오늘을 열면 새 문장. 읽는 도중 자동 교체하지 않는다.
- 화면 이동·재렌더·완료 버튼마다 랜덤으로 바꾸지 않는다. 화면에는 하나만 노출하고 최근 7개는 가급적 제외한다. 후보가 적으면 오래된 것부터 재사용하며 빈 상태가 되지 않게 한다.
- 사용자가 원하면 `다른 문장`으로 직접 바꿀 수 있다. `덜 보기`는 하루 한 번만, `숨기기`는 비노출로 제안한다. 로컬 계정별로 문구 ID·노출 시각·최근 목록·설정을 관리한다.
- 사용자가 제시한 `내일은 그냥 오지 않는다`는 **출처 미확인 사용자 제안 문구**로 기록한다. 유명인의 이름을 붙이거나 dooit이 처음 쓴 문장이라고 표기하지 않는다. 실제 인물 명언은 원문·출처·번역·사용 조건을 검토한 뒤 추가한다.
- 자체 문구 초안: `원하는 내일을 위해, 오늘 작은 행동 하나.` / `아직 자신 없어도, 시작할 자리는 있어요.` / `큰 꿈을 오늘 다 이루지 않아도 돼요. 오늘의 한 걸음부터.`
- 휴식·미실행 복귀에는 `내일은 그냥 오지 않는다` 같은 긴박한 문구를 강제로 붙이지 않는다. `지난날을 만회하지 않아도 돼요. 오늘 가능한 만큼 다시 시작해요.`처럼 맥락에 맞는 후보를 쓴다.
- 격려/명언은 일반 문구로, `이번 주 기본 행동 3회·작은 행동 2회`는 실제 기록 feedback으로 구분한다. AI가 유명인 인용·실천 실적·감정을 생성하지 않는다.

주간 요약의 숫자는 실제 기록에서 얻어야 한다. 문구는 검토된 앱 내 콘텐츠로 시작하므로 명언 순환만을 위한 신규 백엔드나 AI 호출은 필요 없다.

| 1    | 선택된 조합 시안에 운동/단어·동기 문구·빠른 실천 확인 반영                                           | 없음. 조합 시각 목표 확인 후 UI 구현                                      |

| 3    | 오늘 표시·명시적 기본/최소 실천·휴식·취소·재개. 반복 행동에는 다음 행동 입력 생략                    | 회차 결과/스냅샷/중복 방지, 누락 비누적, nextAction 생략 허용             |

| 5    | 문구 목록·순환·맥락·숨기기, AI 초안/요약의 직접 입력·정형 fallback                                   | 정적 문구는 불필요, AI는 기존 요청 계약                                   |

기존 시스템 요청서는 이미 전달됐으므로 원본을 조용히 변경하지 않는다. 새 발견과 합의할 항목은 [반복 행동 보충 확인서](../api/API_PERSONAL_SYSTEMS_DAILY_CLARIFICATION.md)에 두었으며, 후속 [목표 중심 변경 요청서](../api/API_GOAL_JOURNEY_CHANGE_REQUEST.md)가 이를 참조해 함께 전달됐다. 둘을 독립 요청으로 중복 전달하지 않는다. 회신·계약·구현은 미확인이다. 코드에서 발견한 일반 작성의 단일 요일·mock 자연어 매일 미지원·템플릿 반복 누락은 real 동작과 구분하여 보완한다.

## 수용 기준

- 매일 07:00 운동과 시간 없는 매일 단어 행동을 별도로 설정할 수 있고, 기존 일정과 섞여도 오늘 해야 할 행동을 이해할 수 있다.
- 큰 꿈·이유·기한·예상 시간·매회 메모 없이도 행동 하나를 만들고 이어갈 수 있다.
- 기본/최소 실천 각각 확인·취소·수정하면 회차·Task·주간 증거가 일치한다. 시작만 누른 상태는 실천으로 집계하지 않는다.
- 쉬기·일시정지·재개 시 누락 회차가 쌓이지 않고 예약 알림도 맞춰진다. Web 알림 미지원과 native 실제 전달은 따로 검증한다.
- 1분 또는 1개 행동도 표현하고, 분량 없는 행동도 허용한다. 실제 시간이 자동으로 채워지지 않는다.
- 사용자 기록 없이 감정·학습량·성과를 추가하지 않는다. 근거 없는 주간 칭찬은 표시하지 않는다.
- 동기 문구는 바뀌되 읽는 도중 이동하지 않고 숨기기가 가능하다. 휴식 뒤 압박 문구가 나오지 않는다.

검증 결과는 아래에 이어 기록한다. 이번 변경은 점검·설계 문서이며 앱 기능 추가 완료가 아니다.

## 검증 결과

- `npm run validate`: typecheck·lint·format·문서 링크 통과. 기존 대표 스크린샷이 촬영 후 30일이 되어 최신성 검사 실패. 실제 재촬영 없이 manifest 날짜를 변경하지 않았다.
- 별도 `npm run check:release-static` 통과, `npm test` 98 suites / 498 tests 통과, `git diff --check` 통과. 기존 테스트 통과가 이번에 발견한 미지원 시나리오나 운영 API 검증을 대신하지 않는다.
- 이번 변경은 문서만이며 Android/iOS/Web 제품 코드·의존성은 그대로다. 새 검토·선택 기록은 커밋 전이고 push하지 않았다. 백엔드 보충 확인 항목은 목표 중심 변경 요청서에서 참조해 전달됐으며 회신 대기 상태다.
