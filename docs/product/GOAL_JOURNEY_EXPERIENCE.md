# 목표·실행 계획·지나온 길

Last updated: 2026-10-13

상태: 사용자 요구 반영, 기능·화면 설계 수정, 구현 전. 이 문서는 앞선 개인 시스템 하나 중심 제안보다 우선한다. 하나부터 쉽게 시작한다는 원칙은 유지하지만 **목표 하나에 여러 반복 계획과 일회성 행동을 연결하는 기능을 첫 버전에 포함한다.**

## 요구의 중심

사용자가 원하는 것은 목표를 위한 과정을 만들고, 실천하고, 돌아볼 수 있는 도구다. 예를 들어 토익 900점이라는 목표 아래 매일 단어 30개, 주말 문제풀이, 오늘 추가로 문제 30개 풀기를 함께 담는다. 목표는 방향·원하는 결과·선택한 날짜를 보여주고 일상에서는 작은 행동을 제안한다.

목표를 날짜 없는 바람으로만 축소하지 않는다. 목표 이름과 목표일을 쉽게 설정하며 아직 날짜를 정하지 못했다면 건너뛸 수 있다. 구체적 기준도 선택 입력한다. `토익 900점`은 점수가 제목에 있어도 시작할 수 있고, 필요하면 결과 기준을 정리하도록 돕는다. 목표 없는 일반 Task와 반복 행동도 유지한다.

## 기존 기능·화면의 실제 지원

이번 확인은 클라이언트 코드·계약 기반이다. 날짜 목표의 빈 화면은 [기존 감사](../audits/product-architecture-2026-10-12/README.md) 3–4단계에서 확인했다. 채워진 목표의 통합 흐름과 real API를 이번에 새로 화면 감사한 것은 아니다.

| 요구                  | 현재 코드·화면                                                         | 부족한 부분                                                                         |
| --------------------- | ---------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |

목표 날짜는 예시이며 시험 일정 안내가 아니다. 계획과 실천 기록을 구분한다. 할 일을 추가하거나 시작한 것만으로 지나온 길의 실천 수가 늘어나지 않는다. 일회성 행동도 반복 행동과 동등한 노력으로 표시하되 무엇을 했는지 구별한다.

## 필요한 화면과 위치

선택된 `오늘 · 계획 · 돌아보기`와 2번 보드의 시각 스타일을 유지한다. 기존 보드에 목표 상세가 빠져 있으므로 최종 설계로 보지 않는다.

| 화면                | 위치·첫 정보                                                        | 주요 행동                                                            |
| ------------------- | ------------------------------------------------------------------- | -------------------------------------------------------------------- |
| 목표 만들기·수정    | 계획 → 목표 만들기. 목표 이름, 원하는 결과, 목표일, 선택 이유       | 날짜 정하기/나중에 정하기, 저장 후 내 계획 세우기                    |
| 목표 상세           | 계획 → 내 목표 → 토익 900점. 목표·날짜·선택 이유와 반복 계획 목록   | 반복 계획 만들기, 이번에 할 일 추가, 이미 한 일 기록, 지나온 길 보기 |
| 내 실행 계획 만들기 | 목표 상세에서 진입, 목표는 미리 연결                                | 직접 행동·주기·시작 조건·최소 행동 설정; AI 도움은 선택              |
| 오늘                | 여러 목표의 오늘 회차와 일회성 할 일을 함께 표시, 각 행에 목표 이름 | 실천 확인, 작게 시작, 이번에는 쉬기, 목표에 연결한 추가 할 일        |
| 실천 확인·추가 기록 | 오늘 또는 목표 상세에서 짧게 입력                                   | 한 일·실천 날짜, 선택 메모/실제 분량, 저장·취소                      |
| 목표별 지나온 길    | 목표 상세 → 지나온 길, 돌아보기 → 목표 선택 모두 같은 기록으로 이동 | 기간·목표별 반복/추가 실천 원본, 계획 변경 이력, 근거 있는 요약      |
| 돌아보기            | 이번 주 전체 기록과 목표별 진입                                     | 특정 목표의 전체 기간 보기, 계속하기/계획 조정                       |

계획 루트는 목표와 연결되지 않은 반복 행동·보관한 생각도 담는다. 목표를 만든 사람에게는 내 목표가 우선이다. 목표 상세를 하단 탭으로 추가하지 않는다. 날짜 선택은 오늘 상단 달력 바로가기를 유지한다. 검색·설정·공유 공간 등 기존 경로도 보존한다.

## 토익 예시로 보는 전체 흐름

1. **목표 정하기:** `토익 900점 받기`, 목표일 `2026-11-30`. 이미 마음속에 정한 내용을 바로 입력한다. 모호한 바람이라면 원하는 변화·달성 기준을 선택적으로 묻는다.
2. **스스로 계획하기:** 직접 `영단어 30개`, 매일, 아침 식사 후, 최소 3개를 정한다. 이어서 `토익 문제 5개`, 선택한 주말 요일, 최소 1개를 추가한다. AI가 일괄 확정하거나 기한에 맞춘 과량 계획을 강제하지 않는다.
3. **주기의 뜻 확인:** `주말마다`가 토·일 각각인지, 주말 중 한 번인지 먼저 명확히 한다. 초기 날짜 기반 회차에서는 사용자가 토요일 한 번 또는 토·일 각각을 고르고 다음 실행 미리보기를 확인한다. 주말 중 아무 때나 1회 같은 기간 목표는 날짜 기반 구현과 같은 것으로 가장하지 않는다.
4. **오늘 실행:** 오늘 예정된 단어 행동을 표시한다. 짧은 행동은 완료를 명시적으로 확인하면 끝낸다. 작게 시작하거나 쉬고 싶을 때 선택된 실행 sheet가 돕는다. 매회 타이머·긴 메모는 필수가 아니다.
5. **추가 노력 계획:** `오늘 문제 30개 풀기`를 목표에 연결해 추가한다. 완료 전에는 할 일이다. 이것을 매일 반복으로 만들지 않으며 기존 주말 회차도 자동 완료하지 않는다.
6. **이미 한 노력 기록:** 앱을 켜기 전에 풀었다면 `이미 한 일 기록`에서 같은 목표와 실제 날짜로 남긴다. 가짜 미완료 Task를 먼저 만들고 오늘로 옮길 필요가 없어야 한다.
7. **지나온 길:** 예시로 `10/13 단어 30개 실천`, `10/13 추가 문제풀이`, `10/14 작은 행동 실천`을 시간순으로 읽는다. 날짜·행동·기본/최소·일회성의 구분과 실제 메모를 제공한다. 예시가 실제 성과를 뜻하지 않는다.
8. **조정과 달성:** 계획이 버거우면 행동 크기·주기를 바꾼다. 목표일 변경은 과거 기록을 지우지 않는다. 목표일이 지났거나 체크 횟수가 많다는 이유만으로 실패·목표 달성으로 처리하지 않는다. 사용자가 결과를 확인한다.

## 기록을 믿을 수 있게 만드는 규칙

- Task 완료에서 생긴 기록과 목표 여정 기록은 같은 원본이다. 별도로 이중 기록하지 않는다. 반복 회차와 연결 Task도 한 번만 집계한다.
- 이미 한 일 입력과 기존 완료 Task 연결은 별도 경로다. 기존 기록을 연결할 때 복제하지 않는다. 비슷한 제목이라는 이유로 실제 별도 노력을 자동 삭제/병합하지 않는다.
- 추가로 푼 30문제가 주말 계획 5문제와 같은 실행인지 임의로 판단하지 않는다. 초기에는 독립적인 기록으로 두며 같은 행동을 두 번 기록하지 않도록 안내한다.
- `기본 실천 3회·작은 실천 2회·추가 행동 1회`처럼 기록 유형을 분리한다. 실천 횟수를 목표 달성률이나 점수 상승으로 환산하지 않는다.
- 제목의 계획 분량과 실제 분량을 구분한다. 수량은 실제 사용자가 기록했을 때만 사용하고 단어·문제·분을 합산하지 않는다. 고유 단어 수·암기율은 추정하지 않는다. 첫 버전은 제목·확인된 실천·선택 메모로도 충분하다.
- 반복 계획 변경·목표 연결 변경 이후에도 과거에는 어느 목표를 위해 어떤 행동을 했는지 보존한다. 과거 기록의 목표 변경은 명시적 수정만 허용한다.
- 날짜 없는 목표·연결 없는 행동도 유효하다. 목표 보관/달성 시 기록을 유지하고 미래 반복을 계속할지 중지할지 사용자가 정한다.
- 주간뿐 아니라 목표 시작부터의 기록을 기간/페이지 단위로 조회한다. 일부만 불러온 목록을 전체 실적으로 집계하지 않는다.

## 동기부여와 AI

짧고 바뀌는 동기 문구는 오늘·목표 상세에 절제해서 배치한다. `작게 해도, 꾸준히 돌아오는 일이 쌓여요.`처럼 반복의 의미를 설명하고, 실제 기록이 있으면 구체적인 행동을 함께 보여준다. 휴식·복귀에는 압박 문구 대신 다음 실행을 선택하게 한다. 문구 교체·숨기기는 [일상 반복 점검](./DAILY_SYSTEM_FIT_REVIEW_2026-10-13.md)의 정책 제안을 따른다.

AI는 목표 구체화 질문, 사용자가 정할 실행 계획 초안, 기록 근거 요약, 부담을 줄이는 조정만 돕는다. 사용자가 직접 여러 계획을 만들 수 있어야 하고 AI 없이 전 과정을 완료할 수 있어야 한다. 예시의 단어/문제 분량은 사용자 계획 사례이며 토익 900점을 보장하는 학습 처방이 아니다.

## 수정된 최소 구현 범위와 개발 순서

1. 목표 이름·선택 날짜·원하는 결과·상태를 만들고 수정한다. 기존 D-Day 목표와 연결 Task를 보존하는 이행 계약부터 확정한다.
2. **한 목표 아래 최소 두 개 이상의 독립 반복 계획**을 만들고 수정·일시정지·재개한다. 첫 계획부터 쉽게 시작하되 두 번째 계획을 기능 제한으로 막지 않는다.
3. 같은 목표에 일회성 할 일을 만들고 기존 Task도 연결한다. 이미 한 일의 직접 기록을 지원한다.
4. 오늘에서 기본/최소 실천·휴식·완료 취소를 처리하고 목표 여정과 일치시킨다.
5. 목표별 전체 기간·주간 여정과 원본을 조회한다. 계획한 일·실천·계획 변경·목표 결과는 구분한다.
6. 선택된 조합 스타일로 목표 생성·상세·계획 작성·추가 노력·여정 화면을 설계하고 정상/빈 상태/실패/복귀를 실제 감사한다. 구현 전 의미 있는 화면 선택지는 저장소 정책에 따라 시각 비교한다.

복잡한 목표 계층·한 행동의 여러 목표 배분·학습 콘텐츠·범용 수량 계측·자동 점수 예측·자동 일정 재배치·Workspace 목표 확장은 제외한다. 기존 복수 목표를 삭제하거나 전체 앱의 목표 수를 하나로 제한하지 않는다. MVP 검증 시나리오는 하나의 목표에 여러 계획과 일회성 노력이 함께 작동하는 것이다.

## 프론트·백엔드 경계

프론트: 목표 상세/계획 작성/추가 노력/여정, 목표 맥락 유지, 날짜/주기 미리보기, 직접 입력, AI 제안 편집, 문구 순환, 저장/실패/재시도와 cache 일치.

백엔드: 목표 모델과 기존 D-Day 이행, 목표-반복 계획-회차-일회성 Task 관계, 이미 한 일 기록, 원본 기반 여정·집계, 수정/취소·기록 보존·멱등성·시간대·권한. 기존 API 재사용 여부를 먼저 확인한다.

이미 전달한 시스템 요청서는 그대로 보존하고, 범위가 달라진 내용은 [목표 중심 변경 요청서](../api/API_GOAL_JOURNEY_CHANGE_REQUEST.md)로 따로 관리한다. 변경 요청서는 2026-10-13 백엔드 담당자에게 전달됐으며 회신 대기 상태다. 이전 일상 반복 보충 확인서는 새 요청서에 참조해 함께 전달됐고 독립된 두 요청으로 중복 전달하지 않는다.

## 완료 판정 시나리오

목표와 목표일 생성 → 매일 단어/주말 문제풀이 두 계획 생성 → 오늘 기본/최소 실천 → 추가 문제풀이 Task 생성·완료 → 어제 이미 한 일 기록 → 목표의 전체 여정에서 모두 한 번씩 확인 → 기록 취소·계획 변경 후 과거 보존/집계 일치 → 목표 결과 확인.

시나리오 전체가 동작하기 전에는 목표 여정 기능 구현 완료로 표시하지 않는다. 이번 작업은 기능 확인과 명세 수정이며 앱 코드는 변경하지 않았다.

## 문서 변경 검증

2026-10-13 `npm run validate`의 typecheck·lint·format·문서 링크는 통과했다. 기존 대표 스크린샷의 촬영 후 30일 최신성 검사에서 중단되어 전체 validate는 통과가 아니다. 마지막 문서 수정 후 포맷과 링크·`git diff --check`를 다시 확인했다. 앱 코드가 바뀌지 않아 직전 98 suites / 498 tests 통과 결과 이후 테스트를 재실행하지 않았으며, 그 결과는 새 목표 여정 기능의 구현 검증을 뜻하지 않는다. 문서 변경은 커밋 전이며 push하지 않았다. 변경 요청서는 사용자 확인으로 전달됐지만 회신·계약·구현은 미확인이다.
