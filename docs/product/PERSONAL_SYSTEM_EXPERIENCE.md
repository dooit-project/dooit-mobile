# 목표를 위한 계획·시스템·실천 증거 경험

Last updated: 2026-10-13

상태: 제품 제안과 개발 분해 완료, Today 실행 sheet와 TO-BE 1번 구조+2번 스타일 선택, 상세 시안·API 계약 미확정, 구현 전. 현재 출시 범위를 확대하거나 기존 출시 검증 우선순위를 변경하지 않는다.

최신 제품 범위는 [목표·실행 계획·지나온 길](./GOAL_JOURNEY_EXPERIENCE.md), 작업 순서는 [로드맵](./ROADMAP.md)을 따른다. 이미 전달된 [시스템 요청서](../api/API_PERSONAL_SYSTEMS_REQUEST.md)의 단일 시스템 제한은 최신 요구와 다르며 [목표 중심 변경 요청서](../api/API_GOAL_JOURNEY_CHANGE_REQUEST.md)를 별도로 작성해 2026-10-13 전달했다. 회신·계약 합의·구현은 미확인이다.

## 제품 목표와 원칙

사용자가 목표와 원하는 결과·날짜를 구체화하고, 그 아래 여러 반복 계획과 일회성 행동을 만들며, 실제 해온 과정을 목표별로 돌아보도록 돕는다. 목표는 방향으로 쓰고 오늘은 실행 가능한 행동에 집중한다. 목표일은 쉽게 입력하되 미정도 허용한다. 목표 없는 일반 Task·독립 반복 행동도 유지한다.

- 시작 조건, 기본 행동, 최소 행동을 가진 반복 계획 하나부터 쉽게 시작하되 목표 하나에 여러 계획을 연결할 수 있다.
- 반복 외의 일회성 행동과 이미 한 일도 같은 목표에 연결하고 여정에 함께 기록한다.
- 기본 행동과 최소 행동을 모두 유효한 실천으로 인정한다.
- 시작 버튼 선택이나 예정 시간만으로 실제 실천·소요 시간을 추정하지 않는다.
- 기록 없음, 실천, 사용자가 선택한 휴식을 구분한다. 휴식에 점수나 실패 표시를 붙이지 않는다.
- 빠진 실행을 자동으로 누적하거나 만회를 요구하지 않는다.
- AI는 기록에 없는 성과·감정을 만들지 않고 변경은 사용자 확정 후 적용한다.

## 일상 반복 행동으로 구체화

2026-10-13 사용자 설명에 따라 운동·영단어처럼 매일 같은 작은 행동을 반복하는 경험을 기본 사례로 삼는다. [기능·세 원칙 점검](./DAILY_SYSTEM_FIT_REVIEW_2026-10-13.md)에 기존 지원·제약·수용 기준을 기록했다. 일반 작성의 반복/알림은 일정 유형에 한정되며, 템플릿의 반복 설정과 실제 적용 검증은 별도로 구분한다.

작은 행동부터 바로 만들거나 바람에서 행동으로 이어갈 수 있다. 큰 꿈·이유 입력은 필수가 아니다. 같은 행동을 반복할 때 다음 행동·매회 메모는 생략하고, 사용자가 명시적으로 기본/작은 행동을 확인하는 가벼운 경로를 제공한다. 프로젝트의 다음 행동 넘기기는 선택 기능으로 유지한다.

## 핵심 흐름과 화면

1. **목표 정하기:** 계획의 내 목표에서 이름·원하는 결과·목표일을 정한다. 이유와 날짜 미정은 선택이다. 아직 행동하지 않을 바람은 보관할 수 있다.
2. **스스로 계획하기:** 목표 상세에서 반복 계획을 여러 개 추가한다. 직접 작성 또는 AI 초안으로 주기·시작 조건·기본/최소 행동을 정하고 다음 실행을 확인한다. 다음 행동·알림은 선택이다.
3. **오늘 실행:** 목표 이름과 함께 오늘 회차·일회성 할 일을 보여준다. 짧은 행동은 명시적 실천 확인으로 끝내고, 작게 시작·휴식은 선택한 제안형 sheet에서 돕는다.
4. **추가 노력:** 목표 상세/오늘에서 이번에 할 일을 추가하거나 이미 한 일을 실제 날짜로 기록한다. 계획한 행동과 완료한 기록을 구분한다.
5. **지나온 길:** 돌아보기와 목표 상세에서 같은 목표의 주간·전체 기간 기록을 연다. 반복/최소/일회성 노력·원본 메모와 근거 요약을 보여준다. 계획 변경은 실천 수에 합산하지 않는다.
6. **조정·복귀:** 시간대·행동 크기·첫 단계·주기를 조정하고 휴식·일시정지·재개를 지원한다. 과거 누락을 오늘로 몰아서 만회시키지 않는다.
7. **목표 결과:** 사용자가 결과를 확인한다. 반복 완료 수로 목표 달성률을 추정하거나 날짜가 지났다고 자동 실패 처리하지 않는다.

목표 아래 여러 활성 반복 계획은 첫 버전에 포함한다. 각 계획을 개별 수정·정지·재개하고 과거 행동·목표 귀속은 보존한다. 여러 목표 간 복잡한 배분·계층은 별도 범위다. 기존 목표를 하나로 제한하지 않는다.

## 다독임·명언

실행을 방해하지 않는 짧은 문구를 Today, 집중, 실천 완료, 복귀, 주간 회고에 맥락별로 배치한다. 매번 닫아야 하는 팝업과 실행 버튼을 밀어내는 큰 카드는 사용하지 않는다. 기존 Today의 큰 정보 카드 최대 한 개 원칙을 유지한다.

- 일반 응원·명언과 실제 기록에 근거한 피드백을 구분한다.
- 검토된 정적 문구 묶음을 앱에 포함하고 AI 생성은 필수로 하지 않는다.
- 동기부여 문구가 바뀌며 보이기를 원하는 사용자 요청을 반영한다. 새 날 또는 4시간 이후 재방문 시 교체, 화면을 읽는 동안 유지, 다른 문장 보기·최근 7개 중복 회피를 초기 정책으로 제안한다. 덜 보기는 하루 한 번으로 줄인다. 상세 기준은 [일상 행동 점검](./DAILY_SYSTEM_FIT_REVIEW_2026-10-13.md)을 따른다.
- 덜 보기·숨기기 설정과 노출 이력은 첫 버전에서 기기 로컬에 저장한다. 계정 전환 시 이력 범위를 분리한다.
- 인물 명언은 원문·번역·출처·사용 조건을 확인한 콘텐츠만 사용한다. dooit 자체 문구에는 인물 이름을 붙이지 않는다.
- 잠깐 쉬어가기 화면은 막막함·여력 부족·휴식·응원 중 원하는 도움을 선택하고 다음 행동 구체화·최소 행동·쉬기로 연결한다. 자유 대화형 코치는 제외한다.

자체 문구 예시: “오늘 가능한 크기로 시작해도 괜찮아요.”, “지난 계획을 모두 만회할 필요는 없어요. 다음 행동부터 골라볼까요?” 휴식에 노력이나 성취를 꾸며 붙이지 않는다.

## AI 역할과 대체 경로

| 역할                | 입력·결과                                     | 제한·실패 시 경로                            |
| ------------------- | --------------------------------------------- | -------------------------------------------- |
| 시스템 초안         | 목표·일상 조건 → 추가할 반복 계획 초안        | 직접 작성 가능, 확정 전 저장·실행 생성 안 함 |

횟수·날짜는 코드/서버가 계산한다. “피곤했던 날” 등 감정·상태는 사용자 기록이 있을 때만 언급한다. AI에 보내는 바람·메모와 보관 범위를 사용자가 이해할 수 있게 안내하며 서버에서 키와 호출을 관리한다.

전체 화면의 역할·탐색 추천은 [2026-10-13 제품 구조 검토](./PRODUCT_ARCHITECTURE_REVIEW_2026-10-13.md)를 따른다. 이미 전달한 백엔드 요청 계약은 이번 정보 구조 제안에서 변경하지 않았다.

2026-10-13: TO-BE 1번 구조와 2번 스타일 조합을 사용자가 선택했다. 방향을 다시 고르지 않고 일상 반복 행동을 반영한 조합 시안·상세 상태로 진행한다. 순환 명언은 아직 구현되지 않았다.

## 최소 구현 범위와 완료 조건

목표 생성·날짜/결과 구체화→여러 반복 계획과 일회성 행동→오늘 실천/이미 한 일 기록→목표별 주간·전체 여정→조정/목표 결과 확인을 포함한다. 기본·최소 행동, 휴식·정지·재개, 선택 메모·다음 행동, 순환 동기 문구·잠깐 쉬어가기, AI 초안/요약과 대체 경로를 유지한다. AI 조정은 직접 조정 루프 이후 연결할 수 있다.

복잡한 목표 계층·한 행동의 여러 목표 배분, 전용 타이머, 자동 일정 재배치, 점수·연속 달성·경쟁, Workspace 공유, 자유 대화 코치, 서버 push, 문구 CMS는 제외한다.

사용자는 AI 없이도 핵심 루프를 완료할 수 있어야 한다. 최소 행동 실천과 휴식을 구분하고 과거 미실행이 밀린 일로 누적되지 않아야 한다. 완료 취소·시스템 변경 뒤 원본과 주간 집계가 일치해야 한다. 기록 없는 감정·성과를 요약하지 않아야 한다. 선택된 시각 방향과 실제 화면 검증이 있어야 구현 완료로 판정한다.
