# 원하는 삶을 위한 시스템·실천 증거 경험

Last updated: 2026-10-12

상태: 제품 제안과 개발 분해 완료, 시각 방향·API 계약 미확정, 구현 전. 현재 출시 범위를 확대하거나 기존 출시 검증 우선순위를 변경하지 않는다.

작업 순서는 [로드맵](./ROADMAP.md), 백엔드에 전달할 독립적인 요청서는 [시스템·실천 증거 백엔드 요청서](../api/API_PERSONAL_SYSTEMS_REQUEST.md)를 따른다.

## 제품 목표와 원칙

사용자가 원하는 방향을 인정하고, 지속 가능한 시스템 하나를 만들고, 일상에서 실천한 구체적인 증거를 돌아보도록 돕는다. 목표는 방향으로 쓰고 오늘은 실행 가능한 행동에 집중한다. 큰 꿈·기한·성과 수치 입력을 강제하지 않으며 일반 Task 사용도 유지한다.

- 시작 조건, 기본 행동, 최소 행동을 가진 시스템 하나부터 시작한다.
- 기본 행동과 최소 행동을 모두 유효한 실천으로 인정한다.
- 시작 버튼 선택이나 예정 시간만으로 실제 실천·소요 시간을 추정하지 않는다.
- 기록 없음, 실천, 사용자가 선택한 휴식을 구분한다. 휴식에 점수나 실패 표시를 붙이지 않는다.
- 빠진 실행을 자동으로 누적하거나 만회를 요구하지 않는다.
- AI는 기록에 없는 성과·감정을 만들지 않고 변경은 사용자 확정 후 적용한다.

## 기존 기능과 새로운 요구

근거는 [PRD](./PRD.md), `src/types/task.ts`, `src/types/dday.ts`, `src/features/today/today-focus-screen.tsx`다. 백엔드 소스·실행 OpenAPI와 현재 실제 화면은 이번 제안에서 검증하지 않았다. 내장 브라우저는 생성·연결 모두 unavailable 응답으로 실제 화면 감사가 불가능했다.

| 기존 기반             | 재사용                               | 추가 요구·제한                                                      |
| --------------------- | ------------------------------------ | ------------------------------------------------------------------- |
| 빠른 기록·IDEA·기록함 | 바람을 보관하고 시스템 생성으로 연결 | 바람 전환 안내; 모든 아이디어를 시스템으로 전환하지 않음            |
| 반복 Task             | 요일별 실행과 기존 목록 연결         | 상황 기반 시작 조건, 기본·최소 행동, 회차 수명 정책                 |
| Today·Daily Plan      | 오늘 실행 진입                       | 시스템 회차 식별; focus 최대 3개 정책과 별개이며 자동 등록하지 않음 |
| 한 가지 실행          | 한 행동에 집중하는 기존 화면         | 현재 session-only; 실천 기록·다음 행동 연결 필요                    |
| 체크리스트            | 첫 행동 구체화                       | 회차 간 다음 행동과 같은 데이터로 간주하지 않음                     |
| 완료 기록·하루 마감   | 실천 회고 기반                       | 시스템별 기록·주간 집계 필요                                        |
| D-Day                 | 기한 있는 방향의 선택적 연결         | targetDate 필수이므로 기한 없는 바람의 기본 entity로 사용하지 않음  |
| 알림                  | 기존 로컬 예약·선택 이동             | 상황을 자동 감지하지 않으며 선택적인 알림 시각 별도 설정            |
| 추천 API              | 기존 추천 유지                       | 생성형 AI 시스템 제안·회고 계약 확인되지 않음                       |

## 핵심 흐름과 화면

1. **바람 발견**: Today의 선택적 안내, 더보기의 내 시스템, IDEA 상세에서 진입한다. 만들기·배우기·일상 바꾸기 선택과 직접 입력을 제공한다. 이유 질문은 건너뛸 수 있고 아직 실행하지 않을 바람은 IDEA로 보관한다.
2. **시스템 생성**: AI 초안 또는 직접 작성으로 시작 조건·기본·최소 행동·첫 행동을 정한다. 초안 수정과 다음 실행 미리보기 후 저장한다. 알림은 선택이다.
3. **Today 실행**: 예정 회차를 기존 실행 목록에 표시한다. 시작 조건·기본 행동·지난 다음 행동과 시작하기·작게 시작하기·이번에는 쉬기를 제공한다. 타이머는 필수가 아니다.
4. **실천 확인**: 사용자가 실천했어요를 선택할 때 저장한다. 오늘 한 일·다음 행동은 선택 입력이다. 최소 행동은 부분 성공으로 낮춰 표시하지 않는다. Task 체크에서 들어와도 같은 기록 규칙을 사용한다.
5. **일주일의 증거**: 실천 회차·날짜 수, 실제 메모, 근거 있는 요약을 보여준다. 그대로 이어가기·시스템 조정하기로 연결한다. 기록이 없으면 기록 부재만 설명한다.
6. **복귀·조정**: 시간이 없음→시간대·크기 조정, 막막함→첫 행동 구체화, 버거움→최소 행동을 기본으로 변경, 잊음→일상 조건·알림 조정, 쉬고 싶음→이번 회차 쉬기·일시정지. 이유 응답과 조정은 선택이다.

시스템 수정·일시정지·재개는 상세에서 제공한다. 여러 활성 시스템의 관리 UX는 첫 버전에서 제외한다. 동시 활성 개수 제한과 종료 후 새 시스템 생성 규칙은 계약 확정 시 결정한다.

## 다독임·명언

실행을 방해하지 않는 짧은 문구를 Today, 집중, 실천 완료, 복귀, 주간 회고에 맥락별로 배치한다. 매번 닫아야 하는 팝업과 실행 버튼을 밀어내는 큰 카드는 사용하지 않는다. 기존 Today의 큰 정보 카드 최대 한 개 원칙을 유지한다.

- 일반 응원·명언과 실제 기록에 근거한 피드백을 구분한다.
- 검토된 정적 문구 묶음을 앱에 포함하고 AI 생성은 필수로 하지 않는다.
- 같은 날 문구를 안정적으로 유지하고 최근 본 문구 반복을 줄인다. 명시적 노출 간격은 시각 검토에서 정한다.
- 덜 보기·숨기기 설정과 노출 이력은 첫 버전에서 기기 로컬에 저장한다. 계정 전환 시 이력 범위를 분리한다.
- 인물 명언은 원문·번역·출처·사용 조건을 확인한 콘텐츠만 사용한다. dooit 자체 문구에는 인물 이름을 붙이지 않는다.
- 잠깐 쉬어가기 화면은 막막함·여력 부족·휴식·응원 중 원하는 도움을 선택하고 다음 행동 구체화·최소 행동·쉬기로 연결한다. 자유 대화형 코치는 제외한다.

자체 문구 예시: “오늘 가능한 크기로 시작해도 괜찮아요.”, “지난 계획을 모두 만회할 필요는 없어요. 다음 행동부터 골라볼까요?” 휴식에 노력이나 성취를 꾸며 붙이지 않는다.

## AI 역할과 대체 경로

| 역할                | 입력·결과                                     | 제한·실패 시 경로                            |
| ------------------- | --------------------------------------------- | -------------------------------------------- |
| 시스템 초안         | 바람·일상 조건 → 시스템 하나의 초안           | 직접 작성 가능, 확정 전 저장·실행 생성 안 함 |
| 첫 행동·시스템 조정 | 현재 시스템·선택한 어려움 → 한 가지 조정 제안 | 직접 수정 가능, 자동 적용 안 함              |
| 주간 회고           | 서버 집계·메모 → 짧은 요약과 근거 기록        | 정형 요약·원본 목록 유지                     |

횟수·날짜는 코드/서버가 계산한다. “피곤했던 날” 등 감정·상태는 사용자 기록이 있을 때만 언급한다. AI에 보내는 바람·메모와 보관 범위를 사용자가 이해할 수 있게 안내하며 서버에서 키와 호출을 관리한다.

## 최소 구현 범위와 완료 조건

개인 시스템 하나 중심의 생성→실천→주간 증거→조정, 기본·최소 행동, 휴식·일시정지, 선택 메모·다음 행동, 정적 응원·잠깐 쉬어가기, AI 초안·회고와 대체 경로를 포함한다. AI 조정은 직접 조정 루프 이후 연결할 수 있다.

복수 시스템 관리, 전용 타이머, 자동 일정 재배치, 점수·연속 달성·경쟁, Workspace 공유, 자유 대화 코치, 서버 push, 문구 CMS는 제외한다.

사용자는 AI 없이도 핵심 루프를 완료할 수 있어야 한다. 최소 행동 실천과 휴식을 구분하고 과거 미실행이 밀린 일로 누적되지 않아야 한다. 완료 취소·시스템 변경 뒤 원본과 주간 집계가 일치해야 한다. 기록 없는 감정·성과를 요약하지 않아야 한다. 선택된 시각 방향과 실제 화면 검증이 있어야 구현 완료로 판정한다.
