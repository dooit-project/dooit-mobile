# 빠른 등록과 기록함 노출 결정

Last updated: 2026-08-29

Status: 구현 및 Chrome 390px 캡처 비교 완료

## 문제

빠른 등록의 입력 부담은 낮지만 날짜를 해석하지 못한 항목은 기록함으로 저장된다. 저장 직후 composer 안에서는 제목, 저장 위치, `오늘 할 일로 이동`, `내용 확인`을 볼 수 있으나 composer를 닫으면 결과 상태가 사라진다.

Today에는 기록함이 지난 미완료·추천과 합쳐진 `정리할 항목` 숫자로만 남는다. 데이터는 정상 저장됐어도 사용자는 방금 기록한 항목이 어디에 있는지 다시 확인하기 어렵다.

## 제품 결정

기록함 전체 목록을 Today에 펼치지 않는다. 대신 **최신 기록 1개가 보이는 compact 기록함 preview**를 제공하고, 지난 미완료·추천 정리와 분리한다.

```text
오늘 할 일
  …

기록함 3
  방금 기록 · 여행 준비물 확인
  날짜는 나중에 정해도 괜찮아요.                  정리하기 ›

하루 정리 2
  지난 미완료 1 · 추천 1                         확인하기 ›

오늘 완료한 일
  …
```

기본 화면에 추가되는 것은 기록함 한 줄 preview뿐이다. 전체 목록, 통계, 경고 card와 반복 알림은 추가하지 않는다.

## 왜 이 방식인가

- 방금 한 행동의 결과를 같은 Today 흐름에서 다시 확인할 수 있다.
- 날짜를 즉시 정하라고 강요하지 않아 빠른 등록의 장점을 유지한다.
- 기록함 전체를 펼치지 않아 Today의 정보 밀도를 크게 늘리지 않는다.
- 지난 미완료·추천과 분리돼 `기록함에 저장`이라는 시스템 결과와 사용자의 다음 위치가 일치한다.
- 항목 수를 빨간 badge나 경고로 표현하지 않아 미정리 기록이 죄책감이나 할 일 압박으로 느껴지지 않는다.

## 표시 규칙

### 기록함 preview

- Inbox 항목이 1개 이상일 때만 Today에 표시한다.
- 가장 최근 `createdAt` 항목 1개만 제목 한 줄로 보여 준다.
- 같은 앱 사용 중 빠른 등록으로 만든 항목이면 `방금 기록` label을 붙인다.
- 새로고침 뒤에는 `방금`을 추측하지 않고 최신 제목과 `날짜를 정하지 않은 기록`만 표시한다.
- row 전체를 누르면 `/today/review`의 기록함 section으로 이동하고 해당 section에 초점을 둔다.
- `정리하기`는 상세 form을 바로 열기보다 기록함 목록으로 이동한다. Today 이동은 저장 직후 결과 영역에서만 빠른 행동으로 유지한다.
- Inbox가 0개면 빈 기록함 section이나 유도 문구를 보여 주지 않는다.

### 하루 정리

- 현재 `정리할 항목`에서 기록함 count를 빼고 지난 미완료·추천만 표시한다.
- 두 항목이 모두 0이면 row를 숨긴다.
- `하루 정리`는 사용자의 계획 검토이고, 기록함은 저장 위치라는 서로 다른 의미를 유지한다.

### 빠른 등록 결과

현재 결과 구조는 유지하되 문구를 덜 시스템 중심으로 바꾼다.

| 현재                                  | 제안                                                  |
| ------------------------------------- | ----------------------------------------------------- |
| `날짜 정보 없이 기록함에 저장했어요.` | `기록함에 저장했어요. 날짜는 나중에 정해도 괜찮아요.` |
| placeholder `오늘 할 일`              | `할 일을 입력하세요`                                  |
| `오늘 할 일로 이동`                   | `오늘로 옮기기`                                       |

placeholder에 `오늘`을 쓰면 날짜 없는 문장이 기록함으로 가는 실제 동작과 충돌한다. 저장 전에 자연어 날짜·시간을 함께 입력할 수 있다는 짧은 도움말은 composer가 열린 상태에서만 한 번 제공한다.

## `영감`이라는 표현

`영감`은 부드럽지만 모든 빠른 기록을 설명하는 기본 이름으로는 좁다. 장보기, 연락, 업무처럼 실행해야 하는 할 일도 들어오기 때문이다.

- navigation과 저장 위치의 이름은 `기록함`을 유지한다.
- 부담을 낮추는 설명 문구에는 `생각난 일을 가볍게 남겨두세요`처럼 영감의 정서를 사용한다.
- `IDEA` 유형이 명시적으로 선택된 항목에만 `아이디어` label을 사용할 수 있다.
- 기록함 전체를 `영감`으로 바꾸거나 별도 Inspiration tab을 추가하지 않는다.

## 부담을 만들지 않는 기준

- 기록함 개수를 위험색, badge dot, 미완료 경고로 표시하지 않는다.
- 앱 시작 때 기록함 정리를 modal로 요구하지 않는다.
- 자동으로 Today에 이동시키거나 날짜 선택을 필수로 만들지 않는다.
- 1개 preview를 넘는 항목은 사용자가 `정리하기`를 선택한 뒤 보여 준다.
- 정리 화면에서는 각 항목에 `오늘로`, 날짜 선택, 내용 확인을 제공하되 한 row에 주요 행동은 하나만 둔다.
- 오래된 기록은 삭제를 압박하지 않고 검색·정리 대상으로 남긴다.

## 반응형·접근성 기준

- 320px와 font scale 1.5에서 제목과 `정리하기`가 겹치면 action을 다음 줄로 자연스럽게 내린다.
- 최신 제목은 한 줄 말줄임이 가능하지만 접근성 label에는 전체 제목과 기록함 상태를 제공한다.
- row는 하나의 button으로 읽고 내부 장식 text가 별도 focus를 받지 않게 한다.
- `방금 기록`은 색상뿐 아니라 문구로 전달한다.
- 저장 성공과 Today 이동 성공은 polite live region으로 알린다.
- Tab focus, Enter·Space 실행과 focus border를 Web에서 캡처 검증한다.

## 검증 근거

- 빠른 등록 성공, composer 종료 후 최신 기록 preview, 하루 정리 분리를 [`UF-02 audit`](../audits/uf-02-today-quick-capture-2026-08-23/README.md)에서 확인했다.
- 320px·font scale 1.5와 native screen reader는 공통 실기기 검증 항목으로 남긴다.
