# 내비게이션·카테고리 정보 구조 제안

Last updated: 2026-08-30

## 결론

모바일의 좌측 상단에 메뉴 버튼을 두고, 현재 `더보기`에 모인 목적지와 목록 탐색을 한곳에 제공하는 방향을 우선 탐색한다. 하단은 매일 반복해서 오가는 `오늘`과 `달력`에 집중하고, 좌측 메뉴는 범위와 도구를 바꾸는 전역 탐색으로 구분한다.

카테고리는 이 메뉴와 잘 맞지만 현재 API의 자유 입력 문자열을 그대로 메뉴 목록으로 만들지는 않는다. 먼저 카테고리의 조회·정렬·이름 변경·삭제 계약과 Workspace 범위를 정한 뒤 추가한다.

## 현재 구조의 문제

- 하단 `더보기`는 독립적인 작업 화면보다 목표·검색·완료 기록·템플릿·공유 공간·설정으로 가는 중간 메뉴에 가깝다.
- 개인 Task의 카테고리는 작성과 검색 필터에는 쓰이지만 지속적으로 탐색할 수 있는 진입점은 없다.
- 공유 공간은 전역 목적지인데 `더보기 → 공유 공간`을 거쳐야 해 반복 사용 시 깊이가 불필요하다.
- 기능이 늘어날수록 `더보기` 화면의 행만 계속 증가해 사용자가 제품의 구조를 한눈에 파악하기 어렵다.

## 제안 구조

```text
좌측 메뉴
├─ 내 작업
│  ├─ 오늘
│  ├─ 달력
│  ├─ 기록함
│  └─ 완료 기록
├─ 카테고리 (계약 준비 후)
│  ├─ 업무
│  ├─ 개인
│  └─ 카테고리 관리
├─ 목표
│  └─ D-Day
├─ 공유 공간
│  └─ 참여 중인 Workspace
└─ 도구와 계정
   ├─ 검색
   ├─ Task 템플릿
   ├─ 계정
   └─ 설정
```

화면 상단의 메뉴 버튼은 `오늘`과 `달력`을 포함한 최상위 화면에서 같은 위치와 동작을 유지한다. 상세·작성 화면은 기존 뒤로 가기 행동을 우선하고 메뉴 버튼을 중복 배치하지 않는다.

## 단계별 적용

### 1단계. 탐색 메뉴 검증

- `오늘` 좌측 상단에 명확한 접근성 라벨이 있는 메뉴 버튼을 둔다.
- 메뉴는 iOS·Android에서 drawer 또는 접근 가능한 modal sheet, 넓은 Web에서는 고정 sidebar로 표현할 수 있다.
- 현재 `더보기`의 목표·검색·완료 기록·템플릿·공유 공간·설정을 메뉴로 옮긴다.
- 하단 `더보기` 제거 여부는 메뉴 발견성, 한 손 조작, 화면 복귀 테스트 후 확정한다. 전환 기간에는 중복 진입을 허용할 수 있다.

### 2단계. 개인 목록과 카테고리

- 기록함을 독립 탐색 목적지로 제공한다.
- 카테고리 목록 API 또는 전체 데이터와 무관한 집계 계약을 마련한다.
- 카테고리별 Task 수, 사용자 지정 순서, 색상, 이름 변경·삭제 시 Task 처리 방식을 정한다.
- `전체`, `카테고리 없음`과 사용자 카테고리의 선택 상태를 메뉴에서 구분한다.

### 3단계. Workspace 범위

- 참여 중인 Workspace를 메뉴에서 바로 연다.
- 개인 카테고리와 Workspace 카테고리를 섞지 않는다.
- Workspace별 카테고리가 필요해질 때 권한, 정렬, 멤버 간 공유 계약을 별도로 정의한다.

## 필요한 API 계약

현재 Task의 `category`는 최대 30자의 nullable 문자열이며 검색 시 정확한 문자열 필터만 지원한다. 안정적인 메뉴를 위해 백엔드 저장소에는 다음 계약을 별도로 제안해야 한다.

- 개인 카테고리 목록과 사용자 지정 순서 조회
- 카테고리 생성·이름 변경·삭제
- 삭제 시 기존 Task를 `카테고리 없음`으로 둘지 다른 카테고리로 이동할지 선택
- 카테고리별 미완료 수 집계
- 이름 중복, 대소문자, 공백 정규화 규칙
- 개인과 Workspace category scope의 분리

전체 Task 검색 결과에서 카테고리를 클라이언트가 역산하는 방식은 cursor pagination과 오래된 Task 때문에 사용하지 않는다.

## UX 검증 기준

- 첫 사용자가 메뉴 도움말 없이 목표·검색·공유 공간·설정을 찾을 수 있다.
- 메뉴를 연 뒤 현재 위치와 선택된 카테고리를 텍스트와 상태로 인식할 수 있다.
- 320dp, font scale 1.5, VoiceOver·TalkBack에서 메뉴 열기·이동·닫기와 focus 복귀가 동작한다.
- Android back, iOS swipe, Web Escape와 browser back의 역할이 충돌하지 않는다.
- 메뉴가 열린 동안 배경 콘텐츠가 스크린리더와 키보드 focus 대상이 되지 않는다.
- 카테고리나 Workspace가 많아도 계정·설정 진입을 가리지 않는다.

## 이번 범위에서 하지 않는 것

- 메뉴 제안만으로 현재 하단 탭을 즉시 제거하지 않는다.
- 자유 입력 `category` 값을 로컬에서 수집해 영구 카테고리 목록처럼 취급하지 않는다.
- 개인 카테고리 계약을 Workspace에 자동으로 확대하지 않는다.
