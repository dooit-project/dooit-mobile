# 내비게이션·카테고리 정보 구조 결정

Last updated: 2026-10-17

2026-10-13 이후 [화면 필요성·위치 재검토](./PRODUCT_ARCHITECTURE_REVIEW_2026-10-13.md)와 후속 사용자 선택을 반영해 핵심 네 탭을 코드에 적용했다. 아래는 코드 기준 현재 구조이며 실제 검증은 사용자 요청으로 보류 상태다. [메뉴 구조 세 시안](../design/menu-navigation-2026-10-17/README.md) 중 추천 2번 진행을 승인받아 보조 메뉴 정리도 코드에 반영했다.

## 현재 구현

하단 탭은 `오늘·달력·계획·돌아보기`다. `/profile`은 숨김 route로 남기고 좌측 메뉴의 계정에서 접근한다. 좌측 메뉴는 보조 기능만 제공하며 기록함 행 다음에 개인 카테고리 접이식 목록을 둔다. 상세 화면의 화면 내 뒤로가기는 이동 기록이 있으면 이전 화면, 없으면 오늘(공유 공간 상세는 목록)을 대체 목적지로 사용한다. 신규 작성도 이미 이동 기록이 없는 경우의 복귀를 지원한다.

- 첫 행: 검색
- 기록 정리: 기록함, 카테고리, 오래 미룬 일, 날짜별 완료 기록
- 도구: 할 일 템플릿, 공유 공간
- 내 계정: 계정, 설정
- 개인 카테고리: 전체·이름 있는 카테고리는 검색으로 이동하며 이름은 exact-match 필터를 사용한다. 미분류는 서버 검색 필터가 없어 count만 표시한다.

개인 요약은 `GET /api/v1/tasks/categories`에서 조회한다. 카테고리 관리 entity나 Workspace 집계로 취급하지 않는다. 이름 변경·삭제·정렬·색상 관리, Workspace별 바로가기 확장은 현재 구현 범위가 아니다.

## 판단 근거

목적지 탐색을 좌측 메뉴에서 제공하고, 날짜 없는 기록과 오래 미룬 일에 직접 접근할 수 있게 했다. 카테고리는 목록을 항상 펼치지 않고 달력 아래에서 필요한 때 확장한다.

- [카테고리 선택안과 구현 audit](../audits/task-categories-2026-09-06/README.md)
- [핵심 화면 Web 반응형 audit](../audits/responsive-core-2026-09-09/README.md)

남은 native 접근성·기기 검증은 [로드맵](./ROADMAP.md)에서 관리한다.

## 선택한 메뉴 정리안

큰 메뉴 제목·아이콘 배경·중복 목적지 개선은 [2026-10-17 시각 비교](../design/menu-navigation-2026-10-17/README.md)의 2번으로 코드에 반영하고 `19fb0b8`로 커밋했다(미검증). 오늘·달력·목표의 중복 메뉴 행만 제거하고 기존 `/dday`, `/completed`는 유지한다. 목표별 주간 회고와 날짜별 완료 취소는 역할이 달라 일괄 통합하지 않는다. [계정 화면 세 시안](../design/account-focus-2026-10-17/README.md)의 추천 1번 진행 승인 후 계정의 중복 작업 도구를 제거하고 계정 상태·보관 안내·로그인/로그아웃·설정 한 행으로 정리했다(미커밋·미검증). 도구의 대체 메뉴·하단 탭과 기존 route는 유지한다.

## 필요한 API 계약

현재 Task의 `category`는 최대 30자의 nullable 문자열이며 검색 시 정확한 문자열 필터를 사용한다. 개인 메뉴 조회에는 집계 API를 사용하고, 관리 기능을 승인할 때만 다음 계약을 백엔드에 요청한다.

- 카테고리 생성·이름 변경·삭제
- 삭제 시 기존 Task를 `카테고리 없음`으로 둘지 다른 카테고리로 이동할지 선택
- 사용자 지정 순서와 색상
- 이름 중복, 대소문자, 공백 정규화 규칙
- 개인과 Workspace category scope의 분리

전체 Task 검색 결과에서 카테고리를 클라이언트가 역산하는 방식은 cursor pagination과 오래된 Task 때문에 사용하지 않는다.

## UX 검증 기준

- 첫 사용자가 메뉴 도움말 없이 목표·검색·공유 공간·설정을 찾을 수 있다.
- 메뉴를 연 뒤 현재 위치와 선택된 카테고리를 텍스트와 상태로 인식할 수 있다.
- 320dp, font scale 1.5, VoiceOver·TalkBack에서 메뉴 열기·이동·닫기와 focus 복귀가 동작한다.
- Android back, iOS swipe, Web Escape와 browser back의 역할이 충돌하지 않는다.
- 메뉴가 열린 동안 배경 콘텐츠가 스크린리더와 키보드 focus 대상이 되지 않는다.
- 카테고리나 Workspace가 많아도 계정·설정 진입을 가리지 않는다.

## 이번 범위에서 하지 않는 것

- 메뉴 제안만으로 현재 하단 탭을 즉시 제거하지 않는다.
- 전체 Task를 페이지 끝까지 조회해 category 목록을 클라이언트에서 역산하지 않는다.
- 개인 카테고리 계약을 Workspace에 자동으로 확대하지 않는다.
