## 전반 UI·UX 개선 — Today 재탐색 1번 구현 중

계획의 최신 기준은 [목표별 가로 탭 최종안](../design/plan-navigation-2026-10-15/README.md)이다. 목표 전환·전체 목록·간결한 연결 항목·상단 간격을 먼저 코드에 반영했다(미검증). 다음은 통합 항목 추가, 반복 정의 단위 목록, 목표·항목 순서 관리와 저장 계약이며 기존 API의 지원 범위를 구분해 진행한다.

후속으로 계획의 `항목 추가`에서 기존 TaskForm을 재사용하고 선택 목표 자동 연결과 연결 실패 시 같은 항목의 재시도를 구현 중이다(미검증). 현재 반복은 기존 반복 일정 범위이며 시간 없는 반복 TODO·반복 시리즈 전체의 목표 연결은 계약 확인이 필요하다. 상세 범위와 미완료 항목은 최신 계획 문서에서 관리한다.

목표 연결 작성 단계는 `6635c3f`로 커밋했다. 다음으로 수신한 반복 회차를 서버 묶음 ID·규칙 단위로 요약하고 개별 예외는 남기는 계획 목록 표시를 코드에 반영했다(미검증). 서버 반복 정의의 전체 목록을 제공하는 단계는 아직 아니다.

반복 목록 단계는 `d825081`로 커밋했다. 2026-10-16 후속으로 전체 목표 제목 검색, 생성 후 자동 선택, 계정·API 환경별 로컬 선택 복원과 선택 탭 위치 이동을 코드에 반영했다(미커밋·미검증). 다음은 목표·항목 순서 관리와 서버 저장 계약이며 시간 없는 반복 TODO·서버 반복 정의 목록도 아직 남아 있다.

검색·선택 복원은 `5e4cfe8`로 커밋했다. 다음으로 전체 목표의 순서 편집(드래그·위/아래·되돌리기·취소·완료)과 계정/API 환경별 임시 로컬 저장을 코드에 반영했다(미커밋·미검증). 기기 간 동기화와 목표 안 항목 순서는 아직 지원하지 않는다. [백엔드 변경 요청서 G-06](../api/API_GOAL_JOURNEY_CHANGE_REQUEST.md)의 순서 저장/안정적 항목 ID 요구는 새로 추가했으며 미전달 상태다.

목표 순서 편집은 `1a6ddec`로 커밋했다. 이어서 목표의 `··· → 순서 바꾸기`에서 할 일·일정·반복 묶음·예외의 혼합 순서를 편집하고 완료 시 목표별 로컬에 저장하는 흐름을 반영했다(미커밋·미검증). 서버 동기화는 아직 지원하지 않으며 임시 표시 키의 서버 ID 이전은 G-06 회신 후 진행한다.

항목 순서 편집은 `a1f31ca`로 커밋했다. 후속으로 목표 작성 날짜의 빠른 선택(1·3·6개월 후), 숫자 입력/자동 구분선과 날짜·요일 안내를 반영했다(미커밋·미검증). 목표 생성/색상 저장 중 입력을 잠가 중복 제출을 방지하며 기존 서버 필수 목표일 계약은 유지한다.

날짜 입력은 `b7dd520`로 커밋했다. 후속으로 [상단 동기부여 문구](./MOTIVATIONAL_COPY.md)의 자체 문장 13개·출처 확인 명언 2개, 수동 교체와 새날/4시간 이후 재방문 순환을 코드에 반영했다(미커밋·미검증). 현재 최근 7개 회피는 메모리 범위이며 계정별 영속 이력·숨기기/덜 보기·전체 문장/출처 상세는 아직 없다.

초기 문구/순환은 `b174172`로 커밋했다. 이어서 설정의 기본·덜 보기·숨기기, 계정/API 환경별 노출 이력 저장·복원과 헤더 동기 반영, 전체 명언/원문 출처 펼침을 반영했다(미커밋·미검증). 문구 데이터는 이 기기 범위이며 실제 기록을 평가하거나 AI 요약을 만드는 기능은 아니다.

문구 설정/영속 이력은 `b1915a1`로 커밋했다. 다음 돌아보기 단계는 기존 날짜별 완료 Task를 목표에 대한 실제 행동의 증거로 보여주는 구조다. [2026-10-16 시안 세 개](../design/review-evidence-2026-10-16/README.md)를 비교했으며 목표별 증거 목록(1번)을 추천한다. 사용자 선택 전 화면 코드 구현은 하지 않았고 실제 화면 감사/테스트 보류도 유지한다.

돌아보기 시안·문서는 `e57202e`로 커밋했다. 2026-10-17 후속 진행 지시를 추천 1번 진행으로 해석해 알린 뒤, 돌아보기 탭의 주간 이동·목표별 완료 제목/날짜·기록 수/날짜 수·미연결 기록·20개씩 더 보기·상세 이동·조회 오류/재시도·빈 상태를 코드에 반영했다(미커밋·미검증). 기존 날짜별 완료 API를 재사용하며 동일 Task ID 중복만 제외한다. 전체 목표 여정·별도 실천/직접 완료 기록 통합·완료 당시 목표 스냅샷은 백엔드 계약 확인이 남아 있다. 다음은 기존 탐색의 drawer/더보기 중복과 용어·진입 정리다. 검증 보류는 유지한다.

목표별 주간 기록은 `ce0c007`로 커밋했다. 이어서 [메뉴 진입·탐색 문구 정리](../design/NAVIGATION_CONSISTENCY_2026-10-17.md)에서 누락된 계정 링크, 기록함/오래 미룬 일의 경로+focus 선택 표시, 이전 화면 안내와 오늘·템플릿·날짜별 완료 기록 용어를 코드에 반영했다. 메뉴 정리는 `5da730c`로 커밋했으며 검증은 보류했다. 기존 메뉴 구조와 경로를 유지하는 복구 단계로 메뉴/계정 도구 중복 정리 전체가 완료된 것은 아니다.

후속으로 화면 내 뒤로가기 버튼에 공통 `canGoBack` 분기를 연결해 `76e7d51`로 커밋했다(미검증). 이동 기록이 있으면 이전 화면으로, 없으면 오늘로 이동하며 공유 공간 상세의 대체 목적지는 공유 공간 목록이다. 설정·검색·완료 기록·목표·템플릿·오늘 보조 화면·할 일 상세 등에 적용하고 접근성 이름도 목적지에 맞췄다. 시스템/브라우저 뒤로가기를 새로 제어하지 않는다.

다음 [메뉴 시안 세 개](../design/menu-navigation-2026-10-17/README.md)는 큰 헤더·행 밀도·중복 목적지를 비교한다. 2번 보조 기능 직접 목록을 추천하며 사용자 선택 전 화면 코드는 변경하지 않았다. 시안·비교·공식 자료 근거·기존 route 보존과 계정 도구 목록의 후속 범위를 문서화했다(미커밋). 실제 감사·테스트 보류를 유지한다. 오래된 탐색 결정 문서의 하단 3탭 설명도 현재 코드의 네 탭과 계정 메뉴 진입으로 갱신했다.

[화면 필요성·위치 재검토](./PRODUCT_ARCHITECTURE_REVIEW_2026-10-13.md)와 [10개 실제 화면 감사](../audits/product-architecture-2026-10-12/README.md)를 기준으로 진행한다. 사용자는 후속 비교에서 [운영 앱 참고 재탐색 1번](../design/to-be-2026-10-14/TODAY_REFERENCE_INSPIRED_OPTIONS.md)을 선택했다. 목표별 편집 목록, 단일 추가 메뉴, 네 개 하단 탭, 작은 순환 문구와 목표 색상 선택을 먼저 구현한다.

- [ ] U2. 선택한 tab·header·Today 목록·작성 진입과 [계획 탭 선택안](../design/to-be-2026-10-15/README.md)의 실제 화면 감사를 진행하고 세부 밀도를 보정한다. 목표 색상은 서버 계약 전 로컬에 저장하며 이후 계정 동기화 값으로 이전한다. drawer/더보기 중복을 정리하되 기존 목적지·deep link·계정 범위를 보존한다.

## 신규 제품 방향: 목표·여러 실행 계획·실천 여정·동기부여

2026-10-13 구체화한 [목표·실행 계획·지나온 길](./GOAL_JOURNEY_EXPERIENCE.md)이 최신 범위다. 기존 단일 시스템 제한을 대체하며 목표 하나에 여러 반복 계획·일회성 노력·이미 한 일 기록을 포함한다. 현재 출시 검증과 구분하며 아직 구현하지 않았다. 상세 프론트 작업은 [제품 제안](./PERSONAL_SYSTEM_EXPERIENCE.md), 이미 전달한 백엔드 요청의 수정은 2026-10-13 전달한 [목표 중심 변경 요청서](../api/API_GOAL_JOURNEY_CHANGE_REQUEST.md)에서 관리한다.

- [ ] S1. 전달한 [목표 중심 변경 요청서](../api/API_GOAL_JOURNEY_CHANGE_REQUEST.md)를 기준으로 Goal·기존 D-Day 이행·목표 아래 여러 반복 계획·일회성 Task/완료 기록·여정 조회 계약 회신을 받고 확정한다. 기존 요청서의 단일 시스템 제한은 최신 요구와 다르다. 일상 반복 보충 항목도 이 변경 요청에 포함했다.
- [ ] S2. 기존 탐색/스타일 조합과 실행 sheet 선택을 유지하고 목표 생성·상세·계획 작성·추가 노력·전체 기간 여정을 시각 검토한다. 의미 있는 신규 화면 선택지는 비교 후 구현한다.
- [ ] S3. 목표 하나→독립 반복 계획 두 개 이상→기본/최소 실천→추가 Task 완료→이미 한 일 기록→목표별 여정→조정/달성 확인 흐름을 구현한다. 수정/취소·중복 집계·과거 보존 포함. 백엔드 구현은 별도 저장소에서 진행한다.
- [ ] S4. AI 초안·주간 요약과 직접 입력·정형 요약 대체 경로를 연결한다. 조정 AI는 핵심 루프 이후 연결할 수 있다.
- [ ] S5. 정적 응원·출처 확인 명언·잠깐 쉬어가기, 노출 빈도·덜 보기와 로컬 알림을 연결한다. 새 날/4시간 이후 재방문 교체·다른 문장·최근 중복 방지 정책은 일상 행동 점검 문서의 제안을 검토한다. 문구 CMS·서버 push는 제외한다.
- [ ] S6. 실제 화면 감사·Android/iOS/Web·real API 검증과 `npm run validate` 결과를 기록한다.

## 추가 기능 후보

- 완료·날짜 이동 실행 취소: 단일 action부터 원래 상태 복원과 실패 처리 범위를 정한다.
- 카테고리 입력 제안: 기존 개인 summary를 활용하며 CRUD 확대와 분리한다.
- 개인 데이터 내보내기: 장기 사용 수요 확인 뒤 범위·형식·pagination 계약을 정의한다.
- 계정 삭제: iOS Store 준비 시 backend 데이터 삭제·Workspace 소유권·세션 폐기와 함께 설계한다.

선택안과 수용 기준은 [제품 검토](./PRODUCT_REVIEW_2026-09-14.md)에 연결한다. 후보 추가가 구현 승인을 뜻하지 않는다.

## 조건 충족 후 진행

- 미분류 목록 탐색: null-category 검색 계약이 준비된 뒤 활성화한다. 현재 요약 count와 이름 있는 카테고리 탐색은 구현됐다.
- 카테고리 CRUD·정렬: 관리 UX와 삭제 정책을 결정한 뒤 계약을 요청한다.
- 계획·마감 atomic batch: 단건 처리의 부분 실패가 실제로 반복될 때 요청한다.
- 공유 메뉴·iOS widget: 별도 native build에서 인증 bootstrap·cold start·취소·재시도를 검증한 뒤 출시 포함 여부를 결정한다.
- 서버 push: token lifecycle·발송 멱등성·local suppression 검증과 활성화 승인을 거친다.

추가 기능 후보와 제외 범위는 [PRD](./PRD.md), Store·OTA 승격 조건은 [배포 범위 정책](./RELEASE_SCOPE_POLICY.md)를 따른다.
