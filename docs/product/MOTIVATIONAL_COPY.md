# 상단 동기부여 문구와 출처

작성: 2026-10-16 · 코드 반영, 미커밋·미검증

## 제품 기준

사용자가 선택한 위치는 dooit 로고 옆의 작은 문구다. 큰 카드·자동 팝업·실천 완료 때마다 바뀌는 문장을 추가하지 않는다. 사용자의 바람을 존중하고 시작하기 쉬운 행동·실천 기록·다시 돌아오기를 이야기한다. 휴식이나 빠진 날을 실패로 취급하지 않으며 기록 없는 성과·노력·감정을 단정하지 않는다.

## 콘텐츠 원본

[문구 목록](../../src/features/motivation/motivational-lines.ts)에 자체 문장 13개와 출처 확인 명언 2개를 둔다. 자체 문장은 인물 이름을 붙이지 않는다. 명언 항목은 저자·원문 발췌·출처 URL·위치·확인일을 필수로 가진다. 한국어는 원문 일부의 짧은 직접 의역이며 현대 한국어 번역을 복사한 문장이 아니다. UI에서도 저자와 `의역`을 표시한다.

온라인에서 인물 이름만 붙여 퍼지는 출처 미확인 문장은 넣지 않는다. 사용자가 예로 제시한 `내일은 그냥 오지 않는다`는 인용 출처를 확인하지 않았으므로 유명인 명언이나 dooit 자체 창작으로 편입하지 않았다. 새 인물 문구를 추가할 때도 출처·원문 위치·번역 범위를 함께 기록한다.

## 교체 동작

- 첫 노출은 기기의 현지 날짜에 따라 정한 문장을 사용한다.
- 새 날 또는 마지막 교체 후 4시간이 지난 상태에서 앱/브라우저로 복귀하거나 경로를 이동하면 다음 문장으로 바꾼다.
- 화면을 계속 보고 있을 때는 타이머로 바꾸지 않는다. 재렌더와 완료 체크만으로 교체하지 않는다.
- 문구 옆 작은 교체 아이콘과 전체 44 이상 터치 영역을 제공한다. 누르면 다른 문장을 볼 수 있다.
- 같은 헤더가 유지되는 동안 최근 7개를 피한다. 단순히 문구를 바꾸기 위해 서버나 AI를 호출하지 않는다.
- 긴 문장은 한 줄로 말줄임하며 접근성 이름에는 전체 문장을 제공한다. 인물 문구에는 저자와 의역 여부도 읽어준다.

현재 노출 시각·최근 목록은 메모리에만 있다. 앱 재시작/헤더 재마운트 후 노출 이력은 복원하지 않는다. 날짜 초기값이 같으면 같은 문장이 다시 보일 수 있다. 계정별 영속 이력과 숨기기·덜 보기 설정, 앱 안 전체 문장/출처 상세 표시는 후속 작업이다. 이번 단계는 실제 기록 기반 주간 피드백이나 반복 실천 기능의 구현을 대신하지 않는다.

## Product Design 검토 기록

- 대상/목적: 실행 화면을 밀어내지 않으면서 작은 행동과 바람을 지지하는 문장을 가끔 보여준다.
- 근거: 기존 작은 상단 헤더, 선택된 최종 시안의 문구 위치, [일상 반복 점검의 노출 제안](./DAILY_SYSTEM_FIT_REVIEW_2026-10-13.md)과 출처 원문을 확인했다. 기존 Product Design의 시각 위계·방해 최소화·발견 가능성 기준을 적용했다. 새 Figma·실제 앱 캡처 검토는 아니다.
- 유지/변경: 헤더 기본 높이 52와 한 줄 문구를 유지하고, 교체 조작과 명언 저자 한 줄을 추가한다. 명언에는 저자 줄이 있으므로 실제 좁은 화면/글자 확대에서 밀도 확인이 남아 있다.
- 접근성: 문구 교체는 버튼 역할·전체 문장·힌트·눌림 반응을 제공한다. 새 문장은 강제 live announcement로 읽는 중간에 끼어들지 않는다.
- 플랫폼: Android·iOS·Web. 기존 AppState를 사용하며 설치된 React Native Web의 visibilitychange 연결을 소스에서 확인했다. 실제 복귀·키보드·터치·스크린리더 동작을 테스트한 것은 아니다.
- 검증: 사용자 요청으로 `npm run validate`와 실제 화면 감사를 보류했다. 새 의존성·API 계약 변경은 없다.
