# AI 비활성·사용 제한 상태 — F1c-3

2026-10-18 · `e54da65` 커밋, 미검증

후속 [F2a 계획 탭의 새 Goal 연결](../design/GOAL_PLAN_CONNECTION_2026-10-19.md)에서 목표 목록·작성/상태 관리 화면을 연결했다. AI 자동 활성화·AI 화면/hook은 여전히 후속이다.

[일회성 Task·여정 집계](./GOAL_JOURNEY_MOCK_2026-10-18.md)는 `f268a95`로 커밋했다. GoalDraft controller/DTO·AI service·공통 오류/CORS 설정을 읽고 선택적 AI 통신과 오류 상태를 준비했다. Android/iOS/Web 공통 코드이며 새 의존성·화면 변경·외부 제공자 연결은 없다.

## 추가한 범위

- `src/types/goal-ai.ts`: 목표 초안, 사용자 일정 기반 계획 초안, 선택 계획 조정안, 기록 근거 여정 요약 DTO. 초안은 저장하지 않은 제안이며 채택 시 별도 Goal/Plan 저장 API가 필요하다.
- `goal-ai-api.ts`: 네 개 POST wrapper. 호출 함수만 준비했으며 실제 화면/hook·자동 실행·자동 저장·timeout 재시도 허용 목록은 추가하지 않았다.
- `goal-ai-error.ts`: 503/70009 비활성, 429/70010 사용 제한, 409/70008 원본 여정 변경, 취소와 일반 오류를 분리한다. 같은 HTTP 상태라도 다른 오류 코드는 AI 전용 상태로 바꾸지 않는다.
- 공통 ApiClientError에 선택적 retryAt(UTC epoch milliseconds)을 추가했다. HTTP 오류의 읽을 수 있는 Retry-After를 초 또는 HTTP date로 해석한다. 헤더 누락/숨김/잘못된 값은 대기 시간 미상이다. 임의 기본 시간을 넣거나 429를 자동 재시도하지 않는다. 날짜는 응답 오류를 만들 때 고정되며 화면 재렌더링마다 연장하지 않는다.
- mock의 네 AI 경로는 기본 503/70009다. 목표·계획 소유권/연결을 확인하고 가짜 AI 문장·성과·요약이나 새 데이터를 만들지 않는다. mock은 제공자·실제 rate limiter·전체 Bean validation을 모사하지 않는다.

## 화면 연결 시 유지할 동작

AI가 비활성/실패해도 입력 내용과 수동 저장 경로를 유지한다. 목표/계획 제안에는 직접 작성, 여정 요약에는 원본 기록 조회를 대안으로 안내한다. 취소는 오류 안내를 강제하지 않는다. 사용 제한 시 알려진 retryAt은 참고하되 헤더가 없으면 카운트다운/해제 시각을 추측하지 않는다. 원본 여정 변경은 최신 기록을 다시 확인한 뒤 사용자 요청으로 요약한다.

목표/계획을 AI 초안 응답만으로 저장하거나 기존 계획의 일정·상태를 바꾸지 않는다. 여정 요약은 전체 집계·서버 overview와 반환된 highlights 원본을 사용하고 기록에 없는 성과/감정을 보태지 않는다. summary 요청은 1~366일, 원본 근거는 최신 최대 100건·highlight 최대 5건이라는 서버 계약을 유지한다. 수동 여정 조회 자체에는 366일/31일 제한을 임의로 적용하지 않는다.

## 백엔드 후속 — Web Retry-After 노출

확인한 로컬 `CorsConfig`는 exposedHeaders에 Idempotency-Replayed만 등록되어 있다. Retry-After는 실제 응답에 있어도 Web JavaScript에서 읽지 못할 수 있다. [추가 요청](../api/API_GOAL_JOURNEY_CHANGE_REQUEST.md)에 Retry-After 노출 확인을 문서화했다. **아직 전달·배포 확인하지 않았으며 운영 호출도 하지 않았다.** 모바일은 헤더를 읽지 못해도 사용 제한 상태를 표시할 수 있도록 모델링했다.

## 잔여와 검증 상태

F1의 타입/API/mock 기반은 코드 반영 단계이며 실제 기능 화면 완료가 아니다. 다음은 F2의 선택된 계획 UI와 새 Goal API 연결이다. D-Day ID·색상·로컬 순서 보존과 명시적 Goal 대응을 먼저 정하고 자동 데이터 이관은 하지 않는다. AI 제공자·보관/삭제 정책·활성화와 화면/hook/저장 시도 관리는 여전히 후속이다.

비활성/일반 장애 구분, 수동/원본 대안, 사용 제한과 미상 시간, 고정 대기 시각·Retry-After 파싱/HTTP 전송·자동 재시도 없음, 취소·여정 변경, mock AI 실패 후 수동 CRUD/원본 조회 보존의 회귀 사례를 작성했다. 사용자 요청대로 테스트·`npm run validate`·실제 화면 감사·운영 호출은 실행하지 않았다. 포맷만 적용했으며 통과로 기록하지 않는다.
