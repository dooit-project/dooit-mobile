# 오늘 회차 실행 연결 기반 — F3a-1

2026-10-20 구현 · 2026-10-21 커밋 준비/검증 완료 · Android/iOS/Web 공통 · 새 의존성 없음

반복 계획 관리는 `e805059`로 커밋했다. 다음 작업을 조회·상태 변경 기반(F3a-1)과 실제 오늘 화면 연결(F3a-2)로 나눈다. 이 단계의 hook과 분리 함수는 아직 화면에서 호출하지 않는다. 사용자가 반복 계획을 만들었다고 오늘에 자동 표시되거나 새 알림이 예약되는 상태는 아니다.

## 이번 범위

- `useTodayGoalOccurrences`: 오늘 하루만 회차 API에 요청한다. GET이 연결 Task를 생성·변경할 수 있으므로 완료 후 Task·일일 계획 캐시를 갱신한다. 계정이 바뀌거나 로그아웃·요청 취소되면 다른 세션 캐시를 무효화하지 않는다. 인증 전환 시 query 취소/초기화는 기존 auth provider가 담당한다.
- `useChangeGoalOccurrence`: 명시적 결과 저장·결과 취소·휴식·휴식 취소를 전용 API에 보낸다. 화면에서 본 occurrenceVersion을 유지하고 결과 요청의 STANDARD/MINIMUM/UNKNOWN·실제 기록 시각/시간대·다음 행동 patch를 추론해 바꾸지 않는다. 자동 mutation 재시도는 끈다.
- 성공/실패 후 회차를 먼저 갱신하고 Task·일일 계획·여정 캐시를 갱신한다. timeout 후 실제 반영 가능성과 409 충돌을 고려한 재조회이며, 실패한 저장을 몰래 다시 보내지 않는다. stale version의 덮어쓰기나 휴식/완료의 자동 상호 취소도 하지 않는다.
- `separateTodayGoalItems`: 같은 날짜 회차의 linkedTaskId만 일반 Task 목록에서 제외한다. 중복 회차는 최신 version을 보존한다. 완료·휴식 회차도 취소 경로를 위해 남기며 연결 Task가 없는 회차/독립 계획도 버리지 않는다. 조회 불가(undefined)와 정상 빈 결과([])를 구분한다.

## 검증

`npm run validate` 통과: 타입·린트·포맷·문서/캡처 최신성·출시 정적 검사, 112 suites / 583 tests 통과. STG integration 1개는 기본 실행에서 제외된다. 새 9개 사례는 구체화 뒤 캐시 갱신 순서, 계정 전환/로그아웃/취소 후 격리, 명시적 최소 행동과 기록 시간대 유지, 전용 취소 경로, 충돌 비재시도, 날짜/버전 중복 제거와 조회 불가를 다룬다.

화면·정보 구조는 바꾸지 않은 내부 조회/상태 변경 기반이므로 이 단계에 신규 시안이나 별도 화면 감사는 없다. 실제 기존 화면 확인은 [F2b-1 감사](../audits/goal-plan-2026-10-20/README.md)이며 F3a UI 통과 근거로 사용하지 않는다. native/운영 API, hook의 실제 mounted 화면 경쟁 상태는 미검증이다.

## 다음 F3a-2

선택된 오늘 목표 묶음/간결한 체크 행에 hook과 분리 함수를 연결한다. 새 Goal과 기존 D-Day의 ID/색상 namespace를 구분하고 linkedGoalId 일회성 항목도 올바른 목표 아래 놓는다. 단순 체크는 실제로 확인한 수준만 기록하고, 작은 행동 선택·휴식·결과 취소를 맥락 메뉴로 연결한다. 조회 실패·중복 제출·409 재조회와 입력 보존을 화면에서 확인한다. 기존 Task 상세/완료/재개 경로의 회차·여정 캐시 갱신도 이 단계에 포함한다. 완료 후 실제 Web 감사와 플랫폼 한계를 기록한다. native 회차 알림 예약은 별도 후속이다.
