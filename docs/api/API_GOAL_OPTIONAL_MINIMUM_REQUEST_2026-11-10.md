# 백엔드 확인 요청 초안: 선택적 작은 행동과 오늘 표시

작성일: 2026-11-10

상태: **초안 · 미전달 · 미합의 · 운영 배포 미확인**

기존에 전달된 개인 시스템·목표 요청을 대체하지 않는 추가 확인입니다. 사용자에게 전달을 요청하거나 백엔드에 보낼 때 이 문서를 그대로 사용할 수 있습니다.

## 배경

사용자는 목표 아래 ‘매일 영단어 30개 외우기’처럼 지속 가능한 기본 행동을 설정합니다. 힘든 날을 위한 ‘영단어 3개 읽기’는 원하는 경우에만 추가합니다. 작은 행동이 없는 반복 계획도 만들 수 있어야 합니다. 기본 상태의 체크는 한 번이며, 작은 행동 전환은 완료 자체가 아닙니다.

모바일에서 읽은 로컬 백엔드 `8d11333` 기준으로 Goal Plan 생성·수정 DTO의 `minimumAction`은 `@NotNull`이고 계획 버전의 최소 행동 텍스트도 non-null입니다. 또한 `GoalOccurrenceTaskLinkService.syncPendingTask`는 다음 행동이 없으면 연결 Task 제목에 최소 행동을 사용합니다. 이 확인은 코드 읽기이며 운영 버전 확인이나 API 호출이 아닙니다.

## 확인·요청 사항

1. **작은 행동 없는 계획:** `POST /api/v1/goals/{goalId}/plans`, `POST /api/v1/goal-plans`, `PATCH /api/v1/goal-plans/{planId}`의 `minimumAction` 생략 또는 `null`을 허용할 수 있는지, 기존 클라이언트와 호환되는 생성·수정·조회 계약을 제안해 주세요. 기본 행동을 임의의 작은 행동으로 복사하면 ‘대안 없음’과 ‘같은 대안 입력’을 구별할 수 없으므로 표현 방식을 명시해 주세요.
2. **버전·회차 스냅샷:** 대안이 없는 계획의 Goal Plan 버전 및 회차에서 `minimumAction`과 `snapshotMinimumActionText`가 어떻게 표현되는지 알려 주세요. 이후 대안 추가·삭제와 미래 적용일을 처리할 때 과거 스냅샷과 완료 기록은 보존되어야 합니다.
3. **연결 Task 기본 제목:** 별도 선택 전에는 `snapshotNextAction`이 있으면 그 의미를 보존하고, 그렇지 않으면 사용자가 정한 기본 행동이 표시되도록 Task 동기화 정책을 확인해 주세요. 제목이 오늘·상세·달력에 어떻게 반영되고 기존 생성 Task가 언제 갱신되는지도 확인 부탁드립니다. 모바일의 화면 표시만 바꿔 다른 화면이나 기록과 달라지지 않게 조율하려 합니다.
4. **오늘만 대안 선택:** 사용자가 완료 전에 작은 행동으로 바꾸고 복귀하는 상태를 서버에 보관할 수 있는지, 없다면 저장 범위와 재접속·기기 간 동기화 정책을 협의하고 싶습니다. 선택만으로 실천 완료 결과를 생성하지 않습니다. 다음 회차와 계획 원본은 바뀌지 않아야 합니다.
5. **완료·취소 일관성:** 사용자가 실제 확인한 기본/작은 행동을 회차 결과로 기록할 때 연결 Task 완료와 취소, 버전 충돌, 중복 요청, 여정 조회가 일관되게 동작하는 계약을 확인해 주세요. 대안이 없는 회차에서 `MINIMUM` 결과를 요청하면 어떻게 처리할지도 명시해 주세요. 기존 일반 Task 체크로 생성된 `UNKNOWN`을 임의로 기본/작은 행동으로 바꾸지 않습니다.
6. **출시 호환:** 응답 필드 nullability 변경에 따른 기존 모바일·Web 클라이언트 영향, DB migration 및 배포 순서, 오류 코드, 운영 적용 여부를 회신해 주세요. 제안이 기존 앱과 호환되지 않으면 버전 분리 또는 단계적 배포 방안도 함께 부탁드립니다.

## 확인하고 싶은 사례

- 작은 행동 없이 기본 행동만 가진 계획을 생성·조회·수정하고 다음 회차를 생성한다.
- 작은 행동이 있는 계획에서 기본 행동과 작은 행동을 각각 명시적으로 완료·취소한다. 하루의 전환은 다음 날에 남지 않는다.
- 다음 행동이 있을 때 그 문장과 기본/작은 행동의 관계가 유지되고, 연결 Task와 목표 여정의 내용이 서로 모순되지 않는다.
- 대안을 추가·삭제한 뒤에도 이전 회차의 행동과 결과가 보존된다.
- 기존 UNKNOWN 기록, 이전 클라이언트, 같은 회차 동시 수정과 중복 재시도에서 데이터가 손실되거나 추정되지 않는다.

구체적인 요청·응답 구조와 오류 코드는 백엔드와 합의 전이며, 이 초안은 구현이나 전달 완료를 의미하지 않습니다.
