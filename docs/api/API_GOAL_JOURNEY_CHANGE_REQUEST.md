# 목표 중심 계획·실천 여정 — 백엔드 변경 요청서

작성: 2026-10-13 · 전달 상태: 사용자 확인으로 백엔드 담당자에게 전달 완료 · 회신·계약 합의·구현·배포 미확인 · 기존 2026-10-12 요청의 범위 수정

## 기존 요청에서 달라진 핵심

기존 [개인 시스템 요청서](./API_PERSONAL_SYSTEMS_REQUEST.md)는 이미 전달됐습니다. 사용자 요구를 구체화하면서 첫 버전의 중심을 **목표 하나 → 여러 반복 계획 + 일회성 행동 → 목표별 실천 여정**으로 수정합니다. 기존 요청의 개인 시스템 하나 제한·복수 시스템 제외를 이 변경 요청으로 대체합니다. 한 반복 회차의 유효 결과 하나라는 중복 방지 원칙은 유지하되 목표에 별도의 일회성 노력은 여러 개 추가할 수 있어야 합니다.

예: 토익 900점, 목표일 2026-11-30 → 매일 단어 30개 + 선택한 주말 요일 문제 5개 → 오늘 추가로 문제 30개 풀기 → 목표별로 실제 해온 과정을 조회. 날짜와 분량은 사용자 입력 예시입니다.

## G-01. 목표 모델·기존 D-Day 재사용

- 목표 이름, 선택적인 원하는 결과/이유, 선택 목표일, 상태(진행/일시정지/달성/보관 제안), 생성·수정/버전이 필요합니다. 날짜는 쉽게 입력하되 미정도 허용합니다.
- 날짜·설명 수정과 사용자 확인에 의한 달성 기록이 필요합니다. 기한 도래·행동 완료 수로 자동 달성/실패 처리하지 않습니다. 복잡한 지표 엔진은 요청하지 않습니다.
- 기존 D-Day의 필수 targetDate를 확장할지, 별도 Goal과 매핑할지 제안 부탁드립니다. 기존 목표 ID·Task 연결·날짜·알림/deep link·완료 기록을 보존해야 합니다.
- 목표 달성/보관 시 미래 계획을 멈출지 유지할지 명시적 정책과 선택이 필요합니다. 과거 실천은 보존합니다. 기존 복수 목표를 하나로 줄이거나 삭제하지 않습니다.

## G-02. 목표 아래 여러 반복 계획

- Goal 1:N 실행 계획, 실행 계획 1:N 회차를 지원합니다. 목표 없는 독립 반복 행동도 기존 사용 범위와 충돌하지 않게 유지합니다.
- 계획마다 이름·주기·기준일/시간대·선택 시작 시각/상황·선택 알림·기본/최소 행동·선택 다음 행동·상태/버전을 둡니다. 단어와 문제풀이를 각각 수정/정지/재개할 수 있어야 합니다.
- 시작 시각 없는 매일·선택 요일 반복을 지원하고, 일반 일정 startAt을 불필요하게 강제하지 않습니다. 기존 [일상 반복 확인 항목](./API_PERSONAL_SYSTEMS_DAILY_CLARIFICATION.md)의 시간/알림/요일/nextAction 정책도 함께 확인해 주세요.
- 목표와 반복 계획의 연결이 회차에도 반영되어야 합니다. 연결 변경은 미래에 적용하고 과거 귀속은 보존하는 것을 기본 제안으로 둡니다. 기존 완료 기록의 귀속 수정은 별도 명시적 행동으로 처리합니다.
- 주말 중 임의 1회와 토·일 각각은 다릅니다. 초기 날짜 기반 계획에서는 선택 요일별 회차를 지원합니다. 기간 내 N회 엔진을 이미 지원하는지 별도로 알려 주세요. 이번 요청만으로 신규 기간 목표 엔진 구현을 필수화하지 않습니다.

## G-03. 일회성 행동·이미 한 일 기록

- 목표 상세에서 일회성 Task 생성 시 목표가 자동 연결되고, 일반 Task 생성/상세에서도 목표를 선택·연결할 수 있어야 합니다. 기존 D-Day Task 생성/연결 API 재사용 가능 여부를 확인해 주세요.
- 계획하지 않았지만 이미 한 일은 실제 실천 날짜·행동 제목·선택 메모로 바로 기록할 수 있어야 합니다. 원자적인 완료 Task 생성 또는 독립 실행 기록 중 중복 방지·조회가 일관된 방식을 제안해 주세요.
- 추가 실천을 기존 반복 회차의 기본/최소 결과로 억지로 바꾸지 않습니다. 일회성 기록은 해당 계획의 주말 회차를 자동 완료하지 않습니다.
- 생성 중복 재시도와 완료 기록의 생성/수정/취소를 지원합니다. 기존 Task를 목표에 연결하는 경우 새 실천을 복제하지 않습니다.

## G-04. 목표의 지나온 길

- Goal ID·명시 기간·시간대·cursor 기반의 전체 여정 조회가 필요합니다. 주간뿐 아니라 목표 시작 이후도 조회합니다.
- 반복 회차 실천과 일회성 Task 완료/직접 기록을 통합하되 원본 종류·ID·실천 날짜·당시 목표/계획/행동·기본/최소/종류 미확인·메모를 제공해 주세요.
- 연결 Task와 반복 회차는 같은 원본으로 중복 집계되지 않아야 합니다. 계획 변경 이력·목표 결과는 보여줄 수 있되 실천 수에 넣지 않습니다.
- 목표별 실천 회차/일회성 완료 수·실천 날짜 수 등 집계는 전체 원본 기준으로 제공합니다. 페이지 일부를 전체로 간주하지 않습니다. 최소 행동·휴식·기록 없음은 기존 원칙대로 구분합니다.
- 계획한 분량에서 실제 학습량/시간을 계산하지 않습니다. 첫 버전은 분량 합계가 없어도 되며, 실제 분량을 받는다면 단위/실제 입력 여부가 분명해야 합니다. 점수 상승·목표 달성률 자동 추정은 요청하지 않습니다.
- 완료 취소·Task 변경·목표 연결 수정 후 원본과 집계·AI 요약이 일치해야 합니다. 과거 기록을 없애는 계획 재생성은 피합니다.

## G-05. 스스로 계획하고 AI는 보조

사용자가 직접 목표·반복 계획 여러 개를 만들 수 있어야 합니다. AI는 목표 구체화·행동 초안·조정과 실제 기록 요약을 보조하며 자동 확정하지 않습니다. 생성 장애에도 CRUD·실천·여정 조회는 동작해야 합니다. 개인 메모/목표의 AI 전달 범위·보관 정책은 기존 요청과 같습니다. 동기 문구 순환은 앱 로컬 기능으로 신규 서버 요청이 아닙니다.

## 계약 회신과 수용 기준

기존 D-Day·Task·recurrence 재사용 범위, 신규 엔터티/관계, 날짜 선택·과거 입력·조회 범위/정렬·상태 변경·계정/게스트·멱등성·충돌·권한·삭제/보관·알림 정리 정책을 포함한 DTO/OpenAPI와 예시를 부탁드립니다. 아직 신규 경로명을 확정하지 않았습니다.

필수 검증: 목표 하나 아래 독립 반복 계획 둘 생성 → 각 회차 기본/최소 실천 → 일회성 Task 완료 → 이미 한 일 기록 → 목표 여정에 각 원본이 한 번만 등장 → 완료 취소 시 집계 갱신 → 계획/목표일 변경 후 과거 기록 보존 → 목표 달성 확인 및 미래 반복 처리.

기존 요청의 실천 결과·AI·알림·보안/소유권 공통 조건은 유지합니다. 이 문서와 원 요청을 무조건 별도 API 세트로 중복 구현하지 말고 통합 설계로 회신해 주세요. 백엔드 코드는 별도 저장소에서 진행합니다.
