## 현재 확인 결과

모바일 URL `/tasks/{id}`의 숫자를 바꿔 다른 사람의 개인 Task를 볼 수 있는지 확인했다. 모바일은 Bearer JWT로 `/api/v1/tasks/{id}`를 호출한다.

백엔드 `b9495f0`에 개인 소유권 회귀와 legacy `/api/tasks/**` 차단이 있고, STG `stg-b9495f0-20261025163438`에서 모바일도 전용 게스트2개로 검증했다. 거부35건과 양성 대조/원본 보존/목록 격리를 포함한46개 확인 통과, 생성 Task3개 삭제/404 확인과 logout2개 완료다. [직접 검증 근거](../qa/task-authorization-2026-10-25/README.md).

백엔드10월25일 상태 문서에는 운영 `6cdc9e5`에 이 보안 수정이 미반영이라고 기록되어 있다. 운영 버전/차단은 모바일에서 직접 검증하지 않았다.

## 요청 사항

1. **운영 배포 여부/일정 확인:** legacy 차단을 포함하는 최종 SHA와 imageTag, 운영 반영 여부를 회신해 주세요. 미반영이면 백엔드 배포 절차와 승인에 따라 적용해 주세요. 모바일에서 서버/DB/배포는 변경하지 않습니다.
2. **운영 전용 합성 계정 회귀:** 전용 계정 A/B를 사용하고 실제 고객 Task ID는 사용하지 말아 주세요. 회원↔회원, 게스트↔회원 조합도 포함해 주세요.
3. **인증/소유권:** 미인증·잘못된 token은401. 다른 owner의 개인 Task 조회/수정/삭제/완료/재개와 체크리스트 조회/생성/수정/완료/재개/정렬/삭제는 데이터 없이404여야 합니다. 요청의 userId/ownerId를 신뢰하지 않고 인증 사용자·개인 scope로 검사해 주세요.
4. **하위 ID 혼합:** 본인 Task A의 경로에 다른 Task B의 checklist item ID를 넣어도 조회/변경이 불가해야 합니다. 같은 owner의 서로 다른 Task 조합과 다른 owner 조합을 모두 확인해 주세요. 재정렬에 잘못된 item ID가 포함되면 변경 없이 거부해 주세요.
5. **옛 경로 우회:** `/api/tasks` 및 하위 경로를 통한 조회·변경 우회를 막아 주세요. 현재 STG의 미인증401/인증403 정책과 반환 데이터 비노출을 확인해 주세요. 다른 legacy 경로도 같은 서비스에 도달할 수 있는지 검토해 주세요.
6. **원본 보존/정리:** 각 연산의 소유자 정상 동작을 대조하고 거부 후 제목·상태·계획일·체크리스트/순서·목록이 바뀌지 않았는지 재조회해 주세요. 합성 데이터 정리와 잔여 guest/idempotency row 정책을 결과에 적어 주세요.
