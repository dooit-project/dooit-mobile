# 빠른 기록: 사용자가 고른 유형 보존 요청

2026-10-18 · 백엔드 추가 전달용 초안 · 미전달·미합의

기존 목표 중심 변경 요청과 별개 요청이다. 이 문서의 새 필드는 현재 API 계약이 아니며 모바일에서 아직 전송하지 않는다.

## 문제와 원하는 결과

오늘의 추가 메뉴에서 `할 일`을 선택하면 한 줄 자연어 빠른 기록이 열린다. 현재 요청 DTO는 `text`, `referenceDate`, `timeZone`, `defaultCategory`뿐이라 선택 유형을 전달할 수 없다. 모바일 mock은 날짜를 해석하면 종일 SCHEDULE로 저장한다. 실제 백엔드가 같은 정책인지는 사용자 요청에 따라 실 API 검증을 보류해 미확인이다.

사용자가 `할 일`을 선택한 경우 `오늘 영단어 30개 외우기`의 날짜는 할 일의 계획 날짜를 정하는 데 사용하고, 일정으로 자동 전환하지 않기를 요청한다. `일정`·`아이디어`를 명시한 경우에도 선택을 보존한다. 유형을 지정하지 않는 기존 자동 해석 클라이언트의 동작은 깨뜨리지 않는다.

## 제안 계약 — 서버 검토 후 확정

기존 `POST /api/v1/tasks/quick-capture` 요청에 선택 필드를 추가하는 방안을 검토해 주세요.

```json
{
  "text": "오늘 영단어 30개 외우기",
  "referenceDate": "2026-10-18",
  "timeZone": "Asia/Seoul",
  "requestedType": "TODO"
}
```

- `requestedType` 제안 값: `TODO | SCHEDULE | IDEA`. 생략하면 기존 자동 해석. 최종 필드명과 nullable 처리·지원 범위는 회신으로 확정한다.
- TODO를 명시하고 날짜만 있으면 실제 `task.type=TODO`, `task.plannedDate=해석한 날짜`로 저장한다. 기존 TODAY 상태가 미래 계획도 포함하는지 명확히 해 주세요. 클라이언트는 상태 이름만 보고 오늘 날짜라고 판단하지 않는다.
- TODO를 명시했는데 시각 표현도 있으면 일정으로 자동 전환하지 않는다. 시각을 설명에 보존하거나 별도 제안으로 반환할지 정책을 합의한다. 지원하지 않는 조합은 명시적 오류를 반환하고 몰래 유형을 바꾸지 않는다.
- 날짜 없는 TODO는 기록함에 저장하고 이후 날짜 선택/오늘로 이동할 수 있게 한다. 오늘 메뉴에서 날짜가 없을 때 자동으로 referenceDate를 계획일로 둘지, 기존 기록함 정책을 유지할지는 제품 합의 후 확정한다.
- SCHEDULE 명시 시 시작/끝/종일·날짜 부족 시 처리 정책을 확인해 주세요. IDEA 명시 시 날짜 해석만으로 다른 유형으로 바꾸지 않기를 요청한다.
- `task`는 실제 저장된 원본이다. `parsedDate/Time/Type/Recurrence...`가 해석 제안인지 실제 적용 결과인지 명시해 주세요. 모바일 안내는 저장된 `task`를 우선한다.
- 반복 문장을 해석했다면 실제 반복 시리즈/규칙을 저장하는지, 현재는 메타데이터만 반환하는지 확인해 주세요. 저장하지 않은 반복을 완료된 설정으로 안내하지 않는다.
- unsupported 값/조합 오류 시 생성 여부, timeout 후 기존 멱등성 계약 적용 여부도 함께 확인해 주세요. 재시도 때문에 항목을 새로 중복 생성하는 흐름은 피한다.

## 회신 요청과 수용 예시

| 입력과 선택                        | 원하는 저장/응답                                          |
| ---------------------------------- | --------------------------------------------------------- |
| TODO + `오늘 로그인 버튼 연결하기` | TODO, 계획일 2026-10-18, 종일 일정으로 자동 전환하지 않음 |
| TODO + `내일 영단어 30개`          | TODO, 계획일 2026-10-19, 오늘 목록과 구분                 |
| TODO + 날짜 없음                   | 기존 기록함 정책 또는 합의한 기본 계획일 정책             |
| SCHEDULE + `내일 오후 3시 회의`    | SCHEDULE, 실제 시작 시각·종료/종일 응답 일관              |
| IDEA + 날짜 표현                   | IDEA 유지, 날짜 표현을 어떻게 보존했는지 명시             |
| 유형 생략                          | 기존 자동 해석 호환                                       |
| 반복 표현                          | 실제 저장된 시리즈/규칙과 파싱 제안을 구분                |

필드명·적용 정책·DTO 예시·오류 계약·배포 시점을 회신받은 뒤 모바일 타입/요청과 mock을 함께 연결한다. 이번 모바일 수정에서는 서버 구현·DB 변경·mock 파싱 정책 변경을 하지 않는다. 실제 API·운영 데이터 검증도 보류 상태다.
