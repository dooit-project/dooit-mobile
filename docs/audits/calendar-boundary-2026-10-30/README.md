# 기간 일정 주·월 경계 검토

2026-10-30 · 기준 `84d76c1` 이후 작업 트리

- 범위: 선택된 [월간 달력 시안](../../design/calendar-navigation-2026-10-30/README.md)의 구조와 기존 기간 막대를 유지하고 주 경계에서의 이어짐 표시만 보정한다. 기존 [Product Design 달력 검토와 공식 안내 비교](../calendar-review-2026-10-30/README.md)를 참고했으며 이번에 다른 앱을 직접 조작한 것은 아니다.
- 문제: 월요일 00:00에 끝나는 일정은 일요일까지만 차지하지만 일요일 막대에 다음 주로 이어지는 화살표가 나타났다. 일정이 실제 차지하는 마지막 날짜를 여러 날 판별과 이어짐 표시에서 함께 사용하도록 수정했다.
- 실제 화면: 로컬 mock 데이터를 Chrome 앱에서 수정하여 10월 31일 09:00부터 11월 2일 00:00까지의 [자정 종료](./01-midnight-end.jpg)는 화살표가 없고, 종료를 09:00으로 바꾸면 [다음 주로 이어짐](./02-continues.jpg)이 표시된다. [11월 화면](./03-next-month.jpg)에서도 앞 주와 다음 주의 양방향 이어짐 표시를 확인했다. 실제 백엔드 데이터는 변경하지 않았다.
- 범위와 한계: 내장 브라우저와 Chrome 확장의 접근 호스트가 연결되지 않아 Chrome 앱의 접근성 조작으로 확인했다. 캡처는 desktop Web이며, 320/390/430 실제 화면의 새 DOM 측정과 `check:ui-layout`, 확대, 스크린 리더 음성 및 Android/iOS 실기기는 미확인이다. 연결 복구 후 기간 막대와 주변 조작 영역을 측정해야 하며 이 검토를 모바일 시각 승인으로 간주하지 않는다.

## Product Design 재검토

2026-10-30 · Chrome 앱, desktop Web, mock · Product Design audit 기준

1. [달력](./04-recheck-desktop.jpg): 월 이동과 날짜별 목록의 관계가 명확하고 기간 막대를 바로 열 수 있다. 다만 목록의 개별 테두리는 [선택된 모바일 보정 시안](../../design/calendar-navigation-2026-10-30/04-refined.png)의 구분선 중심 표현보다 강조된다. 서로 다른 viewport와 데이터이므로 픽셀 단위 시안 일치 판정은 아니다. [표시용 화면](./06-calendar-display.jpg)은 브라우저 주변을 잘라낸 실제 캡처다.
2. [기간 일정 상세](./05-recheck-detail.jpg): 막대에서 상세를 열면 시작·종료 날짜와 시각을 함께 읽을 수 있다. 상세의 일정·실행일은 별도의 조작이지만 차이를 이해하기 쉬운지 추가 사용자 관찰이 필요하다. 화면에서 두 아이콘은 각 정보 묶음과 대체로 정렬되어 보이나 작은 화면의 광학 정렬은 확인하지 못했다.
3. [Google Calendar 공식 안내](https://support.google.com/calendar/answer/6110849?co=GENIE.Platform%3DAndroid&hl=en)를 다시 확인했다. 날짜 선택과 오늘 복귀를 제공하는 사례로만 참고했으며 다른 앱을 직접 조작한 비교는 아니다. 기간 막대의 화살표를 이용하는 Dooit의 표현이나 접근성 통과를 뒷받침하지는 않는다.

결론: 이번 경계 표시 보정에 대해 desktop에서 새로 확인된 기능 문제는 없다. 다만 목록 테두리의 시각적 차이와 좁은 화면에서 화살표·긴 제목의 가독성은 후속 검토가 필요하다. 선택 상태, 조작 크기와 색상 대비를 스크린샷만으로 접근성 통과 판정하지 않는다. 실기기·확대·스크린 리더·모바일 DOM 검사도 보류다.

캡처 자료에서 개인 브라우저 탭 정보가 포함된 상단 영역은 제거했다. 문서의 원본 캡처 링크는 이 정보가 제거된 기록이며, 잘리지 않은 파일은 로컬 임시 보관소에 보존했다.
