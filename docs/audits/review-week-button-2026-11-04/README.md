# 돌아보기 ‘이번 주’ 상태 비교

2026-11-04 · Product Design audit 기준 · 로컬 Playwright / Chrome mock Web

1. [이번 주 320](./current-320.png), [390](./current-390.png): 파란 점과 텍스트로 된 상태이며 버튼이 아니다. 화면 크기와 관계없이 같다.
2. [지난주 320](./previous-320.png), [390](./previous-390.png): 현재 주로 돌아가는 테두리 버튼이다. 화면 크기와 관계없이 같다. 누르면 이번 주로 돌아갔다. 왼쪽 화살표의 어두운 테두리는 클릭 후 초점 표시다.

현재 구현은 상태에 따라 같은 위치의 텍스트가 상태 표시에서 버튼으로 바뀌므로, 화면 간 캡처를 비교하면 크기 때문에 표현이 달라진 것처럼 느낄 수 있다. 320에서는 버튼의 안쪽 여백과 날짜 영역이 모두 작아 실제 미관과 여유를 다시 살펴봐야 한다.

[Apple 버튼 가이드](https://developer.apple.com/design/human-interface-guidelines/buttons?changes=l_8)는 버튼을 알아보기 쉽도록 스타일·레이블·역할을 연결하고, 충분한 공간과 최소 44pt 터치 영역을 권장한다. 모든 버튼에 테두리를 의무화하지는 않는다. [Google Calendar 공식 안내](https://support.google.com/calendar/answer/6110849?co=GENIE.Platform%3DAndroid&hl=en)는 오늘로 돌아가는 동작을 설명하지만 테두리 형태나 비활성 상태를 비교할 근거는 아니다. 외부 앱을 직접 조작하지 않았다.

추천 방향은 ‘이번 주’를 고정된 위치의 동일한 테두리 버튼으로 유지하고 지난주에서는 활성, 현재 주에서는 차분한 비활성 상태로 구분하는 것이다. 조작이 가능한 주에는 버튼임을 쉽게 알아볼 수 있고, 주가 바뀌어도 한 요소의 역할이 유지된다. 이것은 설계 판단이며 사용자 조사 결과가 아니다. 조작 불가능한 버튼이 계속 보이는 절충이 있다. 실제 구현 여부와 320에서의 표시·초점·접근성은 아직 검증하지 않았다.

내장 브라우저 접근 호스트와 native 앱 연결 장애로 사용자가 이전에 승인한 로컬 Playwright를 사용했다. 320/390 mock Web 빈 상태의 지난주 이동과 복귀만 확인했다. Android/iOS 실기기, 글자 확대와 스크린 리더 음성은 미확인이다. 일부 캡처의 검은 번개는 Expo 개발 오버레이다.
