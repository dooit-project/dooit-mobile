# Task 작성 기본 정보 우선 노출 감사

## 문제와 목표

Today의 유형별 작성 진입 뒤 새 일정은 알림과 반복 선택지가 첫 화면을 길게 만들고, 새 아이디어는 선택 정보가 자동으로 펼쳐져 저장 행동이 아래로 밀렸다. 기존 기능과 값은 유지하면서 필수 입력과 저장 행동을 먼저 보여 주는 것이 목표다.

## 구현 전 Product Design 검토

- 기준 화면: `reference-schedule-before.png`, `reference-idea-before.png`
- 기준 패턴: 기존 `TaskForm`의 `추가 정보` 점진적 공개와 `docs/design/DESIGN.md`의 flat sheet 원칙
- 선택 방향: 새 일정은 제목·유형·날짜·종일·시간, 새 할 일과 아이디어는 제목·유형만 기본 노출한다. 일정의 알림·반복과 공통 설명·예상 시간·카테고리는 같은 펼침 영역에 둔다.
- 기존 화면 안에서 선택 필드의 기본 노출만 조정하는 작은 변경이므로 별도 시각안 3개를 만들지 않았다.
- 성공 조건: 390×844와 320×844에서 필수 입력과 저장 버튼이 첫 화면에 보이고, 추가 정보는 한 번의 44px 이상 행동으로 열리며 기존 입력 기능이 유지된다.

## 감사 결과

- Web Chrome, mock API, light theme에서 확인했다. 앞선 작업에서 앱 내장 브라우저가 로컬 앱에 연결되지 않아 같은 Chrome 연결을 이어 사용했다.
- 제목 예시는 할 일·일정·아이디어 유형에 맞게 달라진다.
- 새 작성 화면의 추가 정보는 기본으로 접힌다. 기존 Task를 수정할 때 설명·카테고리·예상 시간·알림 끄기·사전 알림·반복 값이 있으면 펼친 상태로 시작한다.
- 알림·반복 선택 chip과 추가 정보 toggle의 최소 높이를 44px로 맞췄다.
- 접근성 tree에서 펼침 button의 이름과 `expanded` 상태, 알림·반복 radio의 이름·선택 상태를 확인했다.
- browser console error는 0건이다. 기존 React Native Web `shadow*` deprecation warning만 남아 있다.
- P0/P1/P2 문제는 발견하지 못했다.
- Android·iOS 실제 keyboard, font scale 1.5, dark theme와 screen reader 조작은 이번 Web 감사 범위 밖이다.
