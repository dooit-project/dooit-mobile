## 구현 전 검토

- 대상/목적: 개인 Task 상세에서 수정 없이 닫거나 원문을 복원한 경우 불필요한 버리기 확인을 없애고 실제 입력은 보호한다.
- 원본: [선택05](../../design/task-detail-options-2026-10-24/05-context-panel-aligned.png)를 직접 확인했다. 기존 패널·공통 TaskForm·체크리스트·InlineNotice와 경고의 행동 위계를 유지한다. 새 구조 선택이 아닌 R3 동작 보정이다.
- Product Design audit/index/critical overrides·기본 시각 검사를 적용한다. user-context preflight는 저장 context 없음. 기존 Chrome 연결에서 localhost8082 mock/goal-lanes,390×844/light/기본 글자 배율을 사용한다. 다른 browser surface로 전환하지 않는다.
- 구현 전 새 실제 화면: 상세→수정→입력 없이 X를 눌러 ‘저장하지 않은 내용’ 경고가 뜨는 것을 재현했다. 원인은 편집 모드 자체를 dirty로 취급하는 것이다. 해당 캡처01–03을 저장했다.
- 변경: 폼 진입 당시의 고정 입력 스냅샷과 현재 값을 비교하고 동일한 dirty를 X/Escape/Back/새로고침 보호에 사용한다. 반복 적용 범위/추가 정보 펼침은 그 자체로 입력 변경이 아니다. 체크리스트도 수정 시작 당시 제목을 비교 기준으로 보존한다. 변경한 수정 폼에서 취소해도 같은 기존 확인을 사용하되 취소 완료 후 상세에 남는다.
- 유지/범위 밖: 렌더링·아이콘·제목 완료 체크·일정 API·원래 저장 요청·메뉴는 유지한다. R4 날짜 전용 편집/R5 손잡이/R6 초기 초점, 새 할 일/Workspace 폼 전체의 작성 보호 확장은 이번 범위 밖이다.
- 참고: [기존 감사 R3](../task-detail-external-review-2026-10-25/README.md)와 공식 [W3C modal dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)의 Escape/초점 복귀 기준을 확인했다(2026-10-25). 기존 Todoist Task view 자료는 관리/편집 역할 구분의 배경 참고이며 실제 Todoist를 조작하지 않았다. ‘실제 차이가 있을 때만 경고’는 이번 재현과 Dooit 입력 보존 목적에 따른 설계 판단이다.
- 완료 조건: 무변경/원문 복원은 바로 닫힘, 실제 변경은 계속 작성/버리기, 반복 범위만 변경은 경고 없음, 빈 체크리스트 추가와 실제 입력 구분, 저장 후 dirty 해제, 새 실제 화면/좌표와 자동 회귀·전체 validate. native/보조 기술/운영 API 미확인은 구분해 기록한다.

## 구현과 확인한 동작

`TaskForm`은 편집 시작 당시 입력값을 고정하고 현재 값과 비교한다. 잘못된 날짜/빈 제목/잘못된 숫자 등 저장할 수 없는 입력도 차이가 있으면 보존한다. 폼 펼침·초점·반복 적용 범위 선택 자체는 dirty가 아니다. 원문으로 복원하면 보호를 해제한다. 공통 `useTaskDraftChange`가 실제 변경/해제/폼 닫힘을 부모에 알리며 체크리스트도 같은 경로를 사용한다. 새 의존성/API 요청 계약 변경은 없다.

상세는 `isEditing` 대신 폼/체크리스트의 실제 dirty를 X·Escape·route 제거·지원되는 Web history traversal에 사용한다. 저장 중에는 기존 이동 차단을 유지하며 Web unload 보호도 켠다. 편집 중 목표 경로는 기존처럼 잠근다. 수정 취소의 확인 버튼은 **‘수정 취소’**, 상세 이탈은 **‘버리고 닫기’**로 구분한다. 취소/저장으로 편집만 끝나면 상세의 수정 버튼으로 초점을 돌린다. 초기 상세 초점 R6을 변경하지 않았다.

새 실제 Chrome mock 흐름과 저장 캡처를 직접 확인했다. 모든390 캡처는390×844,320은320×844,430은430×932이며 JPEG 메타데이터와 DOM viewport를 대조했다.

## 검증 결과와 한계

- 새 실제 [320](./layout-final-320.json)/[390](./layout-final-390.json)/[430](./layout-final-430.json)은 각각5행/8조작 영역으로 `check:ui-layout` 통과. 제목 첫 줄/정보 블록 중앙·44px·문서 가로 넘침을 확인했다. 폼 전체의 표식 없는 입력/색 대비를 이 검사로 승인하지 않는다.
- 자동 회귀17개: 폼 진입/초점/펼침과 실제 입력 구분, invalid 값/원문 복원, 유형/종일/알림/반복 간격, 조회 갱신 중 고정 기준, 체크리스트 초기 제목/입력/닫힘, Web unload 등록/해제와 native 미등록이다. 전체 `npm run validate` 통과:124 suites /660 tests, opt-in STG1개 제외.
- **새로고침은 실제 확인창 검증 미완료:** 자동화의 `reload()`는 확인창을 반환하지 않고 다시 로드돼 임시 입력이 사라졌다. 이어 시도한 Meta+R은 실제 새로고침을 일으키지 않아 증거로 쓰지 않는다. 원인을 자동 승인/제품 문제 중 어느 것으로도 단정하지 않는다. 이벤트가 활성 보호 상태에서 `preventDefault`/`returnValue`를 설정하고 dirty 해제/종료 시 해제되는 것은 회귀로 확인했다. 일반 사용자가 Chrome에서 직접 새로고침/탭 닫기를 취소했을 때 입력이 보존되는지는 출시 전 수동 확인이 필요하다. 보호가 완전히 검증됐다고 표시하지 않는다.
- 실제 Android/iOS의 Back/키보드/safe area·글자 확대1.5·VoiceOver/TalkBack·dark·운영 API·저장 오류/긴 지연/외부 갱신 실사용은 미확인이다. 확대/조회 갱신 회귀를 native나 실제 API 검사로 확대하지 않는다. Navigation API 미지원/취소 불가 traversal의 기존 한계는 남는다. 새 할 일/Workspace의 전체 작성 보호는 이번 연결 범위 밖이다.

final result: passed (R3의 명시한 X/Escape/취소/Back·실제 Web 및 자동 회귀 범위). 새로고침 수동 확인과 native는 미완료이며 전체 앱 UX 승인은 보류한다. 다음 단위는 R4 일정 행의 날짜/시간에 집중한 편집이다.
