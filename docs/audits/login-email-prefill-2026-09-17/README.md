# 재로그인 이메일 유지와 삭제 동작 감사

Last updated: 2026-09-17

## 문제와 선택

등록 계정의 세션이 만료되면 사용자가 같은 이메일을 다시 입력해야 했다. 로그인 성공 시 등록 계정 이메일을 기기에 보관하고, 기존 세션 만료 화면에만 미리 채운다. 게스트 전환 시에는 저장 이메일을 삭제하며 최초 로그인에는 임의로 노출하지 않는다.

이메일 입력 오른쪽에는 24px 원형 `close` 아이콘을 표시한다. 실제 버튼 영역은 44×44px로 유지하고 접근성 이름은 `이메일 지우기`로 제공한다. 기존 입력 구조 안의 작은 보완이므로 별도 시각안 비교는 적용하지 않았다.

## 구현 후 Product Design 감사

환경: Chrome, localhost:8090, mock API, 390×844. 내장 브라우저가 제공되지 않아 연결된 Chrome을 사용했다.

1. [기존 이메일이 채워진 재로그인](./01-prefilled-390.png): 정상. `다시 로그인해요`, 세션 종료 안내와 기존 이메일이 한 맥락에 표시된다. 삭제 버튼은 시각적으로 작고 실제 DOM 영역은 44×44px다.
2. [이메일 한 번에 지운 뒤](./02-cleared-390.png): 정상. 한 번의 클릭으로 값과 삭제 버튼이 사라졌으며 이메일 입력으로 포커스가 돌아오는 것을 DOM에서 확인했다. 캡처는 전체 상태 확인을 위해 포커스를 화면 밖으로 옮긴 뒤 저장했다.
3. [최초 로그인](./03-first-login-empty-390.png): 정상. 저장 이메일과 삭제 버튼 없이 빈 입력으로 시작하고 제목은 `로그인해요`다.

세 캡처는 이번 실행에서 새로 저장하고 직접 확인했다. 키보드로 삭제 버튼에 도달할 수 있고 버튼 이름과 입력 포커스 복귀를 DOM에서 확인했다. 실제 Android·iOS 키보드, 비밀번호 관리자, 스크린리더 안내와 cold start 만료는 Web 캡처만으로 확인할 수 없다.

## 데이터 처리

- native: 등록 계정 이메일을 SecureStore에 보관한다.
- Web: 기존 인증 정보와 같은 origin의 localStorage에 보관한다.
- 등록 계정의 access token을 지워도 재로그인을 위해 이메일은 유지한다.
- 게스트 세션 생성·전환 시 저장 이메일을 삭제한다.
