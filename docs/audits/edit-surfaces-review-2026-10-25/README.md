## 결론과 범위

사용자가 지적한 어색함을 새 실제 화면에서 확인했다. **일반 상세는 유지하고 편집 폼과 버리기 확인의 시각 위계를 먼저 보완한다.** 노란 경고 면·갈색 경계·검은 초점 테두리·빨간 버튼이 동시에 강조되고, 폼의 입력/선택/안내가 독립 박스로 반복된다. 테두리 색 하나의 문제가 아니다. R3의 입력 보호 기능 검증 통과를 이 화면의 시각적 완성도 승인으로 확대하지 않는다.

Product Design audit/index/critical overrides/design-audit-framework, 저장소 구현 가이드·기본 시각 검사를 적용했다. user-context preflight는 저장 context 없음이었다. 현재 선택05의 흰 패널/간단한 정보 행과 기존 Today 구조를 변경 대상으로 삼지 않는다. Figma나 외부 앱 로그인/설치는 사용하지 않았다. 이번에는 앱 코드를 바꾸거나 새 TO-BE 시안을 생성하지 않았다.

## 코드·DOM 근거와 공통 영향

[새 실제 수치](./warning-metrics-390.json): 경고는350×112px, 배경`rgb(244,226,174)`/갈색1px 경계/반경6이다. 계속 작성은 검정 계열2px 경계, 버리기는 빨강 채움+2px 경계, 버튼 반경10/높이44다. continue의 computed outline은 none이다. 검은 선을 브라우저가 임의로 추가한 이중 outline으로 오인하지 않는다.

- `InlineNotice`: tone warning이 노란 면/갈색 경계와 `role=alert`를 제공한다. 정보 알림과 응답을 기다리는 결정창의 역할을 분리할 필요가 있다. 정의/참조가41개 TSX 파일에 걸쳐 있으므로 전역 색 변경부터 하는 방식은 피한다.
- `Button`: `isFocused`일 때 모든 variant의 borderColor가 text로 바뀐다. `IconButton`도 같은 색과2px 경계를 넣는다. 공통 변경 시 상세/메뉴/계획/작성/삭제 등의 포인터·키보드 상태를 함께 확인해야 한다.
- `TaskForm`: 여러 TextInput/유형/알림/반복에서 경계·배경·초점 스타일을 반복 정의한다. 한곳씩 임의 수치로 바꾸기보다 공통 필드/선택 규칙을 먼저 적용한다.
