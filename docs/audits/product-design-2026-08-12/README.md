# ToDoLab 전체 UI/UX 감사

- 점검일: 2026-08-12
- 대상: Expo Web mock, 모바일 390×844 및 넓은 화면 1024×768
- 범위: 최초 사용, 인증, Today, Calendar, 검색, 완료 기록, D-Day, Task 생성·상세, 하루 정리, 프로필, 설정
- 방식: 실제 화면과 상호작용을 캡처한 뒤 UX·시각 일관성·접근성 위험을 함께 검토

## 결론

현재 앱은 로그인하지 않아도 오류 페이지에 막히지 않고 Today를 사용할 수 있다. 최초 사용 화면도 게스트 시작, 로그인, 기능 둘러보기를 명확히 분리해 기존 문제를 해결했다. 공통 카드, 버튼, 여백, 타이포그래피와 빈 상태도 전반적으로 일관적이며 모바일과 넓은 화면 모두 레이아웃이 안정적이다.

출시 전에는 아래 세 가지를 우선 개선하는 것이 좋다.

1. **P0 — 비밀번호 재설정 화면을 사용자용 대기 상태로 바꾸기:** 현재 `백엔드 계약 준비 필요`, API 목록처럼 내부 개발 정보를 그대로 노출한다. 기능이 준비될 때까지 로그인 화면에서 진입점을 숨기거나, 이메일 문의·지원 안내처럼 사용자가 실제로 취할 수 있는 행동만 제공한다.
2. **P0 — 설정에서 API·Access Token 진단 정보를 제거하기:** `mock`, API URL, Access Token 저장 여부는 개발 빌드에서만 표시하고 일반 사용자의 설정에는 계정, 테마, 알림, 가이드만 남긴다.
3. **P1 — 프로필과 더보기 역할을 분명히 하기:** 목표, 검색, 완료 기록, 설정이 모두 `프로필` 탭 아래 있어 발견하기 어렵다. 탭 이름을 `더보기`로 바꾸거나, 프로필 헤더와 기능 메뉴의 역할을 시각적으로 구분한다.

| 12   | 하루 정리        | 보통      | 빈 상태는 명료하지만 사용자가 다음에 할 행동이나 Today 복귀 행동이 없다.                                                          |

| 15   | Task 상세        | 보통      | 빠른 날짜 변경과 정보 요약은 유용하다. 정보가 긴 단일 카드에 몰려 스캔 비용이 높다.                                               |
| 16   | 넓은 화면        | 양호      | 콘텐츠 최대 너비와 하단 탭이 안정적으로 재배치된다. 과도하게 늘어나거나 깨지는 요소는 없다.                                       |

## 잘된 점

- 게스트 사용자가 인증 오류를 보지 않고 바로 Today에 진입한다.
- 최초 안내가 선택권을 주며, 가이드를 강제로 끝내야 하는 구조가 아니다.
- 모든 주요 빈 상태가 오류가 아니라 현재 상태임을 설명한다.
- 공통 버튼과 카드의 크기, 모서리, 색상, 화면 좌우 여백이 일관적이다.
- DOM에서 제목, 버튼, 탭, 라디오, 검색 입력, 체크박스 역할과 접근성 이름이 확인됐다.
- 모바일 390px와 넓은 화면 1024px에서 잘림이나 가로 스크롤이 보이지 않았다.
- 점검 중 사용자 화면의 런타임 오류는 없었다. Web에서는 deprecated shadow 스타일 경고만 반복됐다.

## 개선 기회

### 구조와 흐름

- `프로필` 탭은 실제로 계정과 더보기 메뉴 역할을 함께 한다. 탐색 비용을 줄이려면 탭 이름과 헤더 구조를 역할에 맞게 정리한다.
- Today에서 만든 기본 Task가 `오늘`인지 `기록함`인지 저장 전에 알려준다. 예: 저장 버튼을 `기록함에 저장`으로 쓰거나 날짜 선택을 기본 영역에 둔다.
- Calendar, 완료 기록, 하루 정리의 빈 상태에 현재 작업으로 이어지는 작은 행동을 추가한다.
- 검색 진입 직후에는 `찾은 항목이 없어요` 대신 `검색어를 입력하거나 필터로 기록을 둘러보세요`처럼 검색 전 상태를 구분한다.

### 시각적 위계와 문구

- 안내 카드와 빈 상태 설명이 동시에 보이는 첫 방문 화면은 정보가 중복된다. 안내 확인 후에는 빈 상태 CTA만 남기는 현재 방식이 적절하며, 안내 문구를 더 짧게 줄일 수 있다.
- Task 상세의 정보 카드는 일정·분류·기록처럼 2~3개 묶음으로 나누면 빠르게 읽기 쉽다.
- 회원가입 하단의 `로그인하기`, `게스트로 계속 사용` 사이 간격과 위계를 조금 더 분명히 한다.
- 내부 명칭은 사용자 문구에서 제거한다: `백엔드 계약`, `API URL`, `Access Token`, `mock`.

### 접근성 위험

- 스크린샷과 DOM만으로 색 대비, 실제 VoiceOver/TalkBack 읽기 순서, 동적 글자 크기, 스위치 상태 발표, 키보드 가림을 완전히 검증할 수 없다.
- 캘린더 일정 막대와 일부 보조 컨트롤은 시각 높이가 44px보다 작다. 코드상 `hitSlop`이 있지만 실제 네이티브 터치 영역과 인접 항목 오작동 여부를 확인해야 한다.
- 연한 회색 보조 텍스트와 비활성 버튼은 밝은 화면에서 대비가 낮아 보인다. 토큰 단위 자동 대비 테스트와 실기기 확인을 함께 유지한다.
- 경고 카드가 `alert`로 노출되는 것은 적절하지만 프로필을 열 때마다 반복 읽히면 피로할 수 있다. 최초 1회 또는 상태 변경 시 중심으로 발표하는 방식을 검토한다.
- 200% 글자 크기, 화면 회전, 키보드 열린 상태에서 로그인·회원가입·Task 생성의 하단 행동이 가려지지 않는지 네이티브 실기기 확인이 필요하다.

## 권장 작업 순서

1. 비밀번호 재설정과 설정의 내부 개발 정보 차단
2. 프로필/더보기 정보 구조와 탭 이름 결정
3. Task 저장 위치 문구와 빈 상태 CTA 정리
4. Task 상세 정보 그룹화 및 검색 전/검색 결과 없음 상태 분리
5. Android TalkBack, iOS VoiceOver, 큰 글자, 키보드, 알림 권한 상태 실기기 점검

## 검증 한계

- mock 모드의 게스트 빈 상태를 중심으로 점검했다. 로그인 후 실제 서버 데이터, 네트워크 지연·실패·재인증, 계정 병합 결과는 포함하지 않았다.
- Web에서는 네이티브 알림 권한 요청 UI, 햅틱, 키보드 회피, 안전 영역, VoiceOver/TalkBack을 검증할 수 없다.
- 스크린샷은 시각적 위험을 보여주지만 WCAG 충족을 단독으로 증명하지 않는다.
