# 달력 탐색과 선택 상태 점검

2026-10-30 · Product Design audit · Chrome 확장, 로컬 mock Web/light

1. [달력 상단](./02-calendar-top-390.png): 월 제목 양옆 화살표는 접근성 이름과 실제 동작이 이전·다음 **주**다. 세 주를 표시하지만 제목은 월만 보여 이동 단위를 짐작하기 어렵다. 여러 날짜의 일정이 표시되도록 영역을 남긴 탓에 비어 있는 주도 높게 보인다. 이동 단위나 달력 밀도를 바꾸는 것은 선택지가 있는 구조 작업이므로 이번에 변경하지 않았다.
2. [다른 날짜 선택](./03-selected-390.png): 빈 날짜의 목록에는 선택 날짜가 숫자로 반복되지 않는다. 시각적으로는 선택 표시가 있으나 화면을 아래로 스크롤하면 날짜 문맥을 잃을 여지가 있다. 목록 제목 추가 또는 다른 구조는 후속 비교 대상이다.
3. 선택된 날짜·월은 기존 native `accessibilityState.selected`가 있으나 Chrome Web의 접근성 트리에서는 선택 여부가 노출되지 않았다. Web에만 선택된 항목 이름에 ‘선택됨’을 덧붙였다. 오늘과 다른 날짜를 번갈아 선택하고 [월 선택기](./04-month-picker.png)에서 현재 월 이름을 확인했다. 실제 스크린 리더 음성은 확인하지 않았다.
4. [Google Calendar 공식 Android 안내](https://support.google.com/calendar/answer/6110849?co=GENIE.Platform%3DAndroid&hl=en)는 날짜 선택·일정 목록·오늘 돌아가기와 월/일정 보기 전환을 설명한다. 이 문서 참고는 앱 직접 조작이나 dooit에 같은 구조가 적합하다는 검증이 아니다.

기존 달력 구조·날짜 이동·오늘/달력/계획/돌아보기 탭은 유지한다. Web 320/390/430에서 상단 헤더의 실제 좌표는 각 1행/3조작 검사 통과. Android/iOS 실기기, VoiceOver/TalkBack, 확대, 실제 운영 API, 모든 날짜 경계는 미확인이다. 개선 전후 화면의 예시 날짜·시각은 촬영일 기준으로 달라진다.
