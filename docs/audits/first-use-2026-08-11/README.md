# 최초 실행 Web 플로우 점검

점검 환경:

- 날짜: 2026-08-11
- API: mock
- viewport: 390×844
- origin: `http://[::1]:8092`
- 범위: 최초 실행, 기능 둘러보기, 로그인 선택 후 복귀, 게스트 Today 진입

## 단계별 결과

1. [최초 실행](./01-first-use.jpg) — 정상
   - 로그인 없이 시작, 계정 시작, 선택형 기능 둘러보기의 우선순위가 명확하다.
   - 첫 데이터 query나 인증 오류 없이 시작 방식부터 선택한다.
2. [기능 둘러보기](./02-feature-tour.jpg) — 정상
   - Today, Calendar, D-Day 설명이 한 화면에서 읽히고 닫기 동작이 명확하다.
   - 390×844에서 내용이 잘리거나 가로로 넘치지 않는다.
3. [수정 전 로그인 화면](./03-login-no-return.jpg) — 문제 발견
   - header가 숨겨진 상태에서 최초 시작 화면으로 돌아가는 명시적 동선이 없었다.
   - 브라우저나 OS 뒤로가기에 의존해 사용자가 인증을 강요받는 것처럼 느낄 수 있었다.
4. [수정 후 로그인 화면](./04-login-return-fixed.jpg) — 수정 완료
   - `시작 화면으로 돌아가기`를 추가했다.
   - 보호 route인 `/`로 바로 전환하면 Expo Router update loop가 발생해, 공개 `/start` route에서 시작 안내를 재사용하도록 수정했다.
5. [게스트 Today](./05-guest-today.jpg) — 정상
   - 게스트 생성 후 `/`로 이동하며 인증 오류 페이지가 노출되지 않는다.
   - 샘플 데이터 없이 빈 Today, 첫 할 일 CTA, 맥락형 도움말이 표시된다.

## UX·접근성 메모

- 주요 버튼과 보조 버튼의 순서, form label, password 보기 label, tab 접근성 이름은 DOM에서 확인했다.
- 390×844 화면에서는 잘림이나 가로 overflow가 없었다.
- 스크린샷만으로 키보드 전체 이동 순서, focus indicator, 화면 읽기 순서, 200% 확대, VoiceOver·TalkBack 동작은 확인할 수 없다.
- Android·iOS와 320px·430dp, 큰 글꼴 검증은 별도 실기기 QA가 필요하다.
