# 계획 화면 전체 목표 선택

2026-11-07 · Web 목업 데이터 · Android/iOS 미확인

## 범위와 기준

- 원본: 사용자가 선택한 [계획 화면과 전체 목표 시안](../../design/plan-goal-selection-2026-11-07/README.md). 화면 전체 재설계가 아닌 전체 목표 선택 분리부터 적용한다.
- 유지: 가로 목표 탭, 목표 검색/선택, 기존 목표와 새 Goal 구분, 목표 생성 및 이 기기의 목표 순서 편집. 목표 내용·API·기록은 바꾸지 않는다.
- 변경: 본문에 펼쳐지던 전체 목표를 공통 `DetailSheet` 기반 화면 위 시트로 분리하고 선택 표시와 상단 순서 편집을 추가한다. 시트 높이는 공통 컴포넌트의 선택적 속성이며 기본 시트 크기는 유지한다.
- 범위 밖: 반복·일회성 항목의 통합 목록과 혼합 순서 저장. 새 Goal Task 목록에 필요한 [G-07 계약](../../api/API_GOAL_JOURNEY_CHANGE_REQUEST.md)을 확인해야 하며, 문서에 기록된 전달·운영 상태는 최신 백엔드 확인 전까지 미확인이다.

## 실제 화면 확인

내장 브라우저 연결 호스트가 응답하지 않아 사용자가 앞서 허용한 로컬 Playwright와 설치된 Chrome을 사용했다. `npm run web:design -- --port 8096`의 목업 앱에 임시 게스트와 테스트 목표 두 개를 만들었다. 캡처는 운영 데이터가 아니다.

- [320px](./picker-320.png), [390px](./picker-390.png), [430px](./picker-430.png): 같은 긴 목표 이름 두 개, 선택 표시, 검색과 목표 순서 편집을 확인했다. 목표 생성 후 목록 열기, 검색·결과 없음, Escape 닫기와 버튼 초점 복귀, 목표 전환 및 순서 편집 진입을 각 크기에서 확인했다. 순서 저장 자체와 터치 드래그는 이번에 재검증하지 않았다.
- 첫 캡처에서 시트 뒤 하단 탭이 가려지지 않아 공통 시트를 Modal에서 열도록 수정했다. Web에서 선택 표시가 접근성 이름에 드러나지 않아 선택됨을 이름에 포함하고 다시 확인했다.
- `npm run check:ui-layout --`에 세 크기의 [320](./layout-320.json), [390](./layout-390.json), [430](./layout-430.json) DOM 측정치를 전달해 각 1행과 3개 공통 조작 영역의 기하 검사를 통과했다. 목록의 목표 선택 행은 별도 수동 확인 대상이며 이 수치에 포함하지 않았다. 글리프의 광학 정렬은 캡처에서 별도 확인했다.
- 구현 전후 캡처 비교는 동일 390px 화면·테스트 목표 기반이나 생성 시안은 실제 앱과 렌더링 조건이 다른 그림이다. 이미지에서 검색 아이콘과 관리 메뉴가 생략되거나 다르게 표현된 부분은 남아 있다.

## 적용한 검토

- Product Design `audit`: 실제 목업 화면을 새로 캡처해 목록과 선택 목표의 중복을 확인하고, 수정 후 동일 흐름을 다시 캡처했다. 전체 앱 감사나 사용자 조사는 아니다.
- Product Design `image-to-code` 지침 참고: 선택한 두 이미지와 기존 공통 컴포넌트를 직접 비교하여 목표 선택 상태를 구현했다. 정식 `design-qa` 전체 절차를 실행하거나 시안 전체 및 항목 통합을 구현한 것은 아니다.
- `better-layout`, `better-typography`: 작은 화면의 목록 접근, 긴 제목의 전체 표시 및 목표별 화면 전환을 점검했다.
- `better-accessibility` 원칙: 선택 여부를 색과 체크에만 의존하지 않도록 이름을 보완하고 Web 키보드 Escape·초점 복귀를 확인했다. 스크린리더와 native 접근성은 직접 검증하지 않았다.
- 다른 설치 스킬의 정식 감사·외부 앱 직접 조작은 이번 국소 구현에서 실행하지 않았다. 이번 결과를 독립 심사 또는 모든 플랫폼의 접근성 통과로 표현하지 않는다.
