# 돌아보기 전체 재검토

2026-11-04 · Product Design audit 기준 · 로컬 Playwright / Chrome mock Web

## 확인한 흐름

1. [기록 있는 이번 주 390](./audit-populated-390.png), [320](./audit-populated-320.png): 같은 날의 짧은 제목과 긴 제목 두 건을 완료한 다음 돌아보기에 진입했다. 제목과 완료 날짜를 확인할 수 있고, 390에서는 긴 제목의 마지막 글자만 다음 줄로 넘어간다. 항목 오른쪽 날짜를 고정해 제목의 가용 폭이 줄어든다. 항목이 상세로 이어진다는 단서는 화면에 없다.
2. [기록 상세 390](./audit-detail-390.png): 긴 기록 행을 누르면 원본 Task 상세가 열리고 닫으면 돌아보기로 복귀한다. 상세 제목 역시 마지막 글자가 다음 줄로 넘어간다. 이 동작은 mock에서 확인했으며 클릭 가능성이 사용자에게 명확한지는 관찰 조사 없이 단정할 수 없다.
3. [지난주 빈 상태 320](./audit-previous-320.png): 이전 주 이동과 이번 주 복귀는 동작한다. 이번 주 테두리의 좌우 여백이 거의 없어 글자가 눌려 보인다. 48px 터치 영역을 확보하는 기하 검사 통과는 테두리 안의 시각적 여백을 보장하지 않는다. 이전 화살표 테두리는 클릭 후 초점 표시다.
4. [연도 경계 320](./audit-year-320.png): `25.12.29–26.1.4`는 한 줄이지만 두 자리 연도와 붙은 구분자가 촘촘하다. 기하 검사에서 통과했어도 읽기 쉬움까지 통과한 것은 아니다.

## 추천 순서

1. **상단 탐색 보정:** 이번 주의 라벨 안쪽에 명시적인 여백을 확보한다. 날짜·화살표·버튼을 함께 배치해 320에서도 화면 가장자리와 닿지 않게 한다. 날짜 한 줄 선호, 의미가 분명한 연도, 44 이상의 조작 영역은 동시에 검토하고 수치 통과만으로 판정하지 않는다. 연도 경계와 확대 글자는 실제 화면으로 재확인한다.
2. **기록 읽기 보정:** 날짜가 긴 제목의 한 글자 줄바꿈을 만들지 않도록 날짜를 제목 아래에 두는 등 배치를 검토한다. 긴 제목의 첫 줄·다음 줄과 날짜의 시각 정렬, 여러 항목 사이 간격, 누를 수 있는지의 단서를 같은 화면에서 살핀다. 목표별 묶음, 실제 완료 제목·날짜, 전체 데이터의 의미는 유지한다.
3. **빈 상태와 화면 목적:** 현재 안내는 죄책감 없이 기록이 없음을 알리고 오늘으로 돌아갈 수 있다. 이전 주 빈 화면에서는 돌아보기에서 다른 주로 탐색하는 것과 오늘로 나가는 행동 중 무엇을 강조할지 검토한다. 선택된 목표별 실제 기록 구조는 유지하고 의미 있는 정보 구조 변경은 별도 시각안 선택 후 진행한다.

## 외부 비교와 한계

- [Apple 버튼 가이드](https://developer.apple.com/design/human-interface-guidelines/buttons)는 충분한 버튼 주변 공간과 44pt 조작 영역을 권장한다. 이 점에서 현 버튼은 조작 영역과 별개로 눈에 보이는 패딩이 부족하다.
- [Apple Calendar의 기간별 탐색](https://support.apple.com/en-lamr/guide/iphone/iphfd1054569/ios)과 [Todoist 완료 기록 안내](https://lp-regional-test.todoist.com/help/todoist/features/view-completed-tasks-in-todoist-J19h2s)를 공식 자료로 참고했다. 실제 서비스 앱을 조작하거나 그 앱의 글자·버튼 수치를 측정한 것은 아니다.
- 사용자에게 앞서 허용받은 로컬 Playwright와 Chrome mock Web을 사용했다. 캡처의 테스트 기록은 모두 목표 미연결이다. 여러 목표·장기간 다수 기록·실패·확대 글자·실제 스크린 리더·Android/iOS 실기기와 운영 API는 확인하지 않았다. 일부 320 캡처의 검은 번개는 Expo 개발 오버레이다.
