## 동작 계약

`/plan?goal=dday:1` 또는 `/plan?goal=goal:1`의 일회성 이동 의도를 계획에서 소비한 뒤 query param을 지운다. 같은 숫자의 다른 모델을 대신 열지 않는다. Task에 `linkedGoalId`가 있으면 새 Goal 연결을 우선하며 잘못된 명시 ID를 D-Day로 대체하지 않는다. 배열·0·음수·소수·안전 정수 밖·잘못된 접두사는 거부한다.

새 Goal 이름은 기존 Goal 상세 GET을 사용하고 색은 기존 계정/환경별 계획 설정을 읽는다. 이름/색을 못 읽어도 중립적인 이름/기본 색으로 탐색을 유지한다. 신규 API나 저장 계약은 필요하지 않다. 기존 D-Day 이름/색은 기존 동작을 유지한다.

연결 목표가 없으면 화살표/탐색 버튼 대신 `연결된 목표 없음`을 표시한다. 연결은 계속 더보기에서 관리한다. 계획의 대상 source가 로딩/오류이면 다른 목표를 보여주지 않고 기다림/재시도를 제공한다. 목록 로딩이 끝났는데 대상이 없거나 주소가 잘못되면 안내와 전체 목표를 보여주고 관계없는 목표 본문/선택 표시는 숨긴다. 캐시에 정확한 대상이 있다면 백그라운드 갱신 오류에도 그 목표로 이동할 수 있다.

계획의 폼/순서/연결 항목 편집 중에는 현재 입력을 보존하고 안내한다. 편집이 끝나면 보류한 목표 이동을 수행한다. 상세 자체의 작성/저장 중에는 기존처럼 경로 조작을 막는다. 완료 이후 수동으로 선택한 다른 목표를 과거 이동 의도가 다시 덮어쓰지 않는다.
