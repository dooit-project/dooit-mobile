# 달력 상단 추가 밀도 검토

2026-11-02 · Product Design 화면 검토 · 앱 코드 추가 변경 없음

1. [현재 달력 화면](./02-display.jpg): 월 탐색은 가운데로 정렬되어 있으나 로고와 월 제목의 시각적 간격을 더 줄일 여지는 있어 보인다. [원본 캡처](./01-current.jpg)는 Chrome 앱에서 열려 있던 mock Web 390×844 화면이다.
2. 코드 기준: 공통 헤더 최소 높이 48과 헤더 조작 영역 44, 달력 본문의 상단 패딩 0, 월 조작 버튼 44 및 오늘 버튼 48이 조합된다. 보이는 간격의 일부는 각 행의 조작 영역과 글자 여백이다. 별도 상단 패딩을 계속 줄이는 방법은 이미 남지 않았다.
3. 제안: 공통 헤더의 최소 높이를 48에서 44로 조정하는 보정을 먼저 같은 조건에서 시도할 수 있다. 기본 크기에서 월 행은 최대 4만큼 올라가지만 헤더 콘텐츠도 함께 중심 이동하므로 보이는 간격의 변화는 더 작을 수 있다. 모든 탭에 영향을 주므로 전후 화면과 큰 글자·safe area를 확인한다. 버튼 영역을 겹치거나 줄이는 방식은 피한다. 더 큰 변화가 필요하면 헤더와 월 탐색을 한 행으로 합치는 별도 구조 비교가 필요하다.

## 외부 참고와 한계

- [Google Calendar 안내](https://support.google.com/calendar/answer/6110849?co=GENIE.Platform%3DAndroid&hl=en)는 상단 월 이름을 통한 날짜 탐색을 설명한다. [Fantastical 안내](https://flexibits.com/fantastical-ios/help/calendar-views)는 날짜 선택과 일정의 연결을 설명한다. 문서로 기능 패턴을 참고했으며 실기기 앱을 직접 조작하거나 동일한 조건으로 간격을 측정한 것은 아니다.
- [Apple UI 디자인 안내](https://developer.apple.com/design/tips/)는 조작을 관련 콘텐츠 가까이 두고 최소 44pt 조작 영역을 확보하도록 안내한다. 특정 시각 간격 수치에 대한 근거는 아니다.
- 내장 브라우저·Chrome 확장 접근 호스트가 불가해 Chrome 앱에서 기존에 열린 mock 화면을 캡처했다. 서버 연결이 끊긴 상태이므로 이번에는 표시 중인 화면의 정적 검토다. 변경안은 아직 구현하거나 실제 비교하지 않았으며, DOM 기하 검사·글자 확대·스크린 리더·Android/iOS 실기기 검증은 미완료다.

캡처 자료에서 개인 브라우저 탭 정보가 포함된 상단 영역은 제거했다. 문서의 원본 캡처 링크는 이 정보가 제거된 기록이며, 잘리지 않은 파일은 로컬 임시 보관소에 보존했다.
