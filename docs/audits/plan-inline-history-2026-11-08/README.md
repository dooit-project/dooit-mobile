# 계획 화면의 최근 기록 구현

2026-11-08 · mock Web · Android/iOS/Web 공통 코드

후속 [재검토](../plan-inline-history-recheck-2026-11-08/README.md)에서 21개 기록의 화면 페이지 이동을 확인하고 키보드 초점 이탈을 수정했다. 아래의 최초 검증 범위는 당시 결과다.

## 원본과 범위

- 기준: 사용자가 선택한 [작은 중립 체크 시안](../../design/plan-inline-history-2026-11-07/proposal.png). 기존 목표 탭·목표 관리·하단 탐색을 유지한다.
- 이번 변경: 별도 기록 보기 버튼을 없애고 같은 목표의 계획 뒤에 최근 기록을 표시한다. 반복 계획의 시작 조건도 계획 행의 요일 옆에 표시한다. 이전 기록은 같은 화면에서 더 불러온다.
- 목표별 한 번 할 일·일정과 반복 계획의 통합 관리, Goal Task 전체 목록 API, 시스템 실행 결과의 선택 UI는 이 변경으로 완료된 것이 아니다.

## 동작과 데이터

- 새 Goal은 기존 여정 API에서 0100-01-01부터 오늘까지 실제 기록을 최신순 20개씩 조회하고, 최초 3개부터 같은 화면에서 3개씩 노출한다. 이후 페이지는 서버 cursor·여정 버전을 확인한다. 반복 cursor와 버전 불일치·요청 실패는 안내하고 재조회한다. 오류 시 오래된 목록을 정상 기록처럼 보여주지 않는다. 과거 날짜는 날짜 자체를 사용하며 계획한 분량을 실제 수행한 것으로 추정하지 않는다.
- API의 UNKNOWN 반복 회차는 당시 계획 이름과 ‘실천 내용 미확인’을 함께 보여준다. 이름에 계획 분량이 포함될 수 있으므로 이 라벨은 필수다. 실제 선택된 행동이 있는 회차는 그 행동을 사용한다.
- 기존 D-Day는 기존 목표 Task 조회를 재사용하며 완료된 일회성 항목을 상단 계획 목록에서 제외하고 기록에 한 번 표시한다. 반복 계획은 상단에 계속 남는다. 완료 시각이 없는 옛 항목은 계획 날짜를 완료 날짜로 대신 쓰지 않고 ‘날짜 미확인’으로 표시한다.
- 원본 Task가 있는 완료 기록은 행에서 상세를 열어 기존 완료 취소를 사용할 수 있다. 반복 회차와 직접 기록은 해당 Task 상세가 실천 결과를 정확히 대표한다고 가정하지 않고 읽기 전용으로 표시한다. 작은 체크는 상태 표시다.
- 기록이 없으면 기록 영역을 표시하지 않는다. 기존 목표의 진행 항목이 없을 때는 ‘연결된 항목이 없어요’라는 상충하는 안내 대신 항목 추가 행동을 유지한다. 완료/취소와 Task 수정·삭제 시 관련 여정 캐시를 갱신한다.

## 실제 확인

내장 브라우저 접근 호스트가 응답하지 않아, 사용자가 이전에 허용한 로컬 Playwright와 설치된 Chrome에서 `web:design` mock 데이터를 사용했다. 이전에 저장한 [구현 전 화면](./before-plan-390.png)과 선택 시안을 열고, 구현 후 새 화면을 확인했다. 전 화면 전체의 같은 데이터 비교가 아닌 기존 캡처와 새 테스트 데이터 비교다.

- [320](./compact-320.png) · [390](./compact-390.png) · [430](./compact-430.png): 목표, 반복 계획 두 개, 각 완료 기록 두 개를 확인했다. [기록 없음](./empty-390.png)과 [기존 목표의 완료 기록](./legacy-390.png)도 확인했다. 화면에 보이는 검은 번개는 개발 Web 도구 표시이며 앱 UI가 아니다.
- 반복 계획 네 개를 완료해 최초 세 개와 [이전 기록 펼침](./expanded-390.png)을 확인하고, 완료 취소 후 기록이 빠지는 것을 확인했다. 기존 목표의 일회성 할 일을 완료하면 위 계획에서 중복되지 않고 기록에 나타나며, 기록에서 상세를 열어 완료를 취소하면 계획에 돌아오는 것을 확인했다.
- `npm run check:ui-layout --`에 [320](./compact-layout-320.json)·[390](./compact-layout-390.json)·[430](./compact-layout-430.json)과 [기존 목표 390](./legacy-layout-390.json)의 새 DOM 좌표를 전달했다. 각각 6행/3조작 영역 및 3행/4조작 영역 기하 검사를 통과했다. 캡처에서 기록 체크와 두 줄 텍스트의 광학 정렬도 별도 확인했다.
- [더 보기 버튼 화면](./more-390.png)과 [좌표](./more-layout-390.json), 네 계획이 있는 [320](./layout-320.json)·[390](./layout-390.json)·[430](./layout-430.json)은 각각 10행/4조작 영역 기하 검사를 통과했다.
- cursor/버전 불일치, 반복 cursor, UNKNOWN 행동, 중복 원본, 날짜 미확인과 다음 페이지 요청은 단위 테스트로 확인했다. 20개를 넘어 서버의 다음 페이지를 여는 실제 UI, 요청 오류·재시도 화면, 운영 API, 접근성 도구, 확대 글자와 Android/iOS 실기기는 미확인이다.

## 검토 및 남은 차이

Product Design `image-to-code` 지침을 참고해 정확한 원본과 실제 공통 컴포넌트를 대조했다. 이 저장소의 기존 모바일 앱에 범위를 한정한 구현이며 Product Design의 별도 프로토타입·정식 `design-qa` 전체 절차는 실행하지 않았다. `better-layout`·`better-ui` 지침으로 계획과 기록의 묶음 및 아이콘 정렬을, `better-writing`·`better-accessibility` 지침으로 확인되지 않은 실천 내용과 조작 여부를 살폈다. `vercel-react-native-skills`는 기존 React Native 컴포넌트와 탐색을 재사용하는 기준으로 참고했다. 실제 스크린리더 검사나 독립 심사는 아니다.

시안의 새 Goal 일회성 일정/할 일 통합 목록과 목표 색상 서버 동기화는 아직 구현 범위 밖이다. 생성 시안에는 표시되지 않는 기존 기록의 ‘실천 내용 미확인’ 안내와 Task 상세 화살표는 사실성과 기존 완료 취소 경로를 유지하기 위해 추가했다. 전체 목표 기간 기록의 서버 조회 비용과 배포 상태도 확인하지 않았다.
