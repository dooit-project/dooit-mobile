## 구현 전 검토

Product Design index/audit, 검토 정책/구현 가이드와 기존 프론트엔드 자료 검토를 재사용한다. 저장된 별도 Product Design context는 없다. 새로운 외부 앱/Figma 검증을 주장하지 않는다. [긴 이름 비교](../long-goal-labels-2026-10-24/README.md)의 Todoist 상세 읽기/탐색 분리와 기존 Web 키보드/상태 원칙을 적용한다.

IAB가 없었던 기존 동일 Chrome 확장, localhost:8082, goal-lanes mock/light 상태를 이어 사용했다. [390 수정 전](./01-detail-before-390.jpg)을 이번에 저장 후 직접 열었다. 토익 시험 접수는 제목/날짜 정보 x36, 목표/기록 x30, 체크리스트/삭제는 화면 중앙에 있어 축이 불규칙하다. grouped Card가 padding16을 그대로 가지는 코드와 일치한다. 본문 바깥 x20을 기준으로 정렬하고, 공간은 섹션 간격으로 확보한다. 화면 필요성/위치는 유지하고 주 행동 수정·날짜/체크리스트는 직접 노출, 기록/삭제는 낮은 위계를 유지한다.

글자 확대/긴 이름에서는 고정 높이 대신 최소 높이와 줄바꿈이 필요하다. 터치44·초점·확장 상태를 유지하며 색/아이콘만으로 의미를 전달하지 않는다. native/dark/보조 기술은 실검증과 분리한다.

## 반영한 내용

- 개인 상세의 grouped Card와 grouped 체크리스트/날짜 영역에만 `padded={false}`를 전달했다. 공통 Card 기본값과 Workspace의 outlined 표현은 유지한다. 섹션 사이는 공통 24 간격으로 구분한다.
- 상태와 유형은 제목 위에 함께 두고, 제목은 전체 줄바꿈/heading이다. 일정/기록은 보조 label64 + 왼쪽 본문 값으로 정렬하고 첫 줄 baseline을 맞춘다. 제목/주 정보의 실제 시작점은 390px에서 x20이다.
- 체크리스트는 공통 AddItemRow를 재사용하고 grouped 항목 제목의 두 줄 제한을 해제했다. 체크리스트 개수는 실제 항목 완료 수이며 Goal 진척률과 다르다.
- 목표/기록/삭제는 공통 Button의 선택적 `contentAlignment="start"`로 배치한다. 기본 중앙 정렬·로딩/초점·이름/비활성 처리는 그대로다. 목표/기록에는 공통 chevron과 확장 상태를 함께 전달한다.
- 체크리스트 완료 도중 Web AX에서 아이콘/문구는 바뀌는데 체크 값이 0으로 남는 기존 누락을 발견했다. 공통 체크리스트의 `aria-checked`와 항목 행동 `aria-expanded`를 보완한 뒤 checked 1→0을 확인했다. 이 상태 전달은 공통 사용처에도 적용된다.
