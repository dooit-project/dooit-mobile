# 할 일 상세 초기 읽기 초점

2026-10-29 · R6 · 기준 `6b5fc84` 이후 작업 트리 · Chrome 확장 로컬 mock Web/light

- 대상/목적: 목록에서 상세를 열 때 읽기 시작 위치를 제공하고 닫기 버튼의 불필요한 첫 강조를 줄인다. [사용자가 선택한 상세 원본](../../design/task-detail-options-2026-10-24/05-context-panel-aligned.png)의 구조, 버튼, 목록 복귀는 유지한다. 변경은 Web의 초기 초점 위치에 한정하며 Android/iOS 화면 코드는 동일한 공통 컴포넌트에 영향을 받는다.
- Product Design audit. 기존 [WAI-ARIA 및 외부 패턴 검토](../task-detail-external-review-2026-10-25/README.md)의 대화상자 초기 초점·키보드 복귀 근거를 재사용했다. 경쟁 앱을 이번에 직접 조작하거나 실제 스크린 리더 접근성을 검증한 것은 아니다.
- [변경 전 390](./01-before.png): 포인터로 열어도 닫기 X에 강한 초점 경계가 나타난다. [변경 후 동일 390](./03-after.png): 정적 대화상자 자체에 초기 초점이 가고 경계는 없다. 콘텐츠·위치·목표 색·아이콘·문구는 유지한다.
- [키보드 조작](./04-keyboard.png): Tab으로 목표 경로부터 이동하고 닫기 버튼에 도달하면 테두리가 보인다. Escape는 상세를 닫고 원래 목록 항목으로 초점을 돌린다. 화면 읽기용 실제 음성 출력과 전체 키보드 순환·직접 URL은 별도 검증이 필요하다.
- 직전 미저장 문구 재점검: [체크리스트 입력 후 닫기](./02-checklist-confirm.png)에도 문구가 맞고 계속 작성 후 초안이 유지된다. 이전 감사의 전체 수정 취소 검증과 별개로 확인했다. 체크리스트의 실제 저장은 수행하지 않았다.
- [320](./05-after-320.png)·[390](./05-after-390.png)·[430](./05-after-430.png)×844 실제 좌표는 각각 5행/8조작 영역 통과. 한 줄 제목의 전체 텍스트 높이를 첫 줄 높이로 사용한 검사다. 긴 제목·글자 확대, 실제 Android/iOS·VoiceOver/TalkBack, 운영 API는 미확인이다.
