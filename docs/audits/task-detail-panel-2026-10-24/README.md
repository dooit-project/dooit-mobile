# 개인 할 일 상세 패널 구현·감사

2026-10-24 · `5e6463f` 이후 미커밋 working tree · Android/iOS/Web 공통 소스

## 범위와 구현 전 검토

원본은 [선택 패널05](../../design/task-detail-options-2026-10-24/05-context-panel-aligned.png)와 [확정 방향](../../design/task-detail-options-2026-10-24/RECOMMENDED_DIRECTION.md)이다. 직접 열고 Product Design image-to-code/critical overrides/design-qa, 저장소 기본 시각 검사를 적용했다. user-context preflight는 저장 context 없음으로 반환해 저장소 결정을 사용했다. 기존 [공식 서비스 비교](../task-detail-design-review-2026-10-24/README.md)를 재사용했으며 경쟁 앱/Figma를 새로 실행하지 않았다.

목적은 오늘/계획/달력의 맥락을 유지하면서 상세를 보고 체크한 뒤 돌아오는 것이다. 흰 바탕·목표색·작은 원형 체크·네 탭·현재 일정과 실행일의 별도 계약을 유지한다. 변경 범위는 기존 개인 Task 상세 표현과 조작 연결이다. Workspace·새 Goal 회차 상세·백엔드·새 탭은 범위 밖이다. 기존 선택안 구현이므로 새3안 비교를 반복하지 않았다.

## 구현과 경계

`/tasks/[taskId]`를 투명한 Stack 경로로 지정해 이전 화면을 남긴다. 앱 내 이전 경로가 있으면 공통 `DetailSheet`, 직접 진입이면 일반 `Screen`으로 같은 내용을 제공한다. [Expo의 투명 overlay 안내](https://docs.expo.dev/router/advanced/web-modals/)를 참고하고 설치된 SDK56의 옵션/타입을 확인했다. 새 의존성/템플릿/배포는 없다.

목표 경로/수정/더보기/닫기 → 제목/전체 체크 → 실제 일정 → 실행일 → 설명 → 체크리스트 순서다. 일정은 기존 수정 폼, 실행일은 펼치는 날짜 빠른 변경이며 실행일 이동으로 실제 시간이 바뀌지 않는다. 기록·기존 D-Day 연결·삭제 확인은 더보기로 묶었다. 상단 목표 경로는 현재 연결 관리로 연결하며 새 Goal 상세 연결을 구현한 것은 아니다. 하위 항목의 수정/순서/삭제는 작은 더보기에 보존했다.

공통 AppText/AppIcon/IconButton/Button/TaskForm/TaskChecklistSection/TaskDateQuickActions를 재사용한다. AddItemRow의 기존 기본값을 유지하면서 패널에 compact/primary 옵션을 사용한다. 그룹 체크리스트는 원형이며 설명/체크리스트가 없으면 빈 섹션을 만들지 않는다. 전체 완료 시 하위 항목을 완료하는 기존 mock 계약과, 전체 취소 후 하위 체크가 유지되는 응답을 그대로 표시한다. 하위 체크만으로 전체 완료를 자동 호출하지 않는다.

수정/삭제/실행일/완료/취소 후 D-Day 목록을 무효화한다. 완료/취소는 날짜 목록도 갱신한다. 계획 캐시 잔류 UX-14의 해당 Task 변경 경로를 다루며 5개 회귀 테스트로 QueryClient의 계획/달력 캐시 무효화를 확인했다. 운영·새 Goal 전체 캐시 검증은 아니다.

Web은 배경 inert, 패널 내 Tab 순환, Escape, 원래 누른 항목 초점 복귀를 제공한다. 작성 중 확인은 스크롤 밖에 남긴다. 설치된 SDK56의 `expo-router/react-navigation` 제거 방지 hook을 사용하고 새로고침/탭 닫기는 beforeunload 확인을 요청한다. [SDK58 전용 새 API](https://docs.expo.dev/router/advanced/prevent-screen-removal/)를 사용하지 않았다. Chrome Back/Forward는 [Navigation API](https://developer.mozilla.org/en-US/docs/Web/API/NavigateEvent)의 취소 가능한 traverse를 추가 처리한다. **Navigation API 미지원/취소 불가 traversal에는 이 보호가 적용되지 않는다.** 앱 닫기/Escape 보호와 구분한다.

## 시안 비교·수정 이력

[전체/부분 비교 보드](./14-source-comparison.jpg)를 직접 열었다. source853×1844를390×844 CSS로 정규화하고 실제390×844 캡처를1:1로 놓았다. source의 종횡비 반올림 차이 약0.4px는 완전 일치 판정에 쓰지 않는다. 아래 비교는 양쪽 y145부터280px이다. 원본/실제 이미지를 표시한 임시 HTML을 브라우저에서 캡처했고 임시 페이지는 제거했다.

- [초기01](./01-initial-390.jpg)의 아래로 밀린 시작/보조 행동 색을 P2로 보고 헤더·본문 시작 간격과 수정/추가 색을 수정했다.
- [동일 내용02](./02-content-390.jpg) → [보정03](./03-refined-390.jpg): 정보 행을48로 줄이고 체크리스트 축/원형/간격을 정리했다. 최종11/12/13에서 재확인했다.
- 초점 복귀 누락을 수정하고 오늘/계획/같은 제목이 여러 번 있는 달력에서 실제 누른 항목으로 돌아옴을 확인했다.
- 기존 hook만으로 Web Back에 입력이 보호되지 않아 취소 가능한 traverse 보호를 추가했다. Back → 확인 → 계속 작성/입력 유지와 명시적 닫기를 재검사했다.
- RN Web TextInput이 키 전파를 막는 문제는 capture로 보완했다. 하위 항목 입력 → Escape → 확인 → 계속 작성/값 유지 → 취소를 재검사했다.

### 필수 시각 기준

- 글자: 기존 시스템 폰트, 제목22/30·본문16/24·라벨13/18 유지. 긴 제목 줄바꿈/첫 줄 체크를 확인했다. 생성 폰트 획/안티앨리어싱 완전 복제는 아니다.
- 배치: 패널 시작84%, 정보 블록 전체 중앙, 본문 축20, 카드/구분선 없는 읽기 순서. 편집은 키보드/폼 공간을 위해96%로 확장한다.
- 색: 기존 primary/목표색/본문/보조 토큰과 파란 수정/추가, 회색 원을 확인했다. 새 정량 대비 계산은 수행하지 않았다.
- 자산: 실제 glyph/Feather/wordmark 사용. 화면을 이미지로 붙여 구현하지 않았다. 래스터 신규 자산은 없다.
- 문구: 목표/제목/일정/설명/하위 항목은 source와 같다. 배경 문구는 기존 순환 기능의 다른 영어 문장이다. 저자/가짜 성과/진척률은 추가하지 않았다.

남은 P3는 정보 행 간격 수px, 라이브러리 glyph/폰트 획, 추가 행의 최소44px 공간이다. 작은 체크리스트 더보기는 편집·순서·삭제 보존을 위한 의도적인 차이다. 배경 헤더는 승인된56px 기준을 유지하며 source의 큰 상단 공백을 복제하지 않는다. 현재 검증 범위에 남은 P0/P1/P2는 없다.
