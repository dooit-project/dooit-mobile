# Dooit 전체 UI/UX 감사

2026-10-21 · Product Design combined audit · 대상 commit `ddde85b` (`origin/main` 푸시 확인)

## 결론

네 개 하단 탭과 목표별 계획 구조는 유지한다. 다음 우선순위는 **계획한 반복이 오늘에 나타나고, 완료한 일이 같은 목표의 기록으로 이어지는 흐름**이다. 공통 색·글자 크기를 또 일괄 변경하기보다 달력·상세·폼의 정보 밀도와 목적지·상태 전달을 고친다. 시각 보정과 핵심 기능 연결의 완료 여부를 구분한다.

이번에는 앱 코드를 수정하지 않고 수정 목록과 실행 순서를 정리했다. 감사 이후 새 구현·추가 커밋/푸시는 아직 하지 않았다.

## 범위와 증거

- 환경: Expo Web / mock / Chrome 확장 / light / 주로 390×844, 계획·회원가입은 320×844 추가 확인.
- 브라우저: 기존 로컬 앱 탭의 목표·반복 상태를 그대로 사용했다. 이전 세션에서 내장 브라우저가 제공되지 않아 Chrome으로 전환한 사유를 유지한다. 보조 화면은 별도 mock 탭에서 촬영했으므로 서로 다른 탭의 데이터가 이어진다고 가정하지 않았다.
- 데이터: 기존 새 Goal 두 개·반복 계획 두 개를 직접 확인했다. 이번 감사에서 일반 할 일 ‘토익 문제 30개 풀기’를 빠른 작성 → 기록함 → 오늘 이동 → 완료 → 주간 기록/검색까지 조작했다. 실제 계정·개인 일정 데이터는 사용하지 않았다.
- 도구: Product Design index/audit/user-context와 design-audit-framework를 읽고 적용했다. preflight에는 저장 컨텍스트가 없었다. CUA로 DOM·실제 화면·일부 키보드 동작을 확인했다. Figma는 사용하지 않았다.
- 시각 목표: 선택된 [계획 최종안](../../design/plan-navigation-2026-10-15/05-goal-tabs-polished.png)과 [공통 UI 기준](../../design/VISUAL_SYSTEM_ALIGNMENT_2026-10-21.md). 생성 시안은 현재 실행 증거로 사용하지 않는다.
- **이번 감사에서 새로 저장하고 직접 열어 확인한 PNG 33개**만 실제 화면 증거다. [전체 화면 기록](./SCREENS.md)에 순서대로 둔다. 좌하단 번개 모양의 개발 서버 표시는 제품 UI로 평가하지 않는다.
- 관찰한 브라우저 console error는 없다. 자동 검증은 커밋 전 `npm run validate` 112 suites / 584 tests 통과(STG integration 1개 제외)이며, 감사 후 문서 변경 검증과 구분한다.

## 화면 역할과 위치 판단

| 위치             | 판단                      | 유지/개선 이유                                                                                                                |
| ---------------- | ------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 오늘             | 유지                      | 목표를 정리하는 화면이 아니라 지금 할 일과 회차를 체크하는 화면. 큰 ‘오늘’ 제목·상시 날짜·주 달력을 다시 넣지 않는다.         |
| 달력             | 하단 두 번째 유지         | 날짜별 일과 시험·신청 같은 약속을 바로 찾는 진입이다. 접근성보다 현재 달력 내부 밀도와 탐색 단위가 문제다.                    |
| 계획             | 하단 세 번째·목표 탭 유지 | 목표·기한·반복 정의·연결 항목을 만들고 수정한다. 오늘과 같은 실행 체크 목록으로 만들지 않는다.                                |
| 돌아보기         | 유지                      | 일주일간 무엇을 했는지 확인하는 목적지가 필요하다. 숫자 외에 Goal 회차/직접 기록을 실제 여정으로 이어야 한다.                 |
| Drawer           | 보조 도구로 유지          | 검색·기록함·정리·계정/설정에 적합하다. ‘더보기’를 하단 탭으로 복원할 이유는 발견하지 못했다.                                  |
| 템플릿·공유 공간 | 보조 위치 유지            | 자동 반복과 템플릿 복사는 다른 기능이다. 초기 핵심 흐름에서 더 강조하지 않는다. 공유 공간 내부는 게스트 제한 때문에 미검토다. |
| 계정/설정        | 필요                      | 게스트 데이터 보관과 문구/알림 선택을 제공한다. 계정만 하단 탭이 모두 비선택인 보조 화면 규칙은 정리할 수 있다.               |

탭 순서를 바꿀 만큼의 사용 빈도 근거는 없다. 현재 순서는 선택된 시안과 일치하므로 유지하고, 핵심 흐름을 완성한 뒤 실제 사용 빈도로 재평가한다. 이는 설계 판단이며 사용자 조사 결과는 아니다.

## 유지할 강점

- 새 목표는 날짜를 필수로 요구하지 않고 ‘바라는 변화/중요한 이유’를 선택적으로 펼친다. 32·33에서 확인했으며 큰 꿈을 성과 목표로 강제 변환하지 않는 방향을 유지한다.

- 계획·오늘·달력·돌아보기의 역할과 하단 직접 진입. ‘더보기’가 주요 탭을 차지하지 않는다.
- 제목/날짜를 중복으로 크게 표시하지 않는 오늘, 목표색과 선택선을 쓰는 계획, 저자 줄 없이 작은 문구를 두는 헤더.
- 일정 입력에서 알림/반복 같은 추가 정보를 접는 방식, 검색의 필터/초기화, 변경 취소·이전 화면 복귀.
- 별도 타이머·점수·Goal 퍼센트·강제 AI 호출이 없어 체크와 실제 기록에 집중할 수 있다.
- 실제 확인한 달력 이전 주 터치 영역 44×44, Drawer Escape 닫기와 열기 버튼 초점 복귀. 모든 터치/키보드 동작을 검사했다는 뜻은 아니다.

## 공식 패턴과의 비교

2026-10-21 직접 확인했다. 서비스 앱을 로그인해 사용한 비교 감사가 아니라 공식 문서 참고다.

- [Things의 일정 지정](https://culturedcode.com/things/support/articles/2803579/): 오늘·미래·언젠가를 날짜/실행 준비도로 구분한다. Dooit도 오늘의 실행과 계획의 정의를 나누되 저장 목적지가 사용자 의도와 일치해야 한다. 이 패턴을 그대로 복사해 새 목록을 늘리지는 않는다.
- [Todoist Today 안내](https://www.todoist.com/help/todoist/get-started/plan-your-day-with-the-today-view-UVUXaiSs): 여러 프로젝트의 오늘 항목을 모으고 그룹화한다. Goal별 오늘 회차가 실제로 모이는 것이 시각 장식보다 우선이다. 해당 문서는 2026-08-28 갱신으로 표시됐다.
- [Material 구버전 하단 탐색](https://m1.material.io/components/bottom-navigation.html): 자주 접근하는 상위 목적지를 직접 노출하고 선택을 구분한다. 네 주요 탭 유지 판단에만 참고했으며 최신 높이/아이콘 크기 사양으로 사용하지 않았다.
- [W3C Target Size Minimum](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html): WCAG 2.5.8 최소 기준과 저장소의 44 터치 목표는 별개다. 현재 44 내부 목표를 낮출 이유로 쓰지 않는다. 보조 기술 선택 상태와 키보드 검증도 별도로 필요하다.
- Apple Tab bars는 검색 결과의 상위 목적지 설명만 확인했고 본문은 JS/Markdown 도구 제한으로 읽지 못했다. Todoist의 잘못된/이전 URL 한 개도 열리지 않았다. 이들을 직접 읽은 상세 근거처럼 인용하지 않는다.

## 권장 실행 순서와 완료 조건

1. **확정 API로 핵심 루프 연결**: UX-01·02·07. 단, QA-01을 먼저 고쳐 자정 이후의 테스트/캡처 날짜를 신뢰할 수 있게 한다. 계획 하나 → 오늘 체크 → 동일 목표의 이번 주 증거 → 취소/작은 행동/휴식이 실제 데이터로 이어져야 한다. Goal 전체 Task 목록은 G-07과 분리한다.
2. **빠른 작성·상세·오류·선택 상태 정리**: UX-03·05·06·08. 목적지 명확화, 부분 성공 재시도, 빈 정보 축소, 필드 오류 초점, Web 선택 상태를 같은 사용자 흐름에서 마무리한다.
3. **달력 밀도·탐색 개선**: UX-04. 일정이 있는 날/없는 날, 날짜 이동/복귀를 같은 너비에서 비교하고 선택일 항목을 빠르게 볼 수 있는지 확인한다.
4. **보조 화면의 일관성 보정**: UX-09–13. 목표 전환·검색 범위·카피·계정·브랜드/카드 패턴을 정리한다.

새 화면/정보 구조의 의미 있는 선택은 먼저 시각안 세 개를 비교한다. 기존 선택 시안 안의 국소 보정은 그 안을 유지한다. 개선 후 정상·빈 상태·오류·복구를 새로 캡처하고 `npm run validate` 및 영향 플랫폼 결과를 남긴다. 이번 감사만으로 새 UI 구현을 승인/완료 처리하지 않는다.

## 검증 한계

새 목표 기본/선택 변화 입력은 32·33에서 추가 확인했다. 공개 `/start`와 기능 둘러보기의 완전한 신규 계정 onboarding은 이번 실행에서 재현하지 않았다. ‘전체’는 핵심·보조 화면군에 대한 감사 범위를 뜻하며 모든 경로/상태 검증 완료를 뜻하지 않는다. 이전 문서의 Today 주간 strip·더보기 허브 설명은 현재 화면과 달라 UX_REVIEW_LOG를 최신 결정·위험 위주로 정리했다.

문서·캡처 추가 후 `npm run validate`도 통과했다(112 suites / 584 tests, STG integration 1개 제외). 이것은 이번 수정 목록이 구현됐다는 뜻이 아니다.

실제 Android/iOS·safe area·모바일 키보드·글자 확대 1.5·dark 화면·VoiceOver/TalkBack·대량 목록·네트워크 실패·실제 계정/동기화/알림은 미검증이다. 공유 공간은 게스트 제한 입구만 확인했고 구성원·권한/초대 흐름은 범위 밖이다. 개발 진단 카드는 `__DEV__` 조건임을 코드로 확인해 운영 화면 결함으로 분류하지 않았다. 로그인·가입·재설정은 화면만 확인하고 제출하지 않았다.

목표 탭 DOM은 role=tab, aria-selected 없음, 상위 두 단계에 tablist 없음이었다. 선택된 월요일 버튼도 aria-selected/pressed/checked가 없었다. 스크린리더가 실제 무엇을 읽는지는 미검증이다. 비활성 탭 내용이 DOM snapshot에 남는 현상만으로 보조 기술에 노출된다고 단정하지 않는다. Escape 직후의 애니메이션 중간 snapshot은 닫힘 판정에 사용하지 않고 안정화 후 열기 버튼의 초점 복귀를 확인했다.
