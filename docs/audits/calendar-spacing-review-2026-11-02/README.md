# 달력 상단 간격 재검토

2026-11-02 · Product Design audit · 화면 검토만 수행, 앱 코드 추가 변경 없음

## 대상과 결과

1. 달력 진입: [현재 390×844 실제 화면](./02-calendar-crop.png)에서 공통 로고 행과 월 이동 행이 시각적으로 멀어 보인다. 월 제목·화살표·오늘 버튼은 하나의 행으로 읽힌다. 사용자에게 보여주는 캡처는 [원본](./01-calendar.png)을 브라우저 주변만 잘라낸 것이다.
2. 코드 검토: 공통 헤더는 최소 56, 달력 본문은 상단 8, 월 조작은 44~48 높이의 조작 영역을 갖는다. 로고와 제목 글자 자체가 그 영역 안에서 가운데 정렬되어 있어 실제 보이는 간격은 본문 상단 8보다 크다. 8만 줄였던 지난 조정의 체감이 작았던 이유다. 온보딩 안내가 닫히면 해당 컴포넌트는 null을 반환한다.
3. 제안: 먼저 공통 헤더 높이·내부 정렬과 본문 상단 여백을 함께 측정하고, 시각적인 간격을 줄이는 작은 보정을 같은 390 화면에서 비교한다. 조작 영역 44 이상, 월 제목의 가운데 정렬, 오늘 버튼의 위치와 열린 안내 상태를 유지한다. 공통 헤더를 바꾸면 다른 탭에도 영향을 주므로 함께 비교해 결정한다. 숫자는 실제 화면 비교 전 확정하지 않는다.

## 참고와 범위

- [Google Calendar 커뮤니티의 월간/일정 화면 이미지](https://support.google.com/calendar/thread/383709023/trying-to-go-back-to-default-monthly-view?hl=en)를 검색 결과로 확인했다. 월 탐색과 달력을 가까이 배치하는 화면 참고이며 직접 앱 조작이나 정확한 간격 측정은 아니다.
- [Fantastical 공식 달력 안내](https://flexibits.com/fantastical-ios/help/calendar-views)는 월 이동과 아래 일정의 연결을 설명한다. 이 안내는 동작 참고이며 두 앱의 간격을 동일 조건에서 측정한 근거는 아니다.
- [Apple UI 디자인 가이드](https://developer.apple.com/design/tips/)의 가까운 콘텐츠와 조작, 최소 44pt 터치 영역을 참고했다. 특정 간격을 규정하는 근거는 아니다.
- 내장 브라우저와 Chrome 확장 접근 호스트를 사용할 수 없어 Chrome 앱의 반응형 모드에서 기존 로컬 mock 화면을 캡처했다. Metro 연결이 끊어진 상태라 이번에는 현재 로드된 화면의 시각적 정적 검토만 수행했다. 외부 앱 직접 조작, 실제 DOM 좌표, 확대 글자, 스크린 리더 및 Android/iOS 실기기 확인은 하지 않았다. 화면 변경 후 새로 캡처하고 필수 기하 검사를 수행해야 한다.

캡처 자료에서 개인 브라우저 탭 정보가 포함된 상단 영역은 제거했다. 문서의 원본 캡처 링크는 이 정보가 제거된 기록이며, 잘리지 않은 파일은 로컬 임시 보관소에 보존했다.
