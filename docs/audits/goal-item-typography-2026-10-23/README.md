# 목표 제목과 항목 글자·행 정렬

2026-10-23 · `f1f07be` 이후 working tree · 미커밋

후속 사용자 지적을 반영해 계획 목록의 첫 줄 정렬은 [두 줄 전체 블록 중앙 정렬](../item-optical-alignment-2026-10-23/README.md)로 대체했다. 아래 첫 줄 정렬 수치/캡처는 해당 초기 구현 이력이다. 오늘 체크의 첫 줄 정렬과 글자 위계는 유지한다.

## 이번 단위

- 원본: [사용자 첨부 시안](../../design/goal-lanes-correction-2026-10-21/reference.png)을 직접 열고 제목/본문/보조, 첫 줄과 체크의 관계를 확인했다. 계획 탐색 구조는 [기존 선택안](../../design/plan-navigation-2026-10-15/README.md)을 유지한다.
- 유지: 흰 바탕·목표 레일·마커·원형 체크·작은 문구·4탭·추가 버튼·목표/항목 문구·기존 저장 동작. 새로운 카드나 구분선은 넣지 않는다.
- 변경: 오늘/계획의 목표 제목 18/26 공통 역할, 제목 16/24와 보조 13/18의 공통 ItemCopy, 체크/유형 아이콘의 첫 제목 줄 정렬. 계획 목록 행은 오늘과 같은 최소 64로 정리한다.
- 범위 밖: 전역 글자 축소·상세/작성/달력/돌아보기·버튼 위계·목표 탭 노출 문제·새 Goal 회차 연결·백엔드/API.
- 완료 조건: 같은 390×844·mock·문구/완료 상태의 실제 전후, 좁은 화면, 긴 문구, 완료/상세 이름·주요 조작과 필수 validate. 미확인 native/확대/오류는 별도 표기한다.
- 도구/근거: Product Design index/audit 기준, 기존 검토에서 읽은 [Apple Typography](https://developer.apple.com/kr/design/human-interface-guidelines/typography)와 [추가 프론트엔드 자료 기록](../../design/VISUAL_COHESION_REVIEW_2026-10-22.md), 앞선 작업에서 확인한 [IBM icon/text 정렬](https://www.ibm.com/design/language/iconography/ui-icons/usage/) 원칙을 재사용한다. 새 Figma/외부 앱 조작을 한 것은 아니다. 구조 선택이 아닌 기존 선택안의 보정이다.

## 구현과 실제 비교

공통 `AppText.sectionTitle` 18/26과 `ItemCopy`(제목 16/24, 보조 13/18, 간격 4)를 오늘/기존 목표 목록/새 반복 계획 목록에 연결했다. 계획의 목표일도 보조 역할로 바꿨다. `ItemLeading`은 유형 그림을 첫 제목 줄 중앙에 두며, 오늘 체크는 44 이상 터치 영역을 유지하고 본문 위 여백을 첫 줄 기준으로 계산한다. 글자 확대 조건은 fontScale을 사용하지만 실제 확대 검증 완료를 뜻하지 않는다. 같은 역할을 재사용하며 전역 title/display 크기는 바꾸지 않았다.

모든 캡처를 저장하고 직접 열어 source/실제 전후를 비교했다. 04는 긴 문구 검증과 완료/취소 이후에도 원래 데이터/순서·390·메뉴 닫힘과 열기 버튼 초점 상태를 복원해 재촬영했다. 제목/설명을 원문으로 다시 저장한 뒤 design fixture를 새로 로딩해 완료·순서도 기본 상태로 복구했다. 상태 변경은 로컬 mock에서 UI로만 수행했다. 브라우저 evaluate는 DOM 위치/크기/이름 측정에만 사용했다. 갱신 중 DOM 조회가 한 번 지연돼 동일 tab의 AX로 복구했으며 다른 브라우저나 Playwright CLI로 전환하지 않았다.

### 새로 발견한 기능 과제

긴 제목을 저장한 뒤 Today/상세에는 새 내용이 보이지만 이미 열린 계획의 기존 D-Day 목록에는 예전 제목이 남았다. 현재 `useUpdateTask`는 `taskQueryKeys.all`만 무효화하며 D-Day 목록은 별도 query key를 사용한다. 캐시 갱신 누락 가능성을 후속 UX-14로 기록한다. 실제 서버 재현까지 완료한 판정은 아니다. 07은 긴 제목 계획 검증 근거가 아니며, 새 Goal 반복 계획의 실데이터 편집 상태도 이번 Web run에서는 확인하지 않았다. 독립적인 기능 변경이므로 이 스타일 단위에 캐시 수정을 섞지 않는다.

## 검증과 남은 차이

- `npm run validate` 통과: 114 suites / 591 tests, STG 1개 제외. 타입/린트/포맷/문서/정적 release 검사 포함. 단순 시각 수치를 복제하는 새 테스트는 추가하지 않았다.
- 새 공통 컴포넌트는 Android/iOS/Web에 영향이 있다. 실제 확인은 Web light 320/390/430이며 native·fontScale 1.5·dark·VoiceOver/TalkBack·운영 API·조회/완료 실패 복구는 미확인이다.
- 내용/완료/상세 버튼의 접근성 이름은 유지했다. 새 컴포넌트는 완료 취소가 가능한 checkbox와 상세 이동 버튼을 대체하지 않고 본문만 공유한다.
- 새 Goal 반복 계획 목록은 같은 컴포넌트/타입 검사에 포함되지만 해당 실제 폼/상태 화면의 별도 감사는 남았다. 달력/돌아보기·인증/설정의 글자 역할과 버튼 위계도 후속이다.
- 선택 원본의 큰 상단 공백이나 이미지 폰트 자체를 복제하지 않는다. 흰 바탕·레일·작은 헤더와 명시된 글자/행 역할을 기준으로 보정한 범위이며 앱 전체 디자인/기능 완료가 아니다.
