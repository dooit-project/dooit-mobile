# 공통 헤더와 달력 상단 간격 보정

2026-11-02 · Product Design 검토 후 실제 Web 화면 확인

- 원본: [달력 선택 보정](../../design/calendar-navigation-2026-10-30/04-refined.png)과 [상단 여백 재검토](../calendar-spacing-review-2026-11-02/README.md). 월 제목 중앙 정렬과 오늘 버튼, 조작 영역과 네 탭을 유지한다. 여백 보정만 적용하며 달력 구조나 동작은 바꾸지 않는다.
- 공통 `PlannerHeader`의 최소 높이를 56에서 48로 낮추고 상하 패딩을 제거했다. 헤더 항목의 44 크기와 safe area는 유지하며 큰 글자로 내용이 늘면 최소 높이보다 커질 수 있다. 달력 본문의 상단 8 패딩도 제거해 기본 크기에서 월 조작 행이 16만큼 위로 이동한다. 공통 헤더의 변경은 네 탭 모두에 적용된다.
- 동일한 Chrome mock Web 390×844의 [달력 전](./01-before.jpg)과 [후](./03-after-390.jpg), [오늘 전](./02-today-before.jpg)과 [후](./04-today-after.jpg)를 비교했다. [사용자 표시용](./07-display.jpg)은 변경 후 캡처의 앱 영역이다. 달력의 월 제목과 화살표 정렬 및 메뉴·로고·문구의 시각적 중심을 확인했다. 빈 데이터와 기본 글자 크기 조건이다.
- [320](./05-after-320.jpg), [430](./06-after-430.jpg) 달력도 육안 확인했고 390에서 다음 달과 오늘 복귀를 조작했다. 첫 이용 안내는 변경 전 닫고 전후 동일 조건으로 비교했으며 안내가 표시된 상태는 변경 후 따로 확인하지 못했다. 계획·돌아보기의 실제 화면과 긴 문구는 미확인이다.
- 참고: 이전 [Google Calendar·Fantastical·Apple 안내 비교](../calendar-spacing-review-2026-11-02/README.md). 외부 서비스 직접 조작은 아니다.
- 내장 브라우저·Chrome 확장의 접근 호스트가 사용 불가해 Chrome 앱과 DevTools 반응형 모드를 사용했다. 콘솔을 통한 DOM 보고서 수집에 실패해 새 `check:ui-layout`은 미실행이다. 확대 글자, 실제 터치, 키보드·스크린 리더 및 Android/iOS 실기기도 미확인이다. 자동 기하 검사와 native 확인 전 최종 시각 QA는 pending이다.

캡처 자료에서 개인 브라우저 탭 정보가 포함된 상단 영역은 제거했다. 문서의 원본 캡처 링크는 이 정보가 제거된 기록이며, 잘리지 않은 파일은 로컬 임시 보관소에 보존했다.
