# 오늘 화면의 항목이 적을 때 점검

2026-11-04 · 대상 커밋 `1c637b5` · mock Web · 디자인 검토만 수행

## 대상과 방법

사용자가 선택한 [목표별 오늘 시안](../../design/goal-lanes-correction-2026-10-21/reference.png)과 현재 화면을 비교했다. 이번 [실제 390×844 캡처](./02-today.png)는 목표 하나와 반복 계획 하나를 직접 생성한 mock 게스트다. 시안은 두 목표와 다섯 항목의 생성 이미지이므로 데이터와 해상도가 다른 화면을 같은 조건의 구현 검증이라고 판단하지 않는다.

Product Design `audit` 프레임워크를 읽고 현재 캡처의 정보 위계·행동·접근성 위험을 검토했다. 내장 브라우저와 Chrome 확장의 접근 호스트가 없어 기존에 사용자가 허용한 로컬 Playwright와 headless Chrome으로 캡처했다. 실제 서비스는 직접 조작하지 않았으며 공식 설명 자료를 참고했다.

## 발견과 제안

1. **반복 행동의 맥락 누락 — 높음.** 계획은 30개와 최소 3개인데 오늘은 3개만 표시된다. 매일 반복되는지, 평소 목표인지 작은 버전인지 알기 어렵다. 시안에 있던 보조 정보도 없는 상태다. 기본 행동과 실제 선택한 최소 행동을 분명히 구분하고, 저장된 반복 주기·시작 조건이 있을 때만 한 줄로 보조 표시한다. 수행량을 추정하거나 고정 문구를 만들지 않는다.
2. **밀도와 하단 행동 — 중간.** 한 행으로 대부분의 공간이 비고, 하단 고정 추가 버튼이 목록에서 떨어져 보인다. 이것은 한 항목이라는 데이터 조건과 목록 말미 고정 위치의 조합으로 보인다. 카드·일러스트로 임의로 채우기보다 할 일 추가를 목록 끝 가까이 배치하는 안과 기존 하단 고정 안을 적은/많은 항목, 키보드·작은 화면에서 비교한다. 위치 변경은 아직 확정하지 않았다.
3. **서체와 레일의 관계 — 중간.** 현재 한 줄 행은 목표에 비해 정보가 적고 연한 레일만 길게 남는다. 행 간격·체크와 제목의 시각적 중심·보조 텍스트 대비를 공통 컴포넌트에서 확인하며 시안의 목표별 레일과 체크 구조를 유지한다. 기기나 확대 글자에서의 판정은 별도 확인이 필요하다.
4. **완료 기록과 목표의 연결 — 높음.** [완료 후 돌아보기](./04-review.png)는 새 Goal이 아닌 ‘일상의 기록’으로 표시된다. 시각적 여백보다 목표를 향한 행동을 일관되게 확인할 수 없는 기능 문제다. F4에서 실제 회차/여정 계약을 확인해 처리한다.

[Things Today](https://culturedcode.com/things/support/articles/4001304/)는 당일 할 일을 모으고 목록이 길 때 프로젝트별 그룹을 제공한다. [Todoist Today](https://www.todoist.com/help/todoist/get-started/plan-your-day-with-the-today-view-UVUXaiSs)도 프로젝트별 그룹과 완료 항목 표시를 설명한다. 이는 목표 묶음을 유지할 근거이며 버튼 위치나 시각적 완성도를 직접 비교한 결과는 아니다. [Apple의 목록 가이드](https://developer.apple.com/kr/design/human-interface-guidelines/lists-and-tables)는 짧고 읽기 쉬운 항목 텍스트와 그룹 간 여백을 설명한다. 이 자료를 토대로 한 제안은 설계 판단이며 사용자 실험 결과가 아니다.

## 범위와 한계

계획 생성 → 오늘 → 완료 → 돌아보기 → 취소의 mock 흐름을 확인했다. 여러 목표·긴 제목·시간/시작 조건이 들어간 동일 데이터의 비교, 실제 스크린 리더와 글자 확대, 키보드, Android/iOS 및 운영 API는 이번 감사에서 확인하지 않았다. 흰 여백이 많다는 사실만으로 빈 상태 안내를 추가하지 않는다. 새로운 UI는 아직 구현하지 않았고, 기본/최소 선택과 목표별 기록은 기존 로드맵 미완료로 남는다.
