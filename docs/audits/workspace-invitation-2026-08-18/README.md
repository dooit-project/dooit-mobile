# Workspace 초대 흐름 UI/UX 점검

- 점검일: 2026-08-18
- 대상: ToDoLab Web mock 390×844
- 흐름: PENDING 초대 확인 → 초대 수락 → 참여 공간 확인

## 결론

초대받은 공간과 현재 참여 중인 공간이 분리되어 행동 우선순위가 분명하다. 긴 한국어 공간 이름과 설명도 강제 개행이나 말줄임 없이 자연스럽게 읽히며, 수락 직후 같은 화면에서 참여 공간으로 전환된다.

## 단계별 결과

| 단계 | 화면                             | 상태 | 판단                                                                                       |
| ---- | -------------------------------- | ---- | ------------------------------------------------------------------------------------------ |
| 1    | [받은 초대](./01-invitation.jpg) | 양호 | 권한과 초대일이 보조 정보로 구분되고, 긴 이름·설명은 의미 단위로 자연스럽게 줄바꿈된다.    |
| 2    | [수락 완료](./02-accepted.jpg)   | 양호 | 초대 카드가 사라지고 같은 공간이 `참여 중인 공간`으로 즉시 전환되어 결과를 확인할 수 있다. |

## 적용한 보완

- 초대가 있으면서 참여 공간은 없는 상태를 `참여 중인 공간이 없어요`로 명확히 표현했다.
- 빈 상태 설명에 초대 수락과 새 공간 생성이라는 두 진입 경로를 함께 안내했다.
- 초대 수락 버튼에 공간 이름을 포함한 접근성 라벨과 진행 중 상태를 적용했다.

## 확인 한계

- Web mock 캡처를 기준으로 했으며 iOS·Android의 네이티브 글꼴 차이는 포함하지 않는다.
- 스크린샷으로 실제 VoiceOver·TalkBack 읽기 순서와 글자 크기 확대 상태를 확정할 수 없다.
