# 최근 기록 재검토

2026-11-08 · 계획 화면의 목표별 최근 기록 · 테스트 게스트와 mock Web

## 발견과 수정

1. **키보드 초점 이탈:** 마지막 기록을 펼칠 때 ‘이전 기록 더 보기’가 사라져 초점이 `body`로 이동했다. 남은 기록이 없어지면 같은 버튼을 ‘기록 접기’로 전환해 초점을 유지하도록 수정했다. 다시 접으면 세 기록과 ‘이전 기록 더 보기’가 돌아온다. [펼친 화면](./expanded-390.png)에서 초점 경계와 아이콘 정렬을 확인했다.
2. **기록이 많은 경우:** UI로 반복 계획과 완료 21개를 만들어 같은 화면에서 3→6→9→12→15→18→20→21개로 펼쳤다. 20개를 넘어 서버 cursor 다음 페이지를 요청했으며, 표시된 이름이 21개 모두 서로 다른 것을 확인했다. [마지막 기록 화면](./21-records-390.png)은 목록 아래로 스크롤한 상태다.
3. 네 개의 기록에서 펼치기와 접기를 Enter로 조작하며 두 상태 모두 버튼에 초점이 남는지 확인했다. 완료 취소 후 기록이 빠지는 것도 확인했다. 빈 목록과 세 기록, [더 보기](./more-390.png)는 mock에서 다시 확인했다.

## 검토와 범위

내장 브라우저 호스트 연결이 실패해 사용자가 앞서 허용한 로컬 Playwright와 Chrome을 사용했다. 기존 사용자 데이터가 아닌 테스트 게스트다. Product Design `audit`의 실제 캡처·흐름 검토를 적용하고 `better-accessibility` 지침으로 키보드 초점, `better-layout`·`better-ui` 지침으로 화면의 밀도와 아이콘 정렬을 확인했다. [기준 시안](../../design/plan-inline-history-2026-11-07/proposal.png), 기존 [구현 감사](../plan-inline-history-2026-11-08/README.md), 새 캡처를 비교했다. 외부 앱을 새로 조작하거나 스크린리더·실제 native 앱을 검증한 것은 아니다.

새 DOM 측정으로 [320](./layout-320.json)·[390](./layout-390.json)·[430](./layout-430.json)과 [더 보기 390](./more-layout-390.json)은 각각 10행/4조작 영역, [접기 390](./expanded-layout-390.json)은 10행/3조작 영역 기하 검사를 통과했다. 확인된 캡처의 그림 중심도 별도로 살폈다. 검은 번개는 Expo 개발 도구 표시다.

오류·재시도 및 409 충돌 화면, 운영 API, Android/iOS 실기기, 글자 확대와 스크린리더는 직접 확인하지 않았다. cursor 반복·버전 불일치는 단위 테스트 범위다. 시안의 새 Goal 일회성 항목 통합은 여전히 별도 작업이다.
