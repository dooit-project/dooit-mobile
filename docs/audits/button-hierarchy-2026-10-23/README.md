Product Design index/audit와 [공통 구현 가이드](../../design/DESIGN_IMPLEMENTATION_GUIDE.md)를 따른다. 앞서 읽은 [Apple Typography 및 외부 프론트엔드 자료](../../design/VISUAL_COHESION_REVIEW_2026-10-22.md)의 역할별 글자·읽기·상태/접근성 기준을 재사용한다. 새로운 구조 선택이 아닌 기존 공통 컴포넌트 보정이다. 새 Figma/외부 앱 조작은 없다. 기존 IAB 부재로 CUA Chrome 확장의 같은 localhost:8082 design fixture를 사용했다.

구현 전 저장 버튼은 44 높이/1px 테두리이며, 초점에서 테두리가 2px로 바뀐다. loading 분기는 라벨을 제거하고 spinner만 렌더링하므로 내용으로 폭이 정해지는 버튼에서 폭이 바뀔 수 있다. 폼의 저장/취소가 모두 유색 면이라 시각 위계가 약하다. 실제 수정 후 결과와 한계는 아래에 기록한다.

캡처는 모두 이번 run에서 저장하고 각각 직접 열었다. 최종 tab error 로그 0. 브라우저 evaluate는 DOM 크기/초점 측정에만 사용했다. 실제 로딩 화면을 지연시켜 캡처한 것은 아니다. `Button`은 기존 내용의 공간을 유지하고 spinner를 겹치며 문자열 버튼의 접근성 이름을 명시한다. 컴포넌트 회귀 테스트로 loading 전환 시 라벨·접근성 이름·선택 상태 유지, busy/disabled와 해제 후 복구를 확인했다. 브라우저 로딩 중 폭의 실측이나 native 스크린리더 검증을 대신하지 않는다.

기존 RN 0.85 타입에서 지원하지 않는 absoluteFillObject 사용을 명시적인 절대 위치 값으로 고쳤다. 테스트의 Pressable 타입 조회도 실제 테스트 렌더링 경계에 맞춰 button 역할로 바꿔 최종 재실행했다. 새 의존성은 없다.

## 결과와 경계

- `npm run validate` 통과: 115 suites / 592 tests, STG 1개 제외. 타입/린트/포맷/문서/정적 release 검사 포함.
- Android/iOS/Web의 공통 Button 소비처에 영향이 있다. 실제 시각 검증은 Web light의 목표 작성/개인 상세/편집과 320/390/430에 한정한다. 모든 버튼 소비 화면을 전수 검사했다고 표현하지 않는다.
- 반복 계획 취소는 ghost로 바꿨지만 해당 실데이터 화면·상태를 이번 run에서 별도 감사하지 않았다. 실제 로딩 화면·실패 응답·native·fontScale 1.5·dark·VoiceOver/TalkBack은 미확인이다.
- IconButton/AddItemRow/개별 Pressable과 기존 클릭/키보드 초점 표시 방식은 유지했다. 사용자가 정한 목표 레일·체크·계획 아이콘 블록 중앙 정렬을 바꾸지 않았다. 목표 선택 탭 노출/선택 상태, 상세 정보 축과 UX-14 캐시는 후속이다.
