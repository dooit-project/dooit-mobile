## 실제 환경

이번에는 CUA inventory에서 Chrome 확장 연결이 복구됐다. IAB는 inventory에 없어서 기존 Chrome 비교 tab을 이어 사용했다. 종료된 localhost 서버는 같은 주소의 Expo mock fixture 서버로 복구했다. 이번 감사는 **Chrome 확장으로 실행**했으며 앞선 전체 감사의 Playwright 임시 브라우저와 구분한다.

- Expo Web / light / mock `goal-lanes` 개발 fixture / localhost:8082.
- 기존 D-Day/Task 두 목표·다섯 항목, 새 Goal 전체 실행 흐름의 증거가 아님.
- 390×844 기본, 320×844·430×844·1024×844 추가. 캡처 파일을 직접 열어 확인했다.
- 브라우저 evaluate는 문서 폭·DOM rect·초점 위치를 읽는 용도로만 사용했다. 데이터/설정은 UI로 조작했다.
- CUA가 반환한 JPEG 바이트에 맞춰 새 캡처 확장자를 `.jpg`로 기록했다. 원본 이미지 픽셀은 편집하지 않았다.

## 시각 비교 판정과 차이

같은 두 목표·다섯 항목·완료 상태·`One step, your pace.`로 이전 실제/최종 실제/사용자 원본을 함께 열어 비교했다. 원본 생성 이미지의 큰 상단 공백은 사용자 결정에 따라 복제하지 않고 실제 기본 헤더/간격으로 보정했다. 로고 글꼴의 완전 일치와 앱 전체 완성도를 선언하지 않는다. [390px 배치 비교 HTML](./comparison.html)도 기록했으나 browser의 file URL 정책으로 렌더하지 못했다. 이를 새 비교 보드 캡처로 제시하지 않으며, 로컬 원본 이미지들을 직접 열어 비교한 범위로 기록한다.

이번 범위의 헤더 정렬과 문구 잘림 문제는 수정했다. 남은 VC-02 전역 글자/색/아이콘/행/버튼, VC-03 목표 탭 선택 노출 등은 [로드맵](../../product/ROADMAP.md) 후속 단위다. 큰 틀을 보존하는 구현 시작점과 프롬프트는 [가이드](../../design/DESIGN_IMPLEMENTATION_GUIDE.md)에 고정하고 AGENTS에 연결했다.

## 검증과 한계

- Android/iOS/Web 공통 코드 영향. 실제 확인은 Web light이며 native safe area·font scale 1.5·dark·VoiceOver/TalkBack·실제 API는 미확인이다.
- 56은 최소 높이이며 고정 높이/글자 자동 축소를 추가하지 않았다. fontScale > 1에서는 문구의 줄 제한을 해제했다. 실제 큰 글자 화면은 별도 native 확인이 필요하다.
- 설정의 이전 긴 문구 복원 시 모드 보존과 숨김 유지에 회귀 테스트 두 개를 추가했다. 시각 스타일 값을 복제하는 테스트는 만들지 않았다.
- 최종 코드에서 `npm run validate` 통과: typecheck/lint/format/docs/정적 release 검사와 114 suites / 591 tests, STG 1개 제외. `git diff --check` 통과. 최종 실제 tab의 error 로그 0이며 모든 warning/네트워크 검사를 뜻하지 않는다. 검사 통과는 이번 단위에 한정하며 전체 디자인 감사의 미완료 항목을 완료로 바꾸지 않는다.

final result: passed (공통 헤더·Today 간격·헤더 문구 범위, 실제 Web 확인)
