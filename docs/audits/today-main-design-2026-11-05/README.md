## 확인한 화면과 범위

Product Design의 audit 관점(다음 행동·정보 위계·상태·접근성 위험)을 적용했다. 내장 브라우저/Chrome 확장 접근 호스트가 없어 사용자가 기존에 허용한 로컬 Playwright/headless Chrome, 390×844에서 게스트로 조작했다. [빈 화면](./01-multiple.png), 목표 하나에 매일 반복 계획 두 개를 직접 만든 [오늘](./02-today.png), [완료](./03-done.png), [돌아보기](./04-review.png), 완료 취소를 확인했다. 빈 화면 파일명은 캡처 당시 이름이며 여러 목표 화면이 아니다. 여러 목표 fixture는 게스트 시작에서 빈 데이터로 나타나 여러 목표 동작은 확인하지 못했다. Expo 개발 도구 아이콘은 개발용 표시다.

[선택된 시안](../../design/goal-lanes-correction-2026-10-21/reference.png)은 두 목표·다섯 행동이어서 이번 실제 화면과 데이터 수가 다르다. 시안의 구조와 시각 언어를 비교했으며 픽셀 일치 판정은 하지 않았다.

## 디자인 판단과 제안

1. **계획의 기준 행동이 사라짐 — 높음.** 두 행 모두 기본 행동이 아니라 작은 행동으로 만들어져 있다. 목표로 하던 양을 알 수 없어 회차의 의미와 다르게 보인다. 평소 행동을 기본으로 보여주고 사용자가 작은 행동을 선택했을 때만 명시적으로 전환하는 방향을 제안한다. 현재 API 결과와 연결 Task·돌아보기의 실제 표시를 함께 맞춰야 한다.
2. **메인 화면의 정보 밀도와 위계 — 중간.** 항목 두 개가 왼쪽 위에 밀집하고 넓은 빈 영역 끝에 추가 버튼이 떨어져 있다. 추가 버튼을 목록 끝으로 배치하는 안과 하단 고정 안을 같은 한 개·여러 개·긴 목록 조건에서 비교한다. 접근성과 빠른 추가를 함께 평가하고 선택 전 위치 변경을 확정하지 않는다. 장식을 채우기 위한 별도 카드·임의 숫자는 권장하지 않는다.
3. **목표·행의 시각적 완성도 — 중간.** 현재 목표 제목·할 일·보조 문구의 크기 차이와 간격이 작게 느껴지며 반복되는 보조 문구가 단조롭다. 기존 ItemCopy와 색 토큰 안에서 390px 실화면 기준 제목, 행 높이, 체크 중심, 보조 문구 대비를 조정하고 320/430·긴 제목·글자 확대도 점검한다. 시안의 목표색 레일과 체크 구조를 유지한다.
4. **헤더의 역할 — 중간.** 로고와 문장이 같은 줄에서 작게 붙어 있으며 메뉴와 목록 사이 연결이 약하다. 로고·메뉴·짧은 문구의 기준선과 좌우 여백을 조정하고, 긴 문구는 자연스럽게 처리한다. 사용자가 원한 작은 문구를 유지하고 새 큰 제목·날짜·명언 카드는 추가하지 않는다.
5. **빈 화면과 완료 화면 — 중간.** [빈 화면](./01-multiple.png)은 안내 문장과 추가 버튼이 멀다. 최초 시작·오늘 일정 없음·모두 완료를 구분하고 실제 상황에 맞는 짧은 안내와 한 가지 다음 행동을 제안한다. 완료 메시지는 실제 기록에만 근거하고 휴식을 실패로 보지 않는다.

## 기능상 남은 문제

- 반복 행동은 현재 작은 버전만 보이고 일반 체크가 UNKNOWN 결과를 저장한다. 기본/작은 행동 선택, 휴식·되돌리기 및 오류·중복 제출·충돌 처리가 필요하다.
- 이번 [돌아보기](./04-review.png)는 목표 이름 대신 ‘일상의 기록’에 들어간다. 실제 목표의 여정과 연결하고 중복 집계·기록의 사실성을 검증해야 한다.
- 다음 행동 저장, 새로운 Goal 아래 일회성 할 일과 일정 연결, 목표에서 계획으로 자연스러운 이동은 별도 흐름으로 확인해야 한다. 이번 감사에서 기능이 없다고 단정할 수 없는 항목은 미확인이다.

## 자료와 한계

[Things Today](https://culturedcode.com/things/support/articles/4001304/)는 당일 반복·일정과 프로젝트 그룹을 설명한다. [Todoist Today](https://www.todoist.com/help/todoist/get-started/plan-your-day-with-the-today-view-UVUXaiSs)는 날짜가 잡힌 항목과 프로젝트별 그룹을 설명한다. [TickTick 기능 안내](https://ticktick.com/features)는 반복 항목과 습관 기록을 안내한다. 공식 자료를 읽은 것이며 타 앱을 직접 조작하거나 디자인 품질을 점수화한 비교가 아니다. 제안은 설계 판단이며 사용자 실험으로 검증되지 않았다.

실제 운영 API, 여러 목표·긴 목록·긴 문구, 320/430 전체 상태, 다크 모드, Android/iOS, 확대 글자와 보조 기술은 이번 감사에서 확인하지 못했다. UI 구현·변경은 이 감사에서 수행하지 않았다.
