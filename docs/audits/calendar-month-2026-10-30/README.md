# 월간 달력 구현 검토

2026-10-30 · 기준 `bba7f60` 이후 작업 트리 · Chrome 확장, 로컬 mock Web/light

- 정확한 선택 원본은 [2번](../../design/calendar-navigation-2026-10-30/02.png), 사용자 동의에 따른 밀도·오늘 복귀 보정은 [04](../../design/calendar-navigation-2026-10-30/04-refined.png)다. 선택한 월간 그리드·월 이동·선택일 목록을 사용한다. 생성 이미지의 항목·완료 체크 모양을 전역 승인으로 해석하지 않고 기존 TaskCard/ScheduleCard를 유지한다.
- [Google Calendar Android 공식 안내](https://support.google.com/calendar/answer/6110849?co=GENIE.Platform%3DAndroid&hl=en)의 월 탐색·날짜 선택·오늘 복귀를 참고했다. 실제 다른 앱을 직접 조작한 검증은 아니다. Product Design 참고 시안과 구현 후 실제 화면을 구분한다.
- 기존 월 날짜 계산과 여러 날 막대·하루 일정 레이블을 재사용한다. 빈 주의 공간은 줄이되 내용이 있으면 기존 일정 레인이 높이를 차지한다. 이전/다음 달은 선택일을 가능한 범위에서 유지하며 말일을 넘으면 해당 월 마지막 날짜로 조정한다. 기존 월 선택기와 새로운 오늘 복귀, 선택일 제목은 날짜 문맥을 제공한다.
- 실제 Chrome mock: 10월에서 다음 달로 이동해 11월 30일을 선택하고 빈 목록을 확인한 뒤 오늘로 돌아왔다. [320](./screen-320.png)·[390](./screen-390.png)·[430](./screen-430.png) 캡처와 헤더 각 1행/4조작 좌표 검사 통과. 초기에는 주 높이 때문에 목록이 가려져 빈 레인 최소 높이를 줄여 재확인했다.
- 원본 이미지와 실제 캡처는 선택한 시각 목표와 구현 현황을 비교한 것이며 같은 fixture나 픽셀 일치 판정은 아니다. 실제 목록은 기존 카드/체크 모양, 날짜 선택 표시와 일정 레이블을 유지하여 보정 이미지와 다르다. 여러 날 일정의 실제 화면·6주 달력·많은 일정·좁은 날짜 셀의 터치 영역·native·스크린 리더·확대·운영 API는 미확인이다. 기본 탭과 Today는 변경하지 않았다.

## 10월 30일 재검토

- 실제 Web 320px에서 날짜 버튼이 36.42×44px인 문제를 발견했다. 좁은 화면에서만 달력 좌우 공간을 넓히고 Web의 스크롤바 표시를 숨겨 날짜 버튼 45.42×44px, 문서 폭 320px을 확인했다. 일반 폭과 native의 스크롤바 표시 설정은 유지한다. 시각적 스크롤 표시가 없는 좁은 Web에서는 화면을 밀어 스크롤해야 한다.
- 2026년 11월의 6주 그리드와 11월 30일 선택·빈 목록을 실제 Web에서 확인했다. 여러 날 일정 테스트용 별도 mock 서버를 띄웠으나 브라우저 연결 중단과 별도 게스트의 빈 데이터로 해당 일정의 실제 화면은 확인하지 못했다. 단위 테스트는 실제 화면 확인을 대체하지 않는다.
