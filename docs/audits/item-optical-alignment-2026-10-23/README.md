## 측정과 이전 판정 정정

Product Design audit 기준과 앞선 [IBM icon/text 정렬 참고](https://www.ibm.com/design/language/iconography/ui-icons/usage/)를 재사용했다. 직접 확인한 CUA Chrome 확장의 기존 localhost:8082 design fixture를 사용한다. IAB가 없었던 같은 Chrome session이며 다른 browser surface로 바꾸지 않았다. 새 Figma/외부 앱/Playwright CLI를 사용한 것은 아니다.

수정 전 첫 항목의 텍스트 블록은 y=201/h46, 제목은 y=201/h24, 아이콘 slot도 y=201/h24다. 제목 중앙 213에는 맞지만 블록 중앙 224보다 11px 높다. 캡처를 분석용 PNG로만 변환해 실제 어두운 획 범위도 비교했다. 반복/문서/달력 그림과 제목 획의 상하 중앙은 각각 212.5/280.5/348.5로 일치했다. 그러므로 아이콘 glyph 자체의 일률적인 offset 문제가 아니라 **제목 한 줄만 정렬 기준으로 선택한 문제**다.

앞선 ‘첫 줄 중앙에 맞췄다’는 측정은 맞지만 이를 사용자가 원하는 시각적 중앙 정렬 완료로 답한 판단은 부적절했다. [이전 감사](../goal-item-typography-2026-10-23/README.md)의 계획 첫 줄 정렬 결정은 이번 보정으로 대체한다. 오늘 원형 체크와 계획 유형 그림에 같은 정렬 기준을 강제하지 않는다. 기기별 glyph 여백 자체가 모두 같다고 주장하지 않는다.

캡처는 저장 후 각각 직접 열어 비교했다. 390 측정은 slot의 중심과 실제 획을 구분했으며 native 글꼴까지 일치한다고 표현하지 않는다. 별도 데이터 변경 없이 같은 로컬 mock을 유지했다. 검사 후 기존 토익 목표로 복귀하고 viewport override를 해제했다. 최종 tab error 로그 0.

새 Goal 반복 계획 행도 동일한 가운데 정렬로 바꿨지만 해당 실데이터 화면은 이번 run에서 별도 검증하지 않았다. 긴 제목/보조 줄바꿈, fontScale 1.5, dark, Android/iOS 실기기, VoiceOver/TalkBack, 실제 API/실패 상태는 이번 재보정에서는 미확인이다. 앞선 Task/계획 캐시 갱신 과제 UX-14도 미완료다. 정보 구조·버튼/행 높이를 다시 바꾸지 않았다.

`npm run validate` 재실행 통과: 114 suites / 591 tests, STG 1개 제외. 타입/린트/포맷/문서/정적 release 검사 포함. 스타일 값을 복제하는 새 테스트는 추가하지 않았다. Android/iOS/Web 공통 영향이며 실제 시각 확인은 Web light에 한정한다.
