# Task 편집 버튼 밀도 재감사

이번 단위: 기존 알림·반복 표현 보정의 누락을 재평가하고 새 노출 구조를 비교한다. 원본은 이번에 직접 촬영한 아래 두 실제 화면이다. 유지할 것은 기본 입력·목표 경로·흰 편집 패널·저장/dirty·사용자 선택 중앙 확인이다. 변경 대상은 기본 요약과 설정 선택지의 노출 시점이다. 앱 코드/백엔드/전역 시각 언어는 이번에 바꾸지 않는다. 완료 조건은 실제 문제 확인, 선택 가능한 세 시안과 우선순위 기록이다. 구현은 시안 선택 후 진행한다.

Product Design index/audit/get-context/ideate와 저장소 정책을 적용했다. user-context preflight는 저장 항목 없음이다. 기존 IAB 접근 실패로 쓰던 Chrome 확장 browser1을 그대로 이어 localhost8082/mock goal-lanes/light/390×844에서 새 탭으로 캡처했다. 다른 browser surface/local Playwright로 전환하지 않았다. Figma/경쟁 앱 직접 로그인 조작은 하지 않았다.

## 단계와 판정

1. [기본 편집 진입](./01-basic-390.jpg) — 조건부 양호. 제목/유형/날짜/시각/저장은 구분되지만 알림·반복의 현재 값은 접힌 추가 정보에서 읽을 수 없다. 빈 값인지 설정된 값인지 바로 알기 어렵다.
2. [추가 정보→직접 반복 펼침](./02-expanded-390.jpg) — 수정 필요, 높은 우선순위. 알림7·반복5·직접 단위3개가 동시에 보이고 간격 입력까지 붙는다. 설정 하나를 바꾸려는 작업에 세 그룹이 경쟁하고 기본 제목/일정과 저장이 스크롤 밖으로 밀린다. 칩 테두리·색 변경만으로 해결되지 않았다. 캡처는 실제 스크롤된 viewport이며 잘린 위/아래 내용이 사라진 구현을 뜻하지 않는다.

두 파일을 직접 열어 실제 캡처 상태와390×844 크기를 확인했다. 선택은 저장하지 않았다. 기존 검토는 선택 상태·키보드·색 일관성에 집중하고 여러 선택지를 동시에 보여주는 문제를 범위 밖으로 둔 판단 오류가 있었다. 제한된 자동 검사 통과를 화면 전체의 사용성·완성도 통과로 설명하면 안 된다. 이전 감사의 좁은 기능 검사 사실은 유지하되 전체 디자인은 통과가 아니다.

## 외부 패턴과 적용 판단

2026-10-26 공식 안내를 다시 직접 읽었다.

- [Microsoft To Do](https://support.microsoft.com/en-gb/todo/add-due-dates-and-reminders-in-microsoft-to-do?nochrome=true): 상세에서 알림/반복 속성을 선택한 뒤 관련 선택지를 연다. 기능 분리뿐 아니라 편집 시점의 분리를 Dooit 판단에 반영한다.
- [Todoist 반복 날짜](https://www.todoist.com/help/todoist/features/introduction-to-recurring-dates-YUYVJJAV): 날짜 scheduler 안에서 Repeat 메뉴와 custom 반복을 제공한다. 여러 속성의 모든 preset을 같은 기본 폼에 노출해야 하는 것은 아니다.

위는 공식 사용 문서 비교이며 실제 경쟁 앱의 현재 픽셀/조작 감사가 아니다. 요약 행 추천은 Dooit 맥락의 설계 판단이며 사용자 테스트 결과가 아니다. [이전 편집 감사](../edit-surfaces-review-2026-10-25/README.md)에서도 속성 요약과 필요할 때 편집을 제안했지만 표현 보정만 진행하며 해결을 닫지 못했다.

## 권장과 후속

[세 독립 생성 시안](../../design/task-form-density-2026-10-26/README.md)을 실제 캡처 두 개를 첨부해 만들었다. 기본 화면에서 현재 값만 보여주는 두 속성 행을 우선 추천한다. 선택 시 관련 목록을 여는 추가 탭은 들지만, 설정 상태가 보이고15개 선택의 동시 노출을 없앤다. 행별 inline 펼침/별도 설정 화면도 비용과 함께 비교한다. 기존 유형3개는 자주 쓰는 단일 그룹으로 유지하되, 선택 후 전체 화면을 다시 평가한다.

새 구조의 미확인: picker의 Back/초점/초안·스크롤 복원, custom 오류·종일 전환, native safe area/키보드·font scale1.5/스크린 리더·dark·운영 API. 생성 이미지로 동작이나 접근성 통과를 주장하지 않는다. 구현 후 같은 상태 실제 캡처와 `check:ui-layout`, 필수 validate를 수행한다.

이번에는 새 앱 코드/새 테스트를 추가하지 않고 문서·비교 시안만 추가했다. 전체 `npm run validate` 재실행은126 suites /674 tests 통과, opt-in STG1개 제외다. 로그 `/private/tmp/dooit-task-form-density-20261026.log`. 이는 기존 코드 회귀의 근거이며 버튼 밀도를 해소했거나 새 시안이 작동한다는 증거가 아니다. 검토용 직접 반복은 저장하지 않고 반복 없음으로 복원한 뒤 Today 복귀와 원래 항목 초점을 확인했다. viewport override도 해제했다. 미커밋/미푸시.
