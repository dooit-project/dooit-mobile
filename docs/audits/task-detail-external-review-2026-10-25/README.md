후속 상태2026-10-25: 기존 점검/구현은 `5fc024d`까지 커밋·푸시했다. [R1 목표 탐색 수정과 새 감사](../task-goal-navigation-2026-10-25/README.md)를 진행했으며 해당 새 변경은 미커밋이다. 아래는 수정 전 감사의 관찰 기록이고 R2–R6은 남아 있다.

## 범위와 결론

사용자 요청에 따라 선택05로 구현한 개인 Task 상세와 연결 흐름을 UX/시각/접근성 관점에서 다시 점검했다. **선택된 큰 틀과 아이콘 정렬은 유지한다. 예상 동작과 실제 연결 사이의 P2 문제를 먼저 보완한다.** 이전 시안 정합성/기능 검사 통과를 전체 UX 승인으로 확대하지 않는다. 이번에 실제로 재현된 아래 문제는 해당 후속 수정 전까지 열려 있다.

Product Design audit/critical overrides/design-audit-framework, 저장소 구현 가이드/기본 시각 검사를 적용했다. user-context preflight는 저장 context 없음이었다. 외부 앱을 설치/로그인하거나 Figma를 열지 않았다. 경쟁 제품은 공식 사용 안내·공식 구현 가이드의 자료 조사이며 Dooit의 실제 감사와 구분한다.

현재 browser inventory는 Chrome 확장만 제공했다. 기존 Chrome 연결을 이어서 localhost8082의 새 탭에서 실제 흐름을 새로 캡처했다. IAB/Playwright 전환은 없다. Web mock/goal-lanes fixture, light, 기본 글자 배율,390×844 및320×844다. 오늘/실행일은 실제 화면의 **2026-10-25**이며24일 옛 캡처를 이번 증거로 사용하지 않는다. 기준 시안05는 구조 참조다. 데이터 추가/저장/연결 변경/영구 삭제는 하지 않았다.

## 우선순위별 발견 사항

### R1 · P2 · 목표 탐색처럼 보이는 경로가 연결 관리로 이동

근거: 단계2→3. `토익 900점 받기 >`를 누르면 목표 전체 계획이 아니라 연결/해제 버튼이 표시된다. 접근성 이름은 현재 동작을 설명하지만 시각적 경로가 약속하는 탐색과는 다르다.

추천: **상단 경로 → 계획 탭의 해당 목표 선택/내용**, 연결 변경 → 더보기의 목표 연결 관리로 분리한다. 새 목표 화면을 더 만들지 않고 기존 계획을 사용한다. D-Day와 새 Goal ID를 구분하고, 현재 목표를 정확히 선택하는 프론트 연결이 필요하다. 현재 Task 연결 범위를 새 Goal 완료/여정 구현으로 오인하지 않는다.

### R2 · P2 · 더보기로 인해 본문 위치가 이동

근거: 단계2→4. 새 DOM 실측에서 제목 첫 줄 y 차이는164px다. 단순한 세 관리 행동을 보기 위해 읽던 내용이 이동하고, 화면 오른쪽의 떠 있는 텍스트 열이 상세 정보와 섞인다.

추천: 기존 더보기 버튼 아래의 **작은 고정 위치 팝오버**로 묶고 본문 위치를 유지한다. 기록·목표 연결 관리·삭제 순서는 유지한다. 바깥 누름/Escape는 우선 메뉴를 닫고 초점을 더보기로 돌린다. 배경 패널 전체 닫기와 메뉴 닫기를 구분한다.320px에서도 메뉴/터치 영역이 잘리지 않아야 한다.

### R3 · P2 · 변경하지 않았는데 버리기 확인이 뜸

근거: 단계5에서 어떤 값도 바꾸지 않은 채 닫기를 눌렀는데 단계6 확인이 표시됐다. 현재 `isEditing`만으로 미저장 상태를 판단한다. 보관할 변경이 없는데도 경고/판단을 요구한다.

추천: **초기 값과 현재 값의 실제 차이**로 dirty를 계산한다. 수정→원문 복원도 확인 없이 닫고, 실제 변경/작성 중 요청은 보호한다. 전체 수정/체크리스트/반복 범위/새로고침·Back의 경계도 같은 기준으로 검사한다. 화면 모드만으로 버리기 확인을 만들지 않는다.

### R4 · P2 · 날짜/시간 변경의 범위가 과함

근거: 단계2의 일정 행을 누르면 단계5의 전체 수정 폼과 제목 자동 초점이 열린다. 의도한 일정 날짜·시작·종료를 찾기 전에 관계없는 제목/유형이 먼저 나온다.

추천: 일정 행에는 **일정 날짜·시작·종료·종일에 집중한 편집**을 제공하고 상단 수정은 전체 수정으로 유지한다. 실행일은 별도 계약이므로 합치지 않는다. 단순한 TaskUpsert에서 생략값이 지워질 수 있으므로 현재 제목/설명/반복/알림 등을 보존하는 요청 구성이 필요하다. 표현만으로 백엔드 신규 API가 필수인 것은 아니다. 새 선택기 구조에 의미 있는 대안이 생기면 정책에 따라 시각 비교 후 구현한다.

### R5 · P2 · 손잡이의 시각적 약속과 동작 불일치

근거: 단계2에서 위 손잡이를 아래로 드래그해도 패널 높이/닫힘이 바뀌지 않았다. Web에서는 헤더 텍스트 선택만 남았다. 코드에도 손잡이 gesture 연결이 없다. native 드래그 결과는 확인하지 않았다.

추천: 선택 시안의 손잡이를 유지하려면 **손잡이 영역에서 아래로 끌어 닫기**를 연결하고 작성 보호를 그대로 적용한다. 본문 스크롤/체크/키보드와 충돌하지 않게 한다. 제공하지 않을 경우 손잡이를 숨기는 편이 정직하지만 이는 선택 시안의 보정 판단으로 기록해야 한다. 닫기 X/뒤로가기 대체 조작은 유지한다.

### R6 · P3 · 첫 진입부터 닫기 버튼에 강한 테두리

근거: 단계2는 포인터로 항목을 열었는데 닫기 X가 자동 초점을 받아 큰 검은 테두리로 강조됐다. 키보드 상태의 가시성 자체는 필요하지만 첫 읽기에서 제목보다 시선을 끄는 비용이 있다.

추천: 처음에는 제목/패널 시작의 읽기 위치로 초점을 보내고, Tab 이동 시 조작 버튼에 명확한 초점 표시를 유지한다. **접근성 초점 표시를 전부 제거하는 방식은 사용하지 않는다.** VoiceOver/TalkBack 검증은 별도다.

## 외부 패턴과 적용 판단

확인일2026-10-25. 아래는 출처의 실제 내용과 Dooit에 대한 설계 판단을 구분한 것이다.

- [Todoist 공식 Task view](https://www.todoist.com/help/todoist/features/use-the-task-view-to-manage-tasks-in-todoist-eDeRDO0C): 상단 breadcrumb는 프로젝트/섹션 탐색, 날짜 필드는 날짜·시간·duration 편집, 상단 메뉴는 기록/삭제 등 관리다. R1/R2/R4의 역할 구분 근거로 사용했다. Todoist가 Dooit의 패널 높이나 세부 모양을 그대로 쓴다는 주장은 하지 않는다. 공식 모바일 이미지 링크는 가져오기 오류로 열리지 않아 시각 비교 근거에 포함하지 않았다.
- [Things 공식 Scheduling](https://culturedcode.com/things/support/articles/2803579/): 할 일의 날짜 표시에서 When picker를 열며 시작 시점과 deadline을 구분한다. Dooit의 실행일/실제 일정과 동일한 모델은 아니지만, 서로 다른 날짜의 의미를 유지하고 해당 필드에 집중한 조작을 제공한다는 판단을 뒷받침한다.
- [Material 공식 Android BottomSheet](https://github.com/material-components/material-components-android/blob/master/docs/components/BottomSheet.md): drag handle은 선택 요소이고 draggable behavior는 별도 속성이다. 따라서 ‘손잡이는 반드시 있어야 한다’가 아니라 실제 제공하는 gesture와 일치해야 한다는 R5의 근거로 사용했다. Dooit에 라이브러리/Material 시각 체계를 추가하지 않았다.
- [W3C APG modal dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/): 내부 초점/Tab 순환/Escape/호출 요소 복귀와 콘텐츠에 맞는 초기 초점 선택을 설명한다. R6과 이번 실제 키보드 검사 기준으로 사용했다. 전체 WCAG 준수를 선언하지 않는다.

## 유지할 부분·검증 한계

유지: 목록 맥락을 남기는 패널, 목표와 할 일의 위계, 작은 원형 체크, 일정/실행일 구분, 없는 설명/체크리스트의 빈 틀 생략, 흰 바탕·작은 헤더·네 탭. 아이콘을 다시 전역 이동하거나 페이지 구조를 바꿀 근거는 없다.

새 실제390/320 좌표는 각각4행/8조작 영역으로 `check:ui-layout` 통과했다. Tab/Escape/원래 항목 복귀와 최종 console error0을 확인했다. 실제 Android/iOS·화면 읽기·글자 확대·키보드/safe area·dark·저장 오류·여러 브라우저 Back·전체 앱 모든 화면은 이번 감사 범위가 아니다. 동기부여 문구/AI/목표 API의 전체 제품 철학 구현 여부를 이 국소 감사로 완료 처리하지 않는다.

이번에는 코드를 바꾸지 않았다. 추천 구현 순서는 **R1 목표 경로 → R2 메뉴 → R3 dirty 판단 → R4 일정 편집 → R5 손잡이 → R6 초기 초점**이다. 이 보완을 일반 목록 긴 제목 작업보다 먼저 진행한다. P2가 남은 상태를 전체 UX 승인으로 표시하지 않는다. 커밋/푸시는 하지 않았다.
