# Workspace 반응형·키보드 UI/UX 점검

- 점검일: 2026-08-19
- 대상: ToDoLab Web mock의 Workspace 상세
- 사용자 목표: 작은 화면과 키보드에서도 공유 일정·D-Day·멤버 탭을 구분하고 이동하기

## 결론

320px·390px·430px에서 탭, 핵심 행동, 빈 상태와 멤버 카드가 가로로 넘치거나 잘리지 않았다. 키보드 `Tab`으로 다음 탭에 포커스가 이동하고 `Enter`로 해당 탭을 열 수 있으며, 선택 상태와 포커스 외곽선도 서로 구분된다.

## 단계별 결과

| 단계 | 화면                                                   | 상태 | 판단                                                                                                      |
| ---- | ------------------------------------------------------ | ---- | --------------------------------------------------------------------------------------------------------- |
| 1    | [320px 일정 탭](./01-workspace-task-320.jpg)           | 양호 | 가장 좁은 기준에서도 세 탭과 `일정 추가`가 한 줄을 유지하고, 빈 상태 설명이 자연스럽게 줄바꿈된다.        |

## 확인한 항목

- 320px·390px·430px에서 horizontal overflow, 탭 문구 잘림, 고립된 마지막 줄이 없다.
- 탭은 `tablist`와 `tab` 역할을 제공하고 현재 선택 탭 상태를 노출한다.
- 키보드 `Tab` 이동, 포커스 표시, `Enter` 탭 전환이 동작한다.
- 일정·D-Day·멤버마다 관련된 행동과 빈 상태만 표시해 한 화면의 정보량을 제한한다.

## 확인 한계

- 자동화 브라우저가 페이지 확대율을 변경하지 않아 browser zoom 150%는 이번 결과에 포함하지 않았다.
- Web 캡처와 DOM만으로 iOS VoiceOver·Android TalkBack의 실제 낭독 순서와 선택 상태 발음을 확정할 수 없다.
- 일정·D-Day가 많이 쌓인 스크롤 상태와 OS font scale 1.5는 별도 실제 기기 점검이 필요하다.
